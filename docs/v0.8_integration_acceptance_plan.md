# v0.8.x 全链路集成验收方案

> **设计文档 · 只读 · 不修改代码 / 不新增功能 / 仅输出验收方案。**
> 日期：2026-09-02。
> 基线：v0.8.0 QueryTranslator + QueryBuilder、v0.8.1 ConceptSegmenter + Terminology、v0.8.2 IEEE Metadata Parser 均已完成。

---

## 一、验证目标

证明以下**完整闭环**端到端工作：

```
中文科研关键词
  → ① 概念切分（ConceptSegmenter）
  → ② 英文映射（QueryTranslator）
  → ③ 数据库查询生成（QueryBuilder）
  → ④ IEEE 检索（IeeeAdapter）
  → ⑤ 元数据解析（IeeeAdapter._parse_results）
  → ⑥ 报告生成（ReportGenerator.generate_markdown）
```

与 v0.8.1 最终真实验收的区别：v0.8.1 验证到 ④/⑤ 即止（只记录 IEEE 返回结果），**未覆盖 ⑥ 报告生成**。本次验收把 ⑥ 纳入闭环，并显式核对 v0.8.2 元数据解析优化后的 `year / venue / document_type` 完整性。

## 四、验收步骤

对每个 Case 依次执行：

1. **输入**：记录用户输入关键词。
2. **① 概念切分**：调用 `ConceptSegmenter(set(TERMS.keys())).segment(关键词)`，记录结果。
3. **② 英文映射**：`QueryExpansionService().expand(关键词)` → `QueryTranslator().translate_concepts(eq, ["IEEE Xplore"])`，记录概念分组。
4. **③ 查询生成**：`QueryBuilder().build("IEEE Xplore", concepts["IEEE Xplore"])`，记录最终 query。
5. **④ IEEE 检索**：经 `PortalNavigator` 打开 IEEE 落地页，填入 query 回车，等待 `networkidle` + 5s。
6. **⑤ 元数据解析**：`IeeeAdapter._parse_results(page, count)` 解析前 N 条，记录返回数量与前 3 篇 title/year/venue/document_type。
7. **⑥ 报告生成**：对解析出的 `SearchResult` 列表调用 `ReportGenerator.generate_markdown([r.to_dict() for r in results], query_info)`，记录生成的 Markdown 报告（重点核对前 3 篇的 year/venue/type 是否落盘）。

> 执行方式：可复用 `runtime/cross_language_acceptance.py` 的编排骨架（gitignored，仅执行不提交），在 ⑤ 后追加 ⑥ 报告生成调用；或直接交互式在受控 Edge 中执行并人工记录。脚本仅用于驱动验收，**不进入 `src/`、不提交**。

## 六、通过标准

1. **闭环正确**：6 段链路每一段产物与期望一致或合理（Segmenter/Translator/Builder 与上表完全一致）。
2. **IEEE 返回**：每个 Case 返回 ≥1 条且前 3 篇与输入方向相关。
3. **元数据完整性（v0.8.2 优化验证点）**：统计前 3 篇的 `year / venue / document_type` 非空占比。判定：
   - `year`：应 100% 非空（`_YEAR_RE` 整段匹配本就稳定）。
   - `venue`：应显著高于 v0.8.1 基线（v0.8.1 中期刊项 venue 常为 null；v0.8.2 用 `.description a` 结构化提取后应补齐）。
   - `document_type`：应显著高于 v0.8.1 基线（v0.8.1 中期刊项 type 常为 null；v0.8.2 增加 `Magazine Article` 标签后应补齐）。
   - 若某字段仍为 null，记录具体条目与原因（属于哪些版式），不视为整体失败，但需在报告中标注。
4. **报告生成**：`generate_markdown` 无异常，报告包含检索条件、数据源统计、文献列表，且前 3 篇的 year/venue/type 在报告中可见（非 `—` 占位）。

## 八、风险与备注

1. **IEEE 版式差异**：不同版式的 `.publisher-info-container` / `.description a` 结构可能略有差异，导致个别字段仍 null。记录具体条目即可，不影响闭环结论。
2. **低频约束**：全程 3 个 case、每 case 单次搜索，不进入详情页，符合低频单页边界。
3. **授权依赖**：需 TJU 授权有效（`check_tju_auth` = `logged_in`）；若失效需先在受控 Edge 中完成登录。
4. **词典占位拼写**：`antenna` / `radar` / `wireless` 为占位拼写（v0.8.1 已标注待校对）。本验收 3 个 case 均不涉及这些词（`太赫兹`/`通信`/`毫米波`/`通感一体化`），不受影响；但若后续验收涉及 `天线`/`雷达` 需先校对。
5. **报告生成仅验证结构**：`generate_markdown` 为纯模板渲染，本验收只核对报告是否包含检索条件、统计与前 3 篇元数据，不评估报告排版。

## 九、验收结论输出

验收执行完成后，输出一份真实验收报告（建议 `docs/v0.8_integration_acceptance_report.md`），包含：

- 每个 Case 的 6 段闭环产物（含上表期望值对照）；
- 前 3 篇论文的 title/year/venue/document_type；
- 元数据完整性统计（year/venue/type 非空占比）与 v0.8.1 基线对比；
- 报告生成验证结果（报告片段）；
- 结论：完整闭环是否通过，及遗留问题清单。
