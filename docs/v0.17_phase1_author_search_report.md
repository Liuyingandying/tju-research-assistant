## 1. 原来人名独立检索为何不可达

沿链路审计发现四道硬阻断（全部有代码证据）：

1. **UI**：`main_window._on_search()` 无条件要求研究方向非空
   （原 `if not direction: QMessageBox.warning("请输入研究方向。")`）。
2. **模型**：`QueryRequest.validate()` 首条校验即
   `research_direction` 为空 → `ValueError("研究方向不能为空")`。
3. **服务**：`SearchService.search()` 开头同样抛 `"研究方向不能为空"`。
4. **扩展链**：`SearchService.search()` 无条件调用
   `QueryExpansionService.expand(direction, ...)`，而 `expand()` 对空串抛
   `ValueError`——即使前三道放开，空主题也会在扩展链崩溃
   （或生成 `""`/`()`/`( OR )` 伪查询传给 Adapter）。

此外三源 Adapter 均无人名检索语义：CNKI/万方仅在 `author_affiliation`
非空时走高级检索（纯人名会落进普通关键词搜索），IEEE 把传入检索串当
全文关键词。

## 2. UI 校验修改

`main_window.py::_on_search`：

```python
direction = self.input_direction.text().strip()
person = self.input_author_name.text().strip()
if not direction and not person:
    QMessageBox.warning(self, "提示", "请输入研究方向或人员姓名，至少填写一项。")
    return
```

仅人员单位（人员单位有值、方向与姓名均空）仍被阻止——单位不参与该判断。

## 3. Request / SearchService 的 OR 语义（两道防线）

- **第一道（UI）**：见上。
- **第二道（SearchService.search()，防 API/测试/worker 直构非法请求）**：
  `if not direction and not person: raise ValueError("请输入研究方向或人员姓名，至少填写一项")`。
- **QueryRequest.validate()**：改为
  `research_direction` 与 `author_name` 至少一项非空，否则抛同一错误文案；
  docstring 记录契约（v0.17 Phase 1）。`validate()` 语义与 UI/服务一致，
  校验没有散落到任何 Adapter。

## 4. 空 research_direction 绕过 topic expansion

`SearchService.search()`：

```python
if direction:
    expanded = self._expansion.expand(direction, query.expansion_direction)
    self.last_expanded = expanded
    emit(f"检索词：{expanded.original} → ...")
    concepts = self._translator.translate_concepts(expanded, sources)
else:
    self.last_expanded = None
    concepts = {}
    emit(f"作者检索：{person}")
```

循环内 `query_string = self._builder.build(...) if direction else ""`——
纯人名时 expansion / translator / builder / ConceptSegmenter / Terminology
全部不参与（测试断言三者均未被调用），Adapter 收到**空串**，
不产生任何 `""`/`()`/`( OR )` 伪查询。扩展方向（综合/理论/应用/综述）
在纯人名模式下完全不影响查询构造。

## 5. CNKI 作者搜索

- 路由：`author_name` 本就在 `_ADVANCED_CONDITION_FIELDS` → 纯人名自动走
  kns8s 高级检索（既有机制，本 Phase 验证而非重写）。
- 修改：`CNKIAdvancedQueryBuilder.build()` 在 theme 为空时**跳过主题行
  （row0）**，只填作者行（row1，默认字段即"作者"）。
- 组合（全部经高级检索表单）：
  - 仅人名：作者 = 姓名；
  - topic+person：主题 row0 AND 作者 row1；
  - person+affiliation：作者 row1 AND 作者单位 row2（`_switch_field`）；
  - 三条件：三行 AND。
- 真机探针：仅作者单条件提交返回 5 条，**5/5 结果作者命中**。

## 6. 万方作者搜索

- **触发条件调整**：`search()` 由 `if affiliation: advanced` 改为
  `if affiliation or person: advanced`——纯人名不再退化为主题关键词。
- **行规划**（全部基于真机探针，页面 2026-09 已改版：可见行默认字段
  主题/题名或关键词/题名）：
  - 作者行固定占用 row0，且**必须切「精确」**——探针证实模糊形态
    `作者:(张伟)` 服务端恒返回 0（常见姓名亦然），精确形态
    `作者:("吴晓东")` 返回真实数据（≈3636 条）；
  - 作者单位：无作者条件时占用 row0（v0.13 既有行为不变），
    有作者条件时占用 row1；
  - 关键词行按行内字段名定位（题名或关键词/主题/关键词），
    前两行被占满时把下一空闲行切换为「题名或关键词」；
  - 字段下拉用 `.search-option.field` + `:text-is` 精确匹配
    （下拉含 第一作者/期刊-通讯作者，has-text 会误选）；
  - 空主题时普通搜索导航词使用人名（仅域名发现，探针证实可行）。
- 提交前回读校验、发表时间、原生被引排序、结果解析、metadata resolver
  全部复用既有实现，未改动。
- 回归：仅单位路径的表单交互逐事件不变（`test_affiliation_only_row0_unchanged`）。

## 7. IEEE 作者搜索（含真实限制）

- 新增 `compose_ieee_query(keyword, author_name)`：
  - 仅人名：`("Authors":"张三")`；
  - topic+person：`("Authors":"Xiaodong Feng") AND (terahertz OR THz)`。
- 真机探针证实 IEEE 官方搜索框**原生解释 fielded author 语法**：
  作者单条件 3/3 命中；作者 AND 主题 4/4 双命中；带引号/不带引号等价
  （统一带引号）；姓名中的 `"` 会被清洗。
- **中文姓名限制（明确降级，不伪造）**：现有 Translator 无任何
  人名罗马化机制，故中文姓名原样进入 author 语法；真机验证返回 0 条
  ——诚实降级，不偷偷生成拼音。状态消息与报告如实体现。
- 人员姓名从不作为普通全文关键词提交（测试锁定）。

## 8. topic + person 组合

三源均为 **主题 AND 作者**：
- CNKI：主题 row0 + 作者 row1；
- 万方：作者 row0（精确）+ 题名或关键词 row1（原始中文词，非扩展表达式）；
- IEEE：`("Authors":"…") AND (英文扩展 Boolean)`。
SearchService 层 topic 扩展照常运行（测试断言 expand 被调用）。

## 9. person + affiliation 组合

- CNKI：作者 + 作者单位（row1/row2）；
- 万方：作者 row0（精确）+ 作者单位 row1（+可选关键词 row2）；
- IEEE：作者条件生效；单位条件维持既有 MetadataPipeline/FilterService
  行为，strict × IEEE 的 UI 拦截规则一字未动。
- FilterService 本地作者过滤（大小写不敏感、部分匹配）对三源结果统一生效。

## 10. CITATION 兼容

`ranking_mode=CITATION` 仍只影响候选配额（`candidate_quota`）、原生被引
排序与 citation selection。测试锁定：
- 万方 CITATION 与综合推荐的**表单交互事件逐事件一致**
  （`test_citation_mode_keeps_same_conditions`）；
- SearchService CITATION 与综合推荐检索串一致、仅配额从 10 →
  `candidate_quota(10)`（`test_citation_person_only_same_query_as_comprehensive`）；
- 纯人名 + 高引用端到端：作者本地过滤 → 引用选择 → 排序正常
  （`test_person_only_citation_end_to_end`）。
