## 2. Prompt r1（`services/prompts/research_report_prompt.py`）

- `REPORT_PROMPT_VERSION = "r1"`（与单篇 `v4` 完全独立，缓存 key 已含该版本）；
- 系统提示词分区，全部覆盖任务书要求：

| 分区 | 内容 |
|---|---|
| `[ROLE]` | 科研调研助手：基于论文证据生成调研报告初稿，只输出 JSON |
| `[SOURCE TRACE RULES]` | ① 事实只来自输入论文、禁止模型记忆补充；② 每章必填 `source_papers`（[P#] 编号）；③ 无法判断 → 正文写「根据当前论文集合无法判断」并给出被考虑论文；④ 正文 [P#] 与 source_papers 一致 |
| `[USER PROFILE]` | 画像只用于"论文集合 × 用户方向"关系分析（第六章）；禁止修改 Evidence；画像为空 → 固定措辞 |
| `[SOURCE OWNERSHIP]` | 禁止单篇贡献写成领域事实；禁止综述创新冒充原创；禁止生成不存在的实验结果 |
| `[REPORT STRUCTURE]` | 输出 JSON `{title, sections:[{title, content, source_papers}]}`；六章节固定：研究背景 / 领域发展现状 / 关键技术路线 / 主要挑战 / 未来研究方向 / 与用户研究方向关系 |

用户 prompt：`[PAPERS]`（每篇编号、元数据、截断摘要 ≤500 字、已有分析材料）+ `[USER PROFILE]` + 输出要求。

## 3. Parser（契约校验，失败抛异常，不在 Provider 内降级）

```python
parse_report_sections(text, context) -> (title, list[ReportSection])
```

| 违规 | 异常 |
|---|---|
| 空输出 / 非 JSON / 顶层非对象 / 缺 title / 缺 sections / 章节缺 title/content / sections 非列表 | `ReportParseError` |
| `source_papers` 为空 / 非列表 / 编号越界 1..N / bool / 非整数 | `ReportGroundingError` |

- `source_papers` 是 **[P#] 编号数组**，解析后映射为论文 id（报告模型存 id）；
- 兼容 markdown fence、正文前后杂讯、字符串编号（`"1"`）；重复编号去重保序；
- 章节标题 → 模型 key 映射（精确匹配本阶段 Prompt 标题，再宽松匹配标签）。

## 4. LLMReportProvider（`services/llm_report_provider.py`）

```python
class LLMReportProvider:
    name = "openai-compatible"
    def generate(self, context: ReportContext) -> ResearchReport:
        self.calls += 1
        self._client.validate()          # 未配置 → LLMConfigError
        prompt = self._build(context)
        raw = self._client.complete(prompt, system_prompt=r1)
        title, sections = self._parse(raw, context)
        return ResearchReport(title=title, sections=sections)
```

- **不直接 requests**（AST + 运行期替身双重断言）；
- **不降级**：任何失败向上抛（`LLMConfigError` / `LLMNetworkError` / `LLMHTTPError` /
  `LLMTimeoutError` / `ReportParseError` / `ReportGroundingError`），由 `ReportService` 分类降级；
- **只负责 title 与 sections**：`id` / `created_time` / `papers` / `profile_snapshot` /
  `generation_scope` / `provider` / `model` / `report_prompt_version` / `status`
  由 Service 填充（`_normalize` / `_finalize` 已具备，无需改动）。

## 5. 降级细分（ReportService 正交改进）

| 失败 | degraded_reason | 用户文案 |
|---|---|---|
| Grounding 违规（空来源/越界/无法对应） | `source_validation` | AI 报告来源标注不符合要求…已生成基础报告（未调用 AI） |
| JSON 解析失败 | `parse` | AI 报告结果解析失败…已生成基础报告（未调用 AI） |
| Provider 异常 / 网络 / HTTP / 超时 | `provider_error` | AI 报告生成失败…已生成基础报告（未调用 AI） |
| 未配置 | `not_configured` | AI 报告生成未配置…（Provider 调用 0 次） |

降级报告仍含「文献集合概览」「已有研究方向」两节 + 其余 6 节标注"未调用 AI"（C-C 语义不变）。

## 9. 过程中发现并修正的两个真实问题（如实记录）

1. **降级原因无法区分**：C-C 阶段 `ReportService` 把 Provider 内部抛出的
   Grounding/Parse 异常一律归为 `provider_error`，导致"来源标注违规"与"API 失败"
   无法区分。已按 C-D 语义细分（见 §5），并补测试。
2. **测试夹具自身的假阳性**：`_payload()` 默认生成 6 节引用编号 1..6，但 2 篇论文的
   用例会越界——属测试数据错误（非产品缺陷），已让编号按论文数取模；另有
   空画像测试用 `profile or 默认值` 导致空画像从未真正传入，已改为
   `profile is not None` 判断。
