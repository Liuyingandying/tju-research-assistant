## 2. 论文选择能力（C-E-B）

| 项 | 实现 |
|---|---|
| 多选 | 表格新增第 9 列 **"选择"** checkbox（置于表尾，避免既有 8 个数据列索引漂移） |
| 计数显示 | 筛选行 `已选 N 篇` 实时更新 |
| 批量操作 | `全选筛选(≤20)` / `清空选择` |
| 与详情的关系 | 详情区仍跟随"当前行"（单击行为不变）；勾选与行选中互不干扰 |
| 视图变化 | 筛选/排序变化时重置勾选（勾选作用于当前筛选视图） |

**数量规则（实测通过）**：

| 勾选数 | 行为 |
|---|---|
| 0 | `btn_generate_report` **disabled**；若仍触发 → 提示"请先勾选要纳入报告的论文" |
| 1–4 | 点击弹窗 `当前仅勾选 N 篇，调研报告可能不完整，是否继续？`（取消则不请求） |
| 5–20 | 直接生成 |
| >20 | **禁止勾选**：第 21 次勾选被回退并提示"最多选择 20 篇论文生成报告" |

常量 `REPORT_MIN_PAPERS_SOFT = 5` / `REPORT_MAX_PAPERS = 20` 与 `ReportService` 保持一致。

## 3. 生成按钮（C-E-C）

- 位置：论文库底部工具栏；文案 **"生成调研报告"**（objectName `btnSearchPrimary`）；
- 点击只发出 `generate_report_requested(list)` —— **只传论文 id，不直接调用 LLM**；
- `MainWindow._build_report_service()` 仅做依赖注入：从 `APIConfigManager.provider_config()`
  构建 `LLMReportProvider`（未启用/构建失败 → `provider=None` → 服务降级为基础报告）。

## 4. 后台线程（C-E-D）

`ui/report_worker.py`：

```python
class ReportWorker(QObject):
    progress = Signal(int, int, str)   # 已完成, 总数, 阶段文案
    succeeded = Signal(dict)           # ReportGenerationResult.to_dict()
    failed = Signal(str)               # 兜底（Service 设计上不抛）
    finished = Signal()

    @Slot(list, str)
    def run_report(self, paper_ids, title="") -> None: ...
```

- 独立 `QThread`（`MainWindow._report_thread`），**不阻塞 GUI**（实测：提交后主线程继续
  处理事件，进度对话框实时更新，完成后自动关闭）；
- single-flight：`MainWindow._report_busy`，进行中忽略重复提交；
- 阶段文案：`读取论文库并组装报告输入…` → `完成`；
- 关闭窗口：`closeEvent` 中关闭进度对话框 + `_report_thread.quit()` + `wait(3000)`
  （与既有 evidence / summary 线程清理一致，测试断言关闭后线程不再运行）；
- 日志只记异常类型，不输出异常字符串（避免认证信息外泄）。

## 5. 报告查看窗口（C-E-E）

`ui/research_report_dialog.py`（只读，900×640，最小 640×460）：

- **标题**；
- **基本信息**：论文数量 / 生成时间 / Provider（+模型）/ Prompt 版本 / 画像版本 / 状态
  （`AI 生成` 或 `基础报告（未调用 AI）`）；
- **左侧章节列表**（按 `order` 排序；`insufficient` 标注"（证据不足）"、无来源标注"（无来源）"）；
- **右侧 Tabs**：`章节内容`（正文 + `来源：[P1] [P3]`）/ `来源论文附录`
  （`[P#] 标题（作者，年份，来源/类型/匹配等级/优先级/DOI）`）；
- **提示区**：降级文案 / 缓存命中 / 来源校验提示 / "基于旧科研画像或旧 Prompt，建议重新生成" /
  "有 N 篇来源论文已从论文库移除（报告内容仍保留）"；
- 接受两种入参：报告 `to_dict()` 或 Worker 传来的 `ReportGenerationResult.to_dict()`。

## 6. 错误处理（C-E-F）

| 场景 | UI 表现 | 是否出现 traceback |
|---|---|---|
| Provider 失败（网络/HTTP/超时） | 报告窗口 + 提示区"AI 报告生成失败，已生成基础报告（未调用 AI）。" | ❌ 无 |
| 未配置 AI 服务 | 报告窗口 + "AI 报告生成未配置，已生成基础报告（未调用 AI）。" | ❌ 无 |
| 来源校验未通过（Grounding/越界/空来源） | 报告窗口 + "AI 报告来源标注不符合要求…" + 来源校验提示 | ❌ 无 |
| JSON 解析失败 | 报告窗口 + "AI 报告结果解析失败，已生成基础报告（未调用 AI）。" | ❌ 无 |
| Worker 兜底异常 | `QMessageBox.information` 显示"调研报告生成失败" | ❌ 无 |

降级报告内容仍为「文献集合概览」+「已有研究方向」+ 其余章节标注"未调用 AI"（不编造）。

## 8. 过程中发现并修正的问题（如实记录）

1. **报告查看窗口不接受 Worker 载荷**（真实缺口）：`ResearchReportDialog` 原先把
   dict 一律当"报告 dict"解析，传入 `ReportGenerationResult.to_dict()` 会得到空报告。
   已改为自动识别（含 `report`/`status`/`ok` 键 → 按结果对象解析），
   并补测试 `test_7c_dialog_accepts_dict_payload`。
2. **模态窗口阻塞测试**（测试问题，非产品缺陷）：`_on_report_succeeded` 里的
   `dialog.exec()` 是**模态嵌套事件循环**——生产环境由用户关闭窗口，正确；
   但测试若未替身该窗口就会永久卡住。已用 `faulthandler` 定位并给相关用例加替身。
   附带明确一个设计事实：**报告查看窗口打开期间 `_report_busy` 保持 True**
   （单飞语义），关闭后才复位。
3. **测试夹具哨兵歧义**：`_service(provider=None)` 被写成"None → 用 Mock"，
   导致降级用例实际走了 Mock 路径（断言错位）。已改用 `_UNSET` 哨兵区分
   "未指定"与"显式无 Provider"。
4. **断言字段错误**：`ResearchReport.to_dict()` 不含 `paper_count`（它是属性），
   已改用 `len(report["papers"])`。

另观察到：本文件在**出现失败时**曾出现 `rc=127`（进程在打印失败汇总前退出），
与 2.6-PKG-B / 2.8-A 已归档的长套件原生异常属同一类环境现象；修正上述问题后
该文件单跑与分组运行均为 `rc=0` 全绿。
