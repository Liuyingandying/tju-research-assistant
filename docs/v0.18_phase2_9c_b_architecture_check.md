# v0.18 Phase 2.9-C-B-A —— 架构确认审计（ResearchReport 不污染现有模型）

- 阶段：Phase 2.9-C-B-A（实现前架构确认）
- 日期：2026-09-10
- 结论：**ResearchReport 为独立模型，与 `LibraryRecord` / `EnhancedSummary` /
  `ResearchProfile` 零耦合**；报告持久化与 `LibraryStore` 完全分离。

---

## 1. 审计范围与方法

检查对象：

| 层 | 文件 | 检查点 |
|---|---|---|
| models | `models/library.py`（LibraryRecord） | 是否新增报告字段 / schema 是否变化 |
| models | `models/enhanced_summary.py`（EnhancedSummary） | 字段集合是否被扩展 / 是否被报告改写 |

方法：源码结构审查 + **AST 依赖检查**（自动化，见 §4）+ 模型字段断言（见 §5）。

## 2. 既有模型现状（确认未变）

### 2.1 `LibraryRecord`（论文库，schema v2）

字段分四组：基础身份 / 原始证据（`abstract`）/ 分析结果（`basic_summary`、
`enhanced_summary` + `enhanced_provider` / `enhanced_model` /
`enhanced_prompt_version` / `enhanced_profile_version` / `enhanced_at`）/
用户数据（`tags` / `note` / `reading_status` / `saved_at` / `updated_time`）。

**本阶段结论**：`schema_version` 仍为 **2**；**未新增任何报告字段**
（无 `report_id` / `reports` / `research_report` / `generation_scope`）。
报告通过 `ReportSource.paper_id` **单向引用**库记录 id，库侧无反向引用。

### 2.2 `EnhancedSummary`（单篇 AI 分析）

字段：6 解释字段 + `document_type` / `document_type_reason` /
`direction_match_level` / `reading_priority` / `provider` / `ai_generated`。

**本阶段结论**：字段集合**未扩展**；报告只**读取**已持久化的值填入
`ReportSource`（`direction_match_level` / `reading_priority`）作为**快照副本**，
不持有、不改写 `EnhancedSummary` 实例。

### 2.3 `ResearchProfile`（科研画像）

报告侧只读取 `to_dict()` 结果放入 `ResearchReport.profile_snapshot`
（只读快照），**不调用** `bump_version()` / `save()` 等写路径。

## 3. 依赖方向（单向）

```
LibraryRecord ──┐
                ├──▶ ReportSource（快照副本）──▶ ResearchReport
EnhancedSummary ┘                                    │
                                                     ▼
ResearchProfile ──▶ profile_snapshot（快照副本）   ResearchReportStore
                                                     （runtime/reports/）
        ▲                                                      │
        └──────────── 无反向引用、无写回 ◀─────────────────────┘
```

- **报告 → 论文库**：无调用（报告存储不 import `library_store`）；
- **论文库 → 报告**：无字段、无引用（论文库不知道报告存在）；
- **画像 → 报告**：只读快照；
- **报告 ≠ Library 的组成部分**：报告落 `app_paths.reports_dir()`，
  与 `data/library.json`（开发态 `runtime/reports/`，见 §6 路径）互不影响。

## 4. 自动化依赖检查（AST）

新增测试 `tests/test_research_report.py::TestNoPollution` 中的两条：

```python
# 报告存储 / 报告缓存的导入列表中不得出现任何 library 相关模块
assert not any("library" in name.lower() for name in imported)
```

- `services/research_report_store.py` 仅 import：`json` / `os` / `tempfile` /
  `pathlib` / `app_paths` / `models.research_report`；
- `services/report_cache.py` 仅 import：`hashlib` / `json` / `pathlib` /
  `app_paths` / `models.research_report`；
- 两条断言均通过 → **报告持久化与缓存对论文库零依赖**。

> 注：初次实现时该检查写成了"源码文本不得出现 LibraryStore"，
> 被本模块**文档字符串**里的说明文案误触发。已改为 AST 导入检查
> —— 检查的是真实依赖，而不是注释措辞。

## 5. 模型隔离断言（测试）

| 断言 | 验证内容 |
|---|---|
| `not hasattr(LibraryRecord(), "report_id"/"reports"/"research_report"/"generation_scope")` | 论文库模型无报告字段 |
| `LibraryRecord().to_dict()` 不含上述键 | 序列化层也未泄漏 |
| `LibraryRecord().to_dict()["schema_version"] == 2` | 论文库 schema 未升级（无破坏性迁移） |
| `EnhancedSummary.to_dict()` 前后**完全一致**；无 `sections` / `report_id` 属性 | 单篇分析模型未被改写 |
| 报告往返（`to_dict` → `from_dict`）后 `EnhancedSummary.to_dict()` 仍一致 | 报告流程不改单篇对象 |

## 6. 路径与隔离（延续 2.9-B1/B2）

新增两个路径（`app_paths.py`）：

| 用途 | 开发态 | 隔离态（`TEST_USER_DATA_ROOT`） | frozen 态 |
|---|---|---|---|
| 报告文件 `reports_dir()` | `<repo>/runtime/reports/` | `$ROOT/reports/` | `%LOCALAPPDATA%\TJU_Info_Retrieval\reports\` |
| 报告缓存 `report_cache_dir()` | `<repo>/runtime/cache/research_reports/` | `$ROOT/cache/research_reports/` | `%LOCALAPPDATA%\...\cache\research_reports\` |

- 二者均走 `runtime_dir()` / `summary_cache_dir()`，**自动继承测试隔离**；
- 报告缓存与单篇缓存 `enhanced_summary/` **平级不混存**（断言：
  `cache_dir.name == "research_reports"` 且 `!= summary_cache_dir()`）；
- **发布安全**（延续 2.9-B.2 Release Guard）：
  - `prepare_release_runtime.py` 的排除名单新增 `reports/` / `research_reports`；
  - `check_release_data.py` 的源码快照检查新增 `runtime/reports`
    （快照含报告 → `snapshot-user-data` CRITICAL）。
