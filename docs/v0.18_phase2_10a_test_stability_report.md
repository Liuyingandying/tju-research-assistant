# v0.18 Phase 2.10-A 测试环境稳定化 — 验收报告

## 状态：PASS

---

## 1. 任务概述

解决完整测试套件中 97 个 `tmp_path` 权限错误（`PermissionError: WinError 5`），
使测试环境稳定化。禁止修改业务代码（SearchService / Adapter / BrowserSession /
LLM Provider / ReportService / LibraryRecord）。

---

## 2. 根因分析

### 问题定位

系统环境变量 `TEMP` / `TMP` 指向 `D:\DevCache\Temp`。该目录下残留的
`pytest-of-FAJ` 子目录存在**访问拒绝（WinError 5）**：

```
PermissionError: [WinError 5] 拒绝访问。: 'D:\\DevCache\\Temp\\pytest-of-FAJ'
```

pytest 的 `tmp_path` fixture 依赖 `tempfile.gettempdir()` 确定 basetemp，
在 `make_numbered_dir()` 中调用 `os.scandir(root)` 扫描该目录以寻找已有编号，
遇到无权限的 `pytest-of-FAJ` 即抛出 `PermissionError`，导致所有使用
`tmp_path` / `tmp_path_factory` 的测试报 error。

### 验证

- `D:\DevCache\Temp` 本身可写，但 `pytest-of-FAJ` 子目录 `os.listdir` 与
  `mkdir` 均返回 WinError 5（可能是某次异常退出留下的、ACL 损坏的残留目录）。
- `%LOCALAPPDATA%\TJU_Info_Retrieval_TestTemp` 可正常创建、写入、清理。

---

## 3. 修复方案

### 新增 `tests/_test_environment.py`

提供 `get_test_temp_root()`：

| 平台 | 返回路径 |
|------|----------|
| Windows | `%LOCALAPPDATA%\TJU_Info_Retrieval_TestTemp` |
| Linux / macOS | `/tmp/tju-pytest-temp` |

关键函数：

- `get_test_temp_root()` — 返回明确可写的测试临时根目录，目录不存在时自动创建；
- `_ensure_writable(path)` — 检查 exists + write permission，目录存在但不可写时
  尝试清理重建；彻底无法创建时抛出**明确中文错误**：
  `测试临时目录创建失败: {path} ... 请检查目录权限或设置 TMPDIR 环境变量指向可写目录。`
- `_is_writable(path)` — 通过写入探针文件检查写权限；
- `override_pytest_basetemp()` — 覆盖 `tempfile.tempdir` 缓存（Python 3.13 全局
  变量，兼容早期版本 `_tempdir` / `_default_tempdir`）并同步 TEMP/TMP/TMPDIR 环境变量。

### 修改 `tests/conftest.py`

在 `pytest_configure` 钩子中强制覆盖 pytest 的 `--basetemp`：

```python
def pytest_configure(config) -> None:
    from tests._test_environment import get_test_temp_root
    new_basetemp = get_test_temp_root() / "pytest-basetemp"
    new_basetemp.mkdir(parents=True, exist_ok=True)
    config.option.basetemp = str(new_basetemp)
    ...
```

并在导入期 `import tests._test_environment`（早于 `_isolation_support`），
确保在 pytest 首次调用 `tempfile.gettempdir()` 之前完成缓存覆盖。

### 隔离保证

- 临时目录落在 `%LOCALAPPDATA%\TJU_Info_Retrieval_TestTemp`，**不写入**
  `data/`、`runtime/`、用户真实数据目录；
- 原有真实数据指纹护栏（`tests/_isolation_support.py`）继续生效；
- `TEST_USER_DATA_ROOT` 隔离机制不变。

## 5. 环境限制（分类：environment limitation）

完整测试仍存在两类**非业务缺陷**的环境级限制，详见
[`v0.18_phase2_10a_environment_note.md`](./v0.18_phase2_10a_environment_note.md)：

1. **Qt 原生堆损坏 0xc0000374** — PySide6 在 Windows 上聚合运行多个
   `MainWindow` UI 测试时触发；单文件运行大多通过，聚合运行崩溃点漂移。
   属 PySide6/Qt 已知限制，按任务书要求**未修改业务代码**。

2. **test_portal.py 真实授权测试** — 需要天津大学图书馆真实登录态，
   已显式标记 `real_user_data`，用 `-m "not real_user_data"` 排除。
