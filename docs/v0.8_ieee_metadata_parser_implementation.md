## 二、解析方式变化

### 问题根因（来自 v0.8.2 设计审计）
旧 `_parse_results` 把整条结果的 `innerText` 拼成一段文本，用三个正则去匹配：

- `_VENUE_RE = \d{4}\s+(.+?)(?:\s*(?:Year:|Conference:|Journal:|$))` —— 要求 venue 以 4 位年份开头（会议风格）。期刊项的 venue（如 `China Communications`）出现在年份**之前**，且 `(.+?)` 不跨换行，导致期刊 venue 匹配失败 → `None`。
- `_DOC_TYPE_RE` 缺少 `Magazine Article` 标签 —— 期刊页实际使用该标签，导致期刊 document_type 匹配失败 → `None`。
- `_YEAR_RE` 为整段文本匹配，年份基本正常。

### 新策略：结构化 DOM 优先 + 正则回退
在 `page.evaluate` 的 JS 中，对每条结果项按真实 DOM 节点提取，节点缺失时回退到整段正则：

| 字段 | 结构化优先 | 回退 |
| --- | --- | --- |
| `venue` | `item.querySelector('.description a')` 的 `innerText` | `_VENUE_RE` 整段正则 |
| `year` | `item.querySelector('.publisher-info-container')` 内 `Year:\s*(20\d{2})` | `_YEAR_RE` 整段正则 |
| `document_type` | `.publisher-info-container` 内类型标签 | `_DOC_TYPE_RE` 整段正则（已含 `Magazine Article`） |

`title` / `authors` / `url` 保持原有提取方式不变（`h3 a.fw-bold`、`.author a`、`h3 a href`）。

`_DOC_TYPE_RE` 扩展为：
```
Conference Paper|Magazine Article|Journals? & Magazines|Early Access|Standards|Books|Courses
```
`Magazine Article` 置于 `Journals? & Magazines` 之前，避免期刊项被误匹配为后者。

### 真实 DOM 对照
- 期刊项：`.description a` → `China Communications`；`.publisher-info-container` → `Year: 2019`、`Magazine Article`。
- 会议项：`.description a` → `2024 49th International Conference on Infrared, Millimeter, and Terahertz Waves (IRMMW-THz)`；`.publisher-info-container` → `Year: 2024`、`Conference Paper`。

注意：会议项的 `.description a` 文本为**完整会议名**（含括号内缩写 `IRMMW-THz`），因此提取出的 `venue` 是完整会议名，而非仅缩写。这是对真实 DOM 的忠实反映。
