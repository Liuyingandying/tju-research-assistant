# v0.18 Phase 2.11-A 多模型 AI Provider 支持 — 设计

## Phase A：设计审计

---

## 1. 目标

在**单一 OpenAI-compatible 调用链**（`OpenAICompatibleProvider`）不变的前提下，
增加多 Provider 配置能力：天津大学 LLM / DeepSeek API / 自定义 OpenAI Compatible。
用户可在设置页选择服务商，选择后自动填充 base_url / model。

约束：
- 禁止修改 SearchService / Evidence 链 / LibraryRecord / ReportService 接口 /
  SummaryService 接口 / AI 分析 Prompt 逻辑；
- 禁止新增第二套 AI 调用链。

---

## 2. 现有架构审计

### 2.1 调用链（唯一网络出口）

```
APIConfigManager.provider_config()        → {enabled, provider, base_url, model, api_key_env, api_key}
   ↓
OpenAICompatibleProvider(config)          → 通用 Chat Completions 客户端（requests）
   ↓  complete(prompt)  → POST {base_url}/chat/completions
   ↓
SummaryService  → LLMEnhancedProvider（增强分析）
ReportService   → LLMReportProvider（调研报告）
```

**关键结论**：`OpenAICompatibleProvider` 完全由 `base_url` / `model` / `api_key` 驱动，
对"服务商"无感知（`provider` 仅作展示名与缓存 key 的一部分）。因此**只需改配置层**
（provider 下拉 + 默认值），即可支持 DeepSeek 等任意 OpenAI-compatible 端点，
**无需改动 Provider / Service**。

### 2.2 现有配置（`services/api_config_manager.py`）

| 项 | 现状 |
|----|------|
| `SERVICE_OPTIONS` | `("天津大学 LLM","tju")` / `("OpenAI Compatible","openai-compatible")` / `("自定义接口","custom")` |
| `DEFAULT_BASE_URL` | `https://ai.tju.edu.cn/api/v3` |
| `DEFAULT_MODEL` | `tju-llm` |
| `provider_config()` | 返回 `{enabled, provider, base_url, model, api_key_env, api_key?}` |
| `set_from_settings(service_type, …)` | 直接存储 `provider = service_type` |
| 凭据 | `CredentialStore`：keyring → DPAPI `credential.dat` → memory-only（无明文） |

### 2.3 SettingsDialog（`ui/settings_dialog.py`）

- `combo_service`（服务商下拉）由 `SERVICE_OPTIONS` 填充；
- `_on_service_changed` 目前仅处理 `"tju"`（填充默认 base_url/model）；
- `_provider_cfg_from_form` / `_on_save` 统一 fallback 到 `DEFAULT_BASE_URL/DEFAULT_MODEL`。

### 2.4 测试表面（不可破坏）

| 测试 | 关键断言 |
|------|----------|
| `test_api_config_manager.py` | `DEFAULT_BASE_URL` / `DEFAULT_MODEL` 默认值；`set_from_settings("tju", …)` 后 `is_configured()`；JSON 不含 key |
| `test_settings_dialog.py` | `combo_service` 存在；`_provider_cfg_from_form` 回填表单 base_url/model/key；`_on_save` 后 `is_configured()` |
| `test_llm_provider.py` | `OpenAICompatibleProvider` 对 `provider="openai-compatible"` 等字符串透明处理 |

→ 结论：`set_from_settings` 仍接受任意字符串；`DEFAULT_*` 值不变；下拉框结构不变。

## 3. 设计方案

### 3.1 Phase B：`services/ai_provider_registry.py`（新增）

单一事实来源，内置 3 个 provider：

| id | label | default_base_url | default_model | api_key_env |
|----|-------|------------------|---------------|-------------|
| `tju_llm` | 天津大学 LLM | `https://ai.tju.edu.cn/api/v3` | `tju-llm` | `TJU_INFO_LLM_API_KEY` |
| `deepseek` | DeepSeek API | `https://api.deepseek.com` | `deepseek-chat` | `DEEPSEEK_API_KEY` |
| `custom` | 自定义 OpenAI Compatible | ``（空，用户填） | ``（空，用户填） | `TJU_INFO_LLM_API_KEY` |

API（纯数据，无副作用）：
```python
PROVIDER_IDS = ("tju_llm", "deepseek", "custom")
provider_options() -> list[tuple[label, id]]
provider_entry(pid) -> dict
default_base_url(pid) / default_model(pid) / default_api_key_env(pid)
normalize_provider(pid) -> str    # 旧 id 归一：tju→tju_llm, openai-compatible→custom
is_known_provider(pid) -> bool
```

### 3.2 Phase C：`api_config_manager.py`（修改，接口不变）

- `SERVICE_OPTIONS` 改为从 registry 派生（label/id），值为 `tju_llm/deepseek/custom`；
- 保留 `DEFAULT_BASE_URL` / `DEFAULT_MODEL`（= tju_llm 默认，测试引用）；
- `load_config` 读入后对 `provider` 做 `normalize_provider()`（旧配置平滑迁移）；
- `provider_config()` 返回结构不变（SummaryService/ReportService 零改动）。

### 3.3 Phase D：`settings_dialog.py`（修改）

- `_on_service_changed`：对**任一已知 provider** 自动填充 base_url / model
  （custom 填空提示手动填写）；
- `_load_current`：用 `normalize_provider` 匹配下拉索引；
- `_provider_cfg_from_form` / `_on_save`：fallback 到**当前所选 provider 的默认值**
  （而非固定 DEFAULT），`api_key_env` 也取该 provider 的默认环境变量名。

### 3.4 隔离与安全

- Key 仍经 `CredentialStore`（keyring → DPAPI → memory），不因多 provider 新增明文；
- Provider 切换不新增 AI 调用链、不触发真实 API；
- 测试用 `TEST_USER_DATA_ROOT` 隔离目录 + keyring mock。
