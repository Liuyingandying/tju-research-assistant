## 2. 新增实现

### 2.1 `models/report_context.py` — ReportContext（C-C-C）

字段：`papers`（`ReportSource` 快照列表）/ `profile_snapshot` /
`generation_scope` / `created_time` / `source_materials` / `title_hint`。

**关键约束（已实现并测试）**：`papers` **禁止传入 `LibraryRecord` 实例**。
`__post_init__` 校验每个元素：

- 类型名为 `LibraryRecord` / `SearchResult` → 抛 `ValueError` 并给出转换指引
  （"请先转换为 ReportSource 快照"）；
- 非 `ReportSource` 的其他类型同样拒绝。

转换由 service 层完成（`report_source_from_record()`），因此
**models 层不依赖 `models.library`**（保持 C-B 建立的"报告不依赖论文库模型"结论）。

辅助能力：`paper_count` / `paper_ids()` / `known_paper_ids()` / `materials_for()` /
`profile_version()` / `profile_is_configured()` / `profile_summary_text()`
（无画像时输出固定措辞「尚未设置科研画像，无法进行个性化方向匹配。」）/
`to_dict()` / `from_dict()`（脏数据安全降级）。

### 2.2 `services/report_provider.py` — ReportProvider 协议（C-C-B）

```python
class ReportProvider(Protocol):
    name: str
    def generate(self, context: ReportContext) -> ResearchReport: ...
```

- `@runtime_checkable`，与 `SummaryProvider` **完全独立**（不 import 任何 summary 模块）；
- **宽松契约**：Provider 只需产出 `title` 与 `sections`，其余元信息由 Service 填充；
- **失败必须抛异常**（不要吞）：降级策略集中在 Service 一处；
- `MockReportProvider`：固定输出、**绝不联网**，支持注入
  `raises=`（模拟 Provider 异常）、`dangling_sources=`（模拟来源越界）、
  `empty_sections=`（模拟空结果），并计数 `calls` 供缓存断言使用。

### 2.3 `services/report_service.py` — ReportService（C-C-D）

```python
service.generate_report(paper_ids, title=None) -> ReportGenerationResult
```

流程与任务书一致：读库（只读）→ 数量校验 → 组装 `ReportContext` →
查 `ReportCache` → 调 `ReportProvider` → `validate_sources()` → 保存。

**数量规则**：

| 选择数 | 行为 |
|---|---|
| 0 | 拒绝：「请先选择要纳入报告的论文（建议 5–20 篇）」，不调用 Provider、不落盘 |
| 1–4 | 允许，返回 `warning`「当前仅 N 篇，报告覆盖度有限（建议 5–20 篇）」 |
| 5–20 | 正常生成 |
| >20 | 拒绝：「最多支持 20 篇论文（当前 N 篇）」 |
| 全部 id 不存在 | 拒绝：「所选论文在论文库中未找到，请重新选择」 |

**标题优先级**：用户显式 > Provider 生成 > 服务默认（画像领域 + 篇数）。

## 3. 失败降级（绝不抛异常给 UI）

| 场景 | `status` | `degraded_reason` | 是否调用 Provider |
|---|---|---|---|
| Provider 未配置 | `draft` | `not_configured` | ❌ 0 次 |
| Provider 抛异常（含 `requests.ConnectionError`） | `draft` | `provider_error` | 1 次（失败） |
| Provider 返回空章节 | `draft` | `source_validation` | 1 次 |
| Provider 返回类型不合法 | `draft` | `provider_error` | 1 次 |
| 章节来源无法对应所选论文 | `draft` | `source_validation` | 1 次 |

**基础报告内容规则（禁止编造）**：

- 必含两节：
  - **文献集合概览** —— 篇数、年份分布、来源分布、成果类型、文献类型分布、
    `[P#]` 论文清单（全部来自快照统计，`source_papers` = 全部论文 id）；
  - **已有研究方向** —— 按既有 `direction_match_level` / `reading_priority` 分组、
    画像快照文本、「暂不关注」主题（只汇总论文库已有字段与画像，不新增判断）；
- 其余 6 个 AI 章节（研究背景 / 领域发展趋势 / 关键技术路线 / 主要挑战 /
  未来方向 / 与用户研究方向关系）标记 `insufficient=True`，正文固定为
  「未调用 AI：本机未配置或调用失败，无法从所选论文归纳该章节。」；
- 降级结果**不写缓存**（下次仍会尝试 Provider）。

> 实现中修正过一个真实缺口：Provider 返回类型非法时，`_normalize()` 抛出的
> `TypeError` 曾直接穿透到调用方，违反"不能 raise 到 UI"。已改为在
> `generate_report()` 内捕获并降级（`test_service_rejects_non_report_return`）。

## 4. 来源追踪

`ReportService.validate_sources(report, context=None) -> list[str]`（空列表 = 通过）：

1. 报告必须有章节（否则视为无内容）；
2. 每个 `source_papers` 中的 id 必须存在于 `report.papers`（越界 → 报问题）；
3. 至少一个章节引用了来源（否则等于无追溯）。

校验失败 → 降级为基础报告，并把问题列表放进 `result.validation_problems`。
`ReportSource` 快照保证论文库后续变化不影响已生成报告的追溯性
（C-B 已测试：记录改名/删除后报告仍读原始快照）。

## 5. 缓存

- 使用 `ReportCache`（独立目录 `research_reports/`，与单篇 `enhanced_summary/` 平级不混存）；
- key 包含任务书要求的全部字段：
  `paper_ids` / `paper_versions` / `profile_version` / `REPORT_PROMPT_VERSION`
  + `provider` / `model`；
- **命中缓存绝不调用 Provider**（测试用计数 Provider 验证 `calls` 不增）；
- 顺序无关：同一集合反向选择仍命中（`test_8b`）；
- 失效验证：单篇重新分析（`enhanced_prompt_version` 变化）、画像版本变化、
  Prompt 版本变化、换 provider/model → 均重新调用 Provider；
- 缓存命中时若用户显式指定新标题 → 重命名返回对象并回写文件（**不重算、不浪费 API**）。

## 7. 过程中修正的两个真实问题（如实记录）

### 7.1 隔离护栏的假阳性（`runtime/edge_profile`）

分组回归第 3 组曾报错：`测试写入了仓库真实用户数据（隔离失败）: runtime/edge_profile`。
隔离复跑 3 次均通过 → 属**瞬态**变化。排查发现真实 Edge Profile 中
`BrowserMetrics` / `ShaderCache` / `Default/Cache` 等文件会被浏览器进程
（`msedgewebview2` 常驻）持续刷新，**整目录指纹会把外部进程的正常写入误判成测试污染**。

修正：护栏不再对 `edge_profile` 做整目录指纹，改为只指纹**登录态敏感文件**：

```
runtime/edge_profile/Local State
runtime/edge_profile/Default/Cookies
runtime/edge_profile/Default/Login Data
runtime/edge_profile/Default/Preferences
runtime/edge_profile/Default/Network/Cookies
```

这样既保住"测试不得写入真实登录态"的保证，又消除了外部进程造成的假阳性。

### 7.2 Provider 返回非法类型时异常穿透

见 §3 末尾：`_normalize()` 的 `TypeError` 曾直接抛给调用方，已改为降级。
