## 1. 架构确认（C-B-A）

见 [docs/v0.18_phase2_9c_b_architecture_check.md](v0.18_phase2_9c_b_architecture_check.md)。核心结论：

```
LibraryRecord ──┐
                ├──▶ ReportSource（快照副本）──▶ ResearchReport ──▶ ResearchReportStore
EnhancedSummary ┘                                                    (runtime/reports/)
ResearchProfile ──▶ profile_snapshot（只读快照）
        ▲                                                                    │
        └────────────────── 无反向引用 / 无写回 ◀───────────────────────────┘
```

- **单向依赖**：报告读取既有模型，既有模型不知道报告存在；
- **零写回**：报告不改论文库、不改单篇分析、不改画像；
- **AST 验证**：`research_report_store.py` 与 `report_cache.py` 的导入列表中
  不含任何 library 相关模块（自动化断言，见 §5）。

> 实现过程中修正过一处**测试自身**的问题：最初用"源码文本不得出现
> `LibraryStore`"做检查，被模块文档字符串里的说明文字误触发；
> 已改为 **AST 导入检查**（检查真实依赖，而不是注释措辞）。

## 2. 模型实现（C-B-B）

新增 `src/tju_info_retrieval/models/research_report.py`（14.7 KB）。

### 2.1 `ResearchReport`

| 分组 | 字段 |
|---|---|
| 基础信息 | `id`（自动 uuid hex）/ `title` / `created_time`（ISO） |
| 报告来源 | `profile_snapshot`（生成时画像快照）/ `papers: list[ReportSource]` / `sections: list[ReportSection]` |
| 生成信息 | `provider` / `model` / `report_prompt_version`（默认 `r1`） |
| 状态 | `status` ∈ {`draft`, `generated`, `failed`}（默认 `draft`，非法值回落 `draft`） |
| 版本 | `schema_version`（默认 1） |
| 生成方式 | `generation_scope` |

语义辅助方法：`paper_count` / `paper_by_id()` / `ordered_sections()` /
`section(key)` / `traced_paper_ids()` / `untraced_paper_ids()` /
`dangling_source_ids()`（追溯断裂检测）/ `profile_version()` /
`is_stale(profile_version, prompt_version)` / `missing_source_paper_ids()`。

### 2.2 `ReportSection`

`id` / `title` / `content` / `order` / `source_papers`（引用 `ReportSource.paper_id`）
+ 扩展 `key`（6 节固定键之一）/ `insufficient`（证据不足标记）。

**可追溯保证**：`source_papers` 存的是**论文 id 列表**（非标题、非序号），
`traced_paper_ids()` / `dangling_source_ids()` 可做一致性校验。

### 2.3 `ReportSource`（生成时快照）

`paper_id` / `title` / `authors` / `year` / `doi` / `artifact_type` /
`direction_match_level` / `reading_priority`
+ 补充快照 `source` / `document_type` / `index`（[P#] 编号）。

**关键约束（已由测试守护）**：这是**生成时快照**，不实时依赖 `LibraryRecord`。
论文库记录被改名/删除后，报告仍能完整读取原始快照。

### 2.4 序列化与兼容

- `to_dict()` / `from_dict()` / `to_json()` / `from_json()` 四件套齐备；
- **非法字段忽略**：未知顶层与嵌套字段不进 `to_dict()`；
- **缺失字段默认**：`papers`/`sections` 缺失 → `[]`；`created_time` → `""`；
  `report_prompt_version` → `r1`；`status` → `draft`；
- **非法类型安全降级**：`papers="not-a-list"` → `[]`；`source_papers="单id"`
  （字符串）→ `["单id"]`；`order="3"` → `3`；非 dict 列表项被跳过；
- **前向兼容**：`schema_version=99` 的载荷仍按已知字段尽力加载，不抛异常；
- `from_json("")` / 非法 JSON / 顶层非对象 → 抛 `ValueError`（由调用方处理）。

### 2.5 `generation_scope`

```python
build_generation_scope(paper_count=8, profile_version=3,
                       library_filter={"direction_match": ["strong", "medium"],
                                       "reading_priority": ["deep_read", "priority_read"]})
# → {"paper_count": 8, "profile_version": 3,
#    "library_filter": {"direction_match": [...], "reading_priority": [...]}}
```

记录"这个报告如何产生"（论文数 / 画像版本 / 当时的论文库筛选条件）；
非法输入安全降级（`"many"` → 0，`None` filter → `{}`）。

## 3. 持久化实现

### 3.1 `services/research_report_store.py`

| 能力 | 说明 |
|---|---|
| `save(report)` | 原子写（临时文件 → flush + fsync → `os.replace`），返回文件路径 |
| `load(report_id)` | 不存在/损坏/非法 JSON → `None`（不抛异常） |
| `list_reports()` | 按 `created_time` 倒序 |
| `list_summaries()` | 轻量列表视图（不带 `sections` 正文） |
| `delete(report_id)` | 只删报告文件；不存在 → `False`（重复删除安全） |
| `export_json(report, path)` | 导出到任意路径（不纳入 `reports/` 管理） |

- **与 `LibraryStore` 完全分离**：不 import、不读写论文库文件（AST 断言）；
- 非法输入防护：`report=None` / `id=""` → `ValueError`；`os.replace` 失败 →
  原文件保持不变（有专项测试）；
- 临时文件不会被 `list_reports()` 误读（只扫 `*.json`）。

### 3.2 路径（`app_paths.py` 新增）

| 用途 | 开发态 | 隔离态 | frozen 态 |
|---|---|---|---|
| 报告文件 `reports_dir()` | `<repo>/runtime/reports/` | `$TEST_USER_DATA_ROOT/reports/` | `%LOCALAPPDATA%\TJU_Info_Retrieval\reports\` |
| 报告缓存 `report_cache_dir()` | `<repo>/runtime/cache/research_reports/` | `$ROOT/cache/research_reports/` | `%LOCALAPPDATA%\...\cache\research_reports\` |

均走既有 `runtime_dir()` / `summary_cache_dir()` → **自动继承 2.9-B.1 的测试隔离**。

### 3.3 报告缓存（独立命名空间）

`services/report_cache.py`：

```python
report_cache_key(paper_ids, paper_versions, profile_version,
                 prompt_version="r1", provider="", model="")
```

- **必须包含**（逐项有断言）：`paper_ids` / `paper_versions` /
  `profile_version` / `REPORT_PROMPT_VERSION`；另含 `provider` / `model`；
- **顺序无关**：`["b","a"] + ["v2","v1"]` 与 `["a","b"] + ["v1","v2"]` 同 key
  （用户换选顺序不应重复调用）；
- `paper_version_tag(record)`：`library_id:enhanced_prompt_version:enhanced_profile_version:enhanced_at`
  —— 某篇被重新分析 → 集合指纹变化 → 缓存自动失效；仅基础整理的记录标 `basic`；
- 目录 `research_reports/` 与单篇 `enhanced_summary/` **平级不混存**（有断言）；
- `ReportCache` 两级（内存 + 磁盘），写盘失败不影响调用方（缓存非关键路径），
  损坏文件与 `cache_version` 不匹配均安全 miss。

## 7. 下一阶段接口预留（2.9-C-C 可直接使用）

- `ReportService` 只需：读 `LibraryStore.load_all()` → 组装 `ReportSource`
  → `report_cache_key(...)` 查缓存 → 命中直接返回 / 未命中调 LLM → 解析为
  `sections` → `ResearchReportStore.save()`；
- 报告 Prompt 使用同一常量 `REPORT_PROMPT_VERSION = "r1"`（已在模型中定义）；
- 降级（AI 失败）只需构造 `status=STATUS_FAILED`（或 `generated` +
  空来源章节）的 `ResearchReport`：`sections[].insufficient=True` +
  `content` 写明"未调用 AI"，模型层无需改动。
