## 2. 网页端机构筛选行为（真实观测）

操作序列：普通搜索"太赫兹" → 左侧面板 **机构** 组 → 点 **天津大学**。

**URL 变化**：无。
- 普通搜索：`https://lzxepffr…-s.p.lib.tju.edu.cn/paper?q=太赫兹&p=1`；
- 点击机构"天津大学"后：URL **保持不变**（`q=太赫兹&p=1`）——机构筛选完全由 SPA 内部状态承载，**不存在 URL 参数**。

**结果数量**：
- 普通搜索"太赫兹"：**共 128,799 条**（页面统计）；
- 机构面板内建计数："**天津大学 (878)**"（同一页面，机构列表可见，与其它机构并列）；即网页端"太赫兹 + 机构=天津大学"的真实命中数约为 **878 条**。

**Network 请求（关键）**：
- 页面数据全部由 **gRPC-web protobuf POST** 拉取，非普通 JSON/fetch：
  - `POST <智搜>/SearchService.SearchService/search`（content-type: `application/grpc-web+proto`）
  - `POST <智搜>/SearchService.SearchService/facet`
  - 附带 `MoreService/entityDi`、`MoreService/showColu` 等
- **点击"天津大学"即刻产生一条新的 `/facet` POST，其 protobuf body 中出现机构参数字符串字面量 `OrganizationNorm`**（v2 与 v4 两次独立运行均复现）：
  - v2 捕获 body（46 字节）：`\x1b\n\x05paper\x12\t太赫兹(\x010\x03B\x01\x00H\x01J\x10OrganizationNorm…`
  - `J\x10` = protobuf 字段号 9（tag `0x4A` = 01001 010 wiretype 2），长度 16 = 字符串 `"OrganizationNorm"`，其后即机构值负载
  - v4 再捕获同形 `/facet` POST（`orgNorm=True`）

## 3. 关键发现

1. **机构过滤字段名确认：`OrganizationNorm`**（真实 /facet POST protobuf 中捕获的字符串字面量，两次独立复现）。
2. **传输载体为 gRPC-web protobuf body，不是 URL 查询参数**；URL 恒为 `?q=<关键词>&p=<页码>`。
3. 页面内嵌 JS 状态（`__INITIAL_STATE__`/`__NUXT__`/`__NEXT_DATA__`）与 HTML/脚本中**均无** `organizationNorm`/`institution`/`orgName` 等明文 token（facet 数据全部走 POST 拉取）。
4. 机构行 DOM：`<div style="display:flex"><span title="天津大学" class="words">天津大学</span><span class="amount">(878)</span></div>`——**无传统 checkbox**，为可点选 chip；点击即触发含 `OrganizationNorm` 的 facet 查询。
5. 程序当前实现与"网页端机构过滤"的差距 = 缺少对 facet 面板交互的复刻（或对 gRPC 端点的调用）；与 `author_affiliation` 的映射路径完全未建立。

## 5. 后续修改建议（仅建议，未实现）

**验收标准回答**：程序**不能通过增加一个 URL 参数**让万方检索接近网页端机构过滤——网页端没有 URL 过滤参数，机制在 gRPC-web POST body 的 `OrganizationNorm` 字段。可行路径有二：

1. **UI 复刻（推荐，与详情 resolver 同技术栈、零协议逆向）**：
   - 普通搜索完成后，用 Playwright 交互左侧 `div.wf-facet-box:has(span.facet-title:text-is('机构'))` → 点目标行 `span.words`（已实测可触发 `OrganizationNorm` facet 请求）；
   - 随后等待 SPA 应用过滤并重新抓取结果列表（`_RESULT_RE` 复用）；
   - 前置验证项：过滤结果的重渲染交互时序（v2/v3/v4 三次点击均命中选项但未等到过滤后 /search，需确认最终"确认/应用"交互形态）。
2. **直接调用 gRPC-web `/search` 端点**：POST protobuf 含 `OrganizationNorm=天津大学`；需要先补齐两件证据：① 过滤后 `/search` body 完整字段布局；② 响应帧解码（gRPC-web framing）。成本高于方案 1。

**缺失证据清单**（若选方案 2 必须补齐；方案 1 可不依赖）：
- 一次成功应用过滤后的 `/search` POST 完整 body（断言 `OrganizationNorm=天津大学` 与其字段号）；
- 响应 body 的 gRPC-web 帧格式与分页字段。
- 另建议（非本次需求但相关）：万方结果无 `detail_url`（真实页面无 `<a href>`），机构过滤后若要"详情可开"需与已验收的 B′ resolver 联动。
