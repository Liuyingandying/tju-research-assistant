## 一、当前 GUI 架构

### 1.1 文件清单

| 文件 | 行数 | 职责 |
| --- | ---: | --- |
| `main.py` | 26 | 启动入口：创建 `QApplication` → `MainWindow.show()` → `exec()`。无主题、无资源加载 |
| `src/tju_info_retrieval/ui/main_window.py` | 397 | 主窗口：`_build_ui()` 内联创建全部 widget + `_on_*` 动作处理 + worker 信号接线 |
| `src/tju_info_retrieval/ui/worker.py` | 128 | `BrowserWorker(QObject)`：独立线程内按任务创建/释放 `BrowserSession`，封装 Playwright 操作 |
| `src/tju_info_retrieval/ui/__init__.py` | 1 | 仅 docstring，无内容 |

**整个 UI 只有 2 个实质文件**（主窗口 + 后台 worker），没有独立的 widget/视图/主题/资源模块。

### 1.2 主窗口 widget 结构

`MainWindow(QMainWindow)`，中央部件为单个 `QWidget` + `QVBoxLayout`（`main_window.py:66-67`）：

```
QMainWindow
└─ central QWidget + QVBoxLayout
   ├─ QGroupBox("检索条件") + QFormLayout          (main_window.py:69-119)
   │   ├─ 研究方向   : QLineEdit#input_direction    (:72-74)
   │   ├─ 扩展方向   : QComboBox#combo_expansion     (:76-82)  综合/理论/应用/综述
   │   ├─ 人员姓名   : QLineEdit#input_person        (:84-87)  禁用
   │   ├─ 人员单位   : QLineEdit#input_org           (:89-92)  禁用
   │   ├─ 数据来源   : QHBoxLayout(QCheckBox×4)      (:94-106) CNKI/万方/IEEE/其他(禁用)
   │   ├─ 结果数量   : QComboBox#combo_count         (:108-110) 10/20
   │   └─ 按钮行     : QHBoxLayout                   (:112-117) 检查授权状态 / 开始检索
   ├─ QLabel#label_status                           (:121-122) 状态栏（QLabel，非 QStatusBar）
   ├─ QTableWidget#table                            (:124-130) 6 列结果表
   └─ 底部按钮行 QHBoxLayout                        (:132-146) 打开全文/导出/生成报告/演示数据/关于
```

结果表列定义 `RESULT_COLUMNS = ["标题","作者","来源","年份","类型","数据库"]`（`main_window.py:36`），填充在 `_populate_table`（`:379-387`）。

### 1.3 layout 组织方式

- 顶层：`QVBoxLayout`（垂直堆叠：检索条件 → 状态 → 结果表 → 底部按钮）。
- 检索条件：`QGroupBox` + `QFormLayout`（标签/控件两列式）。
- 数据来源与按钮行：内嵌 `QHBoxLayout`。
- 结果表：`QTableWidget`，标题列 `Stretch`，行选中、单选、不可编辑。
- 线程：`QThread` + `moveToThread`，主窗口信号（`check_auth_requested/search_requested/open_detail_requested/shutdown_requested`）→ worker 槽，`QueuedConnection` 跨线程投递；worker 回发 `status_changed/auth_result/search_done/search_failed/error/detail_opened`。

### 1.4 样式文件

**无**。全项目无 `.qss` / `.css` / `setStyleSheet` / `stylesheet` 引用（已 grep 确认），UI 完全使用操作系统默认样式。因此“现代化”改造的第一步是引入统一主题层，这是全新能力而非替换。

### 1.5 资源文件

**无** `.qrc` / `.ui` / `.png` / `.svg` / `.ico` 等资源文件（已 find 确认）。唯一数据“资源”是内置演示数据 `src/tju_info_retrieval/demo_data.py`（可被 `runtime/demo_results.json` 覆盖），非视觉资源。

## 二、职责划分：布局 / 业务 / 可安全修改

### 2.1 谁负责布局

- **全部布局集中在 `main_window.py::_build_ui()`**（`:65-151`）——主窗口是唯一的视图构造点。
- `main.py` 仅负责启动，不参与布局。

### 2.2 谁负责业务逻辑

| 层 | 文件 | 职责 |
| --- | --- | --- |
| UI 编排 | `main_window.py` 的 `_on_*` 方法（`:182-376`） | 组装 `QueryRequest`、收集勾选数据源、调用 worker、刷新表格/状态、导出/报告文件对话框 |
| 后台编排 | `ui/worker.py` | 线程化浏览器会话与 `SearchService.search` 调用 |
| 纯业务 | `services/`（search_service / query_expansion / query_translator / query_builder / concept_segmenter / terminology / result_merger / ranking / export / report_generator / test_report） | 检索、翻译、去重、排序、导出、报告（均无 Qt 依赖，单测覆盖） |
| 数据模型 | `models/`（QueryRequest / SearchResult） | 纯数据 |
| 浏览器 | `browser/` | Edge 会话 / 门户导航 / Adapter |

### 2.3 哪些文件可以安全修改

| 文件 | 修改风险 | 说明 |
| --- | --- | --- |
| `main_window.py`（布局部分 `_build_ui`） | 中 | UI 重构主战场；**必须保留测试依赖的公开表面**（见第四节） |
| `main.py` | 低 | 可安全追加全局主题/字体/资源加载（QSS 接入点） |
| `worker.py` | 低 | 信号契约（`detail_opened`/`error`/`_new_session`/`_session`/`_service`）被 `test_worker.py` 依赖；本轮无需改动，保持稳定 |
| `services/`、`models/`、`browser/`、`demo_data.py` | 低 | 业务纯逻辑，与 UI 解耦；重构不应触碰（v0.9 目标只是 UI） |
| `tests/test_gui.py`（34）、`tests/test_worker.py`（6） | **禁止修改** | 按任务约束保持不动，重构以兼容现有测试为验收底线 |

## 三、UI 重构方案（v0.9，仅设计）

### 总体原则

- **分层但保持单文件结构友好**：新增主题层 + 主窗口局部重构，不推翻 `QMainWindow` + `QThread` 模型（线程模型已稳定且经真实验收）。
- **保持公开表面不变**：widget 属性名、`_on_*` 方法名、`_searching` 状态、窗口标题、worker 信号契约全部保留，保证 34 个 GUI 测试与 6 个 worker 测试不破。
- **样式优先用 QSS + objectName 选择器**，避免给每个控件硬编码 `setStyleSheet`。

### 3.1 Header 改造位置

- **替换点**：`main_window.py:69-119` 的 `QGroupBox("检索条件")`。
  - 改为 `QFrame#searchHeader`（卡片风背景 + 圆角 + 阴影），内部保留表单字段。
  - 顶部一行：应用标题/副标题（可用 `QLabel`，风格化字体）+ 右侧“检查授权状态”按钮与授权状态徽标。
  - 状态栏：`:121-122` 的 `QLabel#label_status` 升级为真正的底部 `QStatusBar`（或保留 QLabel 但改为顶部/卡片内徽标位）。**注意**：测试断言 `label_status.text()` 内容（如 `"检索失败"`、`"天津大学授权正常"`），改造后 `label_status` 属性必须保留并继续承载这些文本。
- **窗口标题**：`main_window.py:53` `setWindowTitle("信息自动检索整理系统")` 保持（测试断言），可叠加 `setWindowIcon`（需未来引入图标资源，本轮不新增文件）。

### 3.2 检索卡片化方案

- 将 `:69-119` 整体包成一张“检索卡片”（`QFrame` + objectName `searchCard`），QSS 统一卡片样式。
- 卡片内布局改为现代两行式：
  - 行 1：研究方向 `QLineEdit`（大字号、占主要宽度）+ 扩展方向 `QComboBox` + “开始检索”主按钮（主题色）。
  - 行 2：数据来源按钮组 + 结果数量下拉（收进右侧）。
- 保留字段：`input_direction`、`combo_expansion`、`combo_count` 属性名不变。
- 禁用态字段（人员姓名/单位）暂保留在卡片底部折叠区（标记“下一阶段”），或先隐藏（隐藏需评估 `input_person`/`input_org` 是否被测试引用——当前测试未引用，可安全隐藏/移除，但保留属性更稳妥）。

### 3.3 数据源按钮化方案

- **替换点**：`:94-106` 的 `QCheckBox` 行。
  - 改为可勾选 `QPushButton` 组（`setCheckable(True)` + 组合式分段按钮），用 `QButtonGroup`（非互斥，可多选）管理。
  - 视觉：选中态用主题色填充，未选中灰底；禁用“其他资源”按钮置灰。
- **兼容关键**：测试依赖 `chk_cnki.isChecked()`（`test_gui.py` 以 `chk_cnki/chk_wanfang/chk_ieee` 收集数据源）。方案二选一：
  1. **保留 QCheckBox 作为状态源**（`chk_cnki` 等仍存在），按钮组视觉层与 `isChecked()` 双向同步——零测试影响，推荐；
  2. 直接改按钮，则需同步改测试，违反“禁止修改测试”——不采用。
- 收集逻辑（`_on_search:194-200`）保持读 `chk_cnki.isChecked()` 等不变。

### 3.4 结果表优化方案

- **替换点**：`:124-130` 表格配置 + `:379-387` `_populate_table` + `:36` `RESULT_COLUMNS`。
- 优化项（保持 `self.table` 属性与 `rowCount()/item()` API）：
  - 交替行色 / 悬停高亮 / 选中主题色：QSS 选择器（`QTableWidget`、`QTableWidget::item:selected`）。
  - 列宽策略：标题 `Stretch`，其余 `ResizeToContents`（当前仅标题 Stretch）。
  - 表头排序：`setSortingEnabled(True)`（注意 `_populate_table` 需在填充后处理排序状态，避免插入期排序抖动）。
  - 行高/字体：`verticalHeader().setDefaultSectionSize` + 全局字号。
  - 可选新增列（需改 `RESULT_COLUMNS`）：`会议/期刊`（`SearchResult.venue`，v0.8.2 已有）、`链接/摘要` 提示列。测试只断言第 0 列标题与 `rowCount()`，加列安全。
  - 空态提示：无结果时显示居中占位（`QTableWidget` 上方叠加或 `NoItem` 样式）。

### 3.5 QSS 主题接入位置

- **主接入点**：`main.py` 创建 `QApplication` 之后、`MainWindow` 之前（`main.py:17-18` 之间）调用 `app.setStyleSheet(THEME_QSS)`。
- **主题来源（未来）**：新增 `src/tju_info_retrieval/ui/theme.py` 提供 `THEME_QSS` 常量（或 `styles.qss` 资源文件）；当前审计阶段**不新增文件**，仅标注接入位置。
- **选择器基础**：为关键控件设 `objectName`（`searchCard`、`searchHeader`、`sourceGroup`、`resultTable`、`btnSearchPrimary` 等），QSS 用 `QFrame#searchCard`、`QPushButton#btnSearchPrimary`、`QTableWidget#resultTable::item:selected` 精准作用。
- 颜色/间距/圆角定义成 QSS 变量风格（QSS 无原生变量，可在 `theme.py` 用 f-string 常量拼装，或未来引 CSS 变量方案），保证一套主题可整体替换（含“夜间模式”预留）。
- 图标：QSS 可引用 `url(:/icons/...)`，需未来 `.qrc` 资源；本轮先用内置矢量（`QStyle.StandardPixmap`）或纯文字按钮占位。

重构后必须保持以下公开表面（来自 `tests/test_gui.py` 34 项 + `tests/test_worker.py` 6 项断言）：

| 表面 | 要求 |

## 五、风险与建议

1. **测试耦合是主要约束**：属性名与方法名是重构的硬边界。若未来想彻底解耦（如引入 `QTableView + Model`），需先在本轮将测试改为按 `objectName` 查询控件，属后续阶段工作，不在本轮。
2. **无现有主题基线**：首次引入 QSS 是全新能力，建议先在 `main.py` 全局样式小步验证（字体/间距/配色），再逐块改造卡片与表格，避免一次性大面积改动难回滚。
3. **结果表交互**：开启排序后需回归 `_on_search_done` 的填充路径，防止插入期排序导致行错乱。
4. **状态栏语义**：`label_status` 现在是纯 `QLabel`；若升级为 `QStatusBar`，需保留 `label_status` 属性名作为同一文本载体（或保留 QLabel，仅换位置/样式）。
5. **演示数据按钮**：`btn_demo` 保留（测试依赖 `_on_load_demo` 语义），重构只改其外观。

## 六、结论

当前 GUI 是**单一 `QMainWindow` + 内联 `_build_ui()` + 无主题**的 MVP 结构：布局全部集中在 `main_window.py`，业务逻辑在 `worker.py` 与 `services/` 中已良好解耦，UI 层与业务层边界清晰。现代化重构的**主战场是 `main_window.py` 的呈现层**（检索条件区改 Header/卡片、数据源改按钮组、结果表优化），**QSS 主题接入点选在 `main.py` 的 `QApplication` 之后**；通过保留测试依赖的公开表面，可在不改测试、不动业务逻辑的前提下完成现代化改造。**无需推翻现有架构**，属于“呈现层增量重构”，而非“架构重构”。
