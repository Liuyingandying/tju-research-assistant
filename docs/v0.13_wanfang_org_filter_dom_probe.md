## 4. 必答问题：真正触发机构过滤的 DOM 元素是什么？

**在当前站点（天津大学代理 → 万方智搜）环境下：不存在可提交机构过滤的 DOM 元素。**

实证支持：
1. “天津大学”行的可交互控件是 `label.checkbox.limitcheckbox` 内的**隐藏复选框**（`ivu-checkbox-input`）——点击会翻转选中态（视觉高亮 + checked 属性），**但从不产生过滤查询**；
2. 控制组证明这不是机构组的特例：自始有复选框的常规 facet（“有全文”）勾选也同样零请求、零结果变化——**整个左侧 facet 复选框体系在该 SPA 视图下都不把勾选提交为 /search**；
3. “更多”（`span.more-item`）入口点击后无面板/无提交按钮，页面未渲染任何机构完整列表或确认控件；
4. 全流程唯一发出的相关请求是 `POST /facet`（body 含 `OrganizationNorm` 字段名，字段号 9）——属于**选项查询**，不是过滤提交。

一句话结论：**该视图中“机构=天津大学”过滤不存在可点击提交的元素；热词/复选框是视觉可选中但不生效的展示组件**（类名 `limitcheckbox` 即“受限展示”语义）。

## 5. 推断与缺口证据

真人操作若确能使“找到878条”，其生效路径必在我们的会话外，候选：
- **机构登录态差异**：当前代理会话为游客态（页面可见“登录/注册”）；机构过滤提交可能在机构账号登录态下才启用（面板/提交控件随登录态渲染）。
- **其它入口**：高级检索页的“机构”字段（此前 dump 可见“题名/作者/关键词”输入框，机构字段未展开核查），而非结果页左侧 facet。
- 需补证据：① 机构登录态下重放本探针；② 高级检索页机构字段的请求捕获。
