## 1. 本次 UI Hotfix 实际修改内容

### 1.1 `src/tju_info_retrieval/ui/main_window.py`

1. **自适应底部按钮栏 `_ResponsiveActionBar`**（新增 widget 类）
   - 宽窗口：10 按钮单行、均分 stretch（保持原观感）；
   - 窄窗口（如 1366×768@125% 逻辑宽 ≈1093）：自动切 5+5 两行；
   - 判定基准为按钮 `minimumSizeHint` 总和 + 间距，滞回 8px 防临界抖动；
   - relayout 仅用 `takeAt`/`addWidget` 在行间迁移按钮，不 hide/show，避免重入；
   - `_build_bottom_bar` 由返回 `QHBoxLayout` 改为返回该 widget；`_build_ui` 对应 `addWidget`。
2. **主窗口最小尺寸**：1100×656 → **920×560**（容纳 1366×768@125% 逻辑工作区约 1093×582，宽度不再依赖 10 按钮单行全宽）。
3. **默认尺寸随屏幕 `availableGeometry` clamp**（保留，去除旧的 max(1100/656) 下限）。
4. **搜索卡**：移除 `columnMinimumWidth(240/200)` 硬约束，列比例仅由 stretch（0/5/0/3）决定——窄逻辑宽下输入框自然变窄，不重叠/不消失。
5. **人员单位区**：单位输入与「匹配模式」下拉由垂直堆叠改为**水平并排**；二者均显式 `setMinimumHeight(30)` + `QSizePolicy`（输入 Expanding、下拉 Fixed），高度由 layout 自然决定，不固定行高。
6. **垂直压缩**：header 84→48、section tab→26、搜索卡 margins/spacing 收紧、主操作按钮行高 36→32、ActionBar 按钮高 38→32、status strip 边距收紧、footer→26、root margins/spacing 收紧。

### 1.2 `src/tju_info_retrieval/ui/theme.py`

- `QLineEdit` padding 8px→6px、`QComboBox` padding 7px→5px（垂直方向，字号/配色不变）——输入控件最小高下降，为小屏表格让出空间。
- 曾临时新增 `QSpinBox` QSS 规则用于压缩数字输入框高度；**最终已移除**（保留 Qt 默认外观）。移除依据：该规则与全局 QSS 的组合在长时间多窗口套件中伴随 0xc0000374 堆损坏复现；移除后获得过一次完整 clean run（§7），故不保留该规则。

### 1.3 `tests/test_gui.py`

- 新增 `TestResponsiveActionBarLayout`（6 项）：宽窗口单行 / 窄窗口(1093)两行且 5+5 / 两行模式按钮不裁切 / 单行模式按钮不裁切 / 变宽回单行。
- 窗口在类级共享创建一次（`setUpClass`），仅改变 resize，避免逐测试建窗放大长套件 Qt 生命周期负担。

## 8. TEST ENVIRONMENT / LONG-SUITE STABILITY BLOCKED
- 现象：全量长套件在浏览器测试区（真实 Edge persistent-context fixture）与后续大量 Qt GUI 实例混合运行时，出现**非确定性原生崩溃**（`Windows fatal exception 0xc0000374` 堆损坏），崩溃点随运行漂移（不同轮次 37–47% 区间不等）；同代码有时完整 1096 passed、有时中断。
- 关联因素：用户常开 Edge（18–21 进程）与测试内 Playwright module-scope 实例的累积；长套件中 40+ MainWindow × worker 线程的 Qt 堆生命周期；该问题在本项目历史中已有记录（"38 errors Edge fixture 瞬时争用"类）。
- 判定：**TEST ENVIRONMENT / LONG-SUITE STABILITY BLOCKED** —— 不归入本轮 UI Hotfix，不再扩大排查，不把环境问题修进 UI 代码。
- 单文件 / 针对性 UI 测试可**稳定**通过（§6）；后续反复 full-suite 重跑边际收益不足，本轮按指示停止。
