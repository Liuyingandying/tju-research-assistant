## 2. 架构变化

```
用户（普通）                       开发者（兼容）
   │                                  │
   ▼                                  ▼
SettingsDialog  ◄───────────  runtime/summary_provider.json（既有格式）
   │ 保存/测试                            │
   ▼                                     ▼
APIConfigManager ──────────────────► OpenAICompatibleProvider（协议不变）
   ├─ 配置 JSON：frozen→%LOCALAPPDATA%\TJU_Info_Retrieval\config\；
   │            开发→runtime/（向后兼容既有）
   └─ API Key：Windows Credential Manager（keyring，service=
                TJU_Info_Retrieval_AI, username=default）
                不可用 → LocalAppData/config/secret.json（不进 git/package/
                reports/日志）
   │
   ▼
SummaryService（不变） → LLMEnhancedProvider → EnhancedSummary
```

- 保持 `SummaryService → LLMEnhancedProvider → OpenAICompatibleProvider` 不变；
- SummaryService 构造时传入 `APIConfigManager.provider_config()`（key 仅内存注入）；
- 保存配置后 `_refresh_summary_service()` 重建增强 Provider（basic 不变）。

## 3. 安全策略

1. **API Key 不落 JSON**：`save_config` 剥离 `api_key` 字段（测试断言 JSON 无明文）；
2. **keyring 优先**：Windows Credential Manager（service=TJU_Info_Retrieval_AI）；
   keyring 不可用才降级 secret.json（隔离目录，runtime/ 已 gitignore）；
3. **日志零输出**：新模块无 logger；llm_provider 的 Authorization 只在
   requests 调用内构造；summary_worker 日志只记异常类型；
4. **provider_config 内存注入**：key 只在返回 dict 中，绝不落盘；
5. **扫描**：dist/zip/reports/logs/docs 无真实凭据模式命中；runtime 无
   secret.json 残留；测试仅占位 key。
