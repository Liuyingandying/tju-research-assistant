## 1. source / database / media 最终语义（审计结论）

`SearchResult.source` 审计：**不参与任何内部 grouping/routing**——
citation_selector 按 `database` 分组（citation_selector.py:68）、merger 按
doi/url/(artifact_type,title) 去重、ranking 按 database 权重、FilterService
按 artifact_metadata。故：

| 字段 | 值 | 语义 |
| --- | --- | --- |
| database | `"天津大学新闻网"` | = registry source 名（与 万方专利 同理由） |
| source | **真实媒体名**（健康报/科技日报/精仪学院…） | 来源列直接显示真正媒体（无内部语义，测试锁定） |
| artifact_metadata.media | 同 source | NewsMetadata 正式字段（Phase 2.1 schema，无 byline） |
| artifact_type | `"news"` | — |
| authors | 详情署名（记者）镜像；媒体名绝不入 authors | — |

## 2. Adapter 架构

`src/tju_info_retrieval/sources/tju_news.py`（独立模块，与论文/专利零耦合）：
- `TjuNewsAdapter.search()`：路由 + 列表解析 + 组合策略 + bounded enrichment；
- `parse_dateline` / `parse_arc_info`：纯函数（媒体行/署名行正则，真机形态容错）；
- `TjuNewsDetailResolver`：detail_url + authors bounded enrichment
  （cap≤8 / 单项≤5s / 总预算≤30s / 缓存 / 失败降级 / 不伪造）；
- 复用 `session.context` 同槽开页（公开站点，无需授权会话；生命周期约束遵守）。

## 3. 搜索入口策略（按任务 §七）

**主路径 = 正常页面提交**：新闻网首页 `input.qwss` 填关键词 → Enter →
新标签搜索结果页（expect_page 捕获，同页跳转有兜底分支）。构造直达 URL
（base64 payload，token=tourist）已在 PoC 验证并保留为文档化备用
（`build_search_url`），不作主路径。无凭据、无一次性 token、无私有 API 逆向。

## 4. topic / person / 组合查询（编码前探针 + 真机验证）

- **topic only**：原始中文 research_direction（"太赫兹"→约 15 条真实科研新闻；
  不继承 IEEE 英文 Boolean，不做扩展）；纯 person 模式不运行 topic 扩展链
  （Phase 1 语义，SearchService 层已保证）。
- **person only**：全文搜索框按人名检索（PoC：田震 → 当选会士新闻）。
- **组合语义（预编码探针 09 json 证据）**：站点多词查询=短语匹配——
  "太赫兹 田震" → **0 条**（两单词各自有结果）；且 topic 搜索不命中正文层
  （田震 Fellow 文章正文含"太赫兹"却不在 topic 结果中）→ 标题交集方案不可行。
  **最终策略**：以 person 结果为基（数量通常少），bounded 打开详情后验证
  标题/摘要/正文含 topic 关键词者保留——真实 AND，宁缺毋假；
  超 enrichment 上限（8 条）的 person 结果不保留并在代码注释/报告说明。
  真机验证：太赫兹+田震 → 恰好 1 条（Fellow 文章，正文含"太赫兹光子学"）✓。

## 5. readiness

统计条「相关结果约为 N 个」出现（真实 0 条也带统计）+ 连续 2 次稳定——
区分真实 0 条与未加载；无陈旧渲染（每次首页新开导航）。

## 6. Parser（列表页，selector 均来自 PoC 03/04/05/08 json）

- title：`a.title`（含高亮 span）
- summary：`p.desc`
- 媒体行：`div.createDate_style` =「<分类> <媒体>-<YYYY-MM-DD HH:MM:SS>」
  → `parse_dateline` 正则拆分（媒体聚焦/健康报/2025-07-17 15:54:40）

## 7. 详情 enrichment

详情页 `div.arc-info` =「日期 作者：…编辑：…来源：…」→ `parse_arc_info`
非贪婪正则 → authors（空白/顿号拆分）+ media（列表缺失时兜底）。
content_head（正文前 1500 字）为**瞬态属性** `_news_content_head`，仅供
组合 topic 过滤，不入 to_dict / artifact_metadata。

## 8. Enrichment 上限（结合 quota 审计）

cap = 8（与专利 resolver 同理：不随 CITATION candidate_quota(≤50) 放大）；
单项 ≤5s、总预算 ≤30s、缓存按归一化标题（进程级、上限 500）、失败降级。

## 9. SearchResult 映射

```python
SearchResult(title=..., authors=[]→署名镜像, source=媒体名, year=发布年,
             detail_url=点击捕获, document_type=分类（媒体聚焦/综合新闻）,
             database="天津大学新闻网", abstract=列表摘要,
             artifact_type="news",
             artifact_metadata={"media":…, "publish_time":…, "authors":…,
                                "related_person":[person 若正文/标题真实出现]},
             citation_count=None)
```

## 10. NewsMetadata

严格 Phase 2.1 schema（media/publish_time/authors/related_person）；
无 byline（测试锁定）；related_person 仅在有真实文本证据时写入。

## 11. Filter 集成（filtering.py 零修改）

related_person / metadata.authors / authors 匹配命中保留；publish_time 区间
（year → publish_time）；人物元数据全缺失 → 保留（unknown≠mismatch）。

## 18. 剩余风险

1. 搜索范围限于天大新闻网（含转载）——非天大关联的方向命中少；
2. 组合策略以 person 结果为基：person 命中超过 cap(8) 时仅前 8 条参与
   topic 验证（宁缺毋假，已文档化）；
3. 站点多词=短语的引擎语义由单点探针得出（09 json），改版可能变化——
   组合结果为空时会显式报错而非静默退化；
4. 详情署名/来源行格式依站点模板（arc-info），少数文章可能字段缺失
   （降级为空，unknown 保留）。

## 19. Phase 2.3-C 建议

   内部 source「天津大学新闻网」，无支持组合明确提示）；
3. strict × news 语义提示（strict 下新闻元数据缺失会被删，需用户知情）；
4. UI 来源列展示真实媒体 + 类型列「新闻」标签（Phase 2.1 已就绪）。
