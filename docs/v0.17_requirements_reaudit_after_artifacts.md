## 2. 重点复审 R2：扩展方向跨源真实传播

代码证据链：
- `query_expansion.py`：方向限定词（理论=理论/机理/原理…，应用=应用/系统/装置…，
  综述=综述/进展/研究现状…）进入 `expanded.query_string` 与 `expanded.filters`；
- `query_translator.py:59`：中文源 concepts = `[[expanded.query_string]]`（含方向限定）；
  `query_translator.py:69`：**IEEE 概念仅切分 `expanded.original`** —— 方向限定词
  从不进入 IEEE 查询；
- 各 Adapter 关键词来源：CNKI = 扩展串（✅ 方向生效）；万方论文
  （wanfang.py:193）/ 万方专利（wanfang_patent.py:289）/ 新闻（tju_news.py:144）
  = 原始 `research_direction`（❌ 方向 no-op，属 v0.13 起的 source-specific
  routing 设计——万方不接受 Boolean）。

回答任务书问题：
1. **真正读取 expansion_direction 的来源：仅 CNKI**；
2. "应用"在 CNKI 附加 `(应用 OR 系统 OR 装置 OR 实现 OR 工程)`；
3. "理论"在 CNKI 附加 `(理论 OR 机理 OR 原理 OR 模型 OR 算法)`；
4. "综述"在 CNKI 附加 `(综述 OR 进展 OR 研究现状 OR 展望 OR 回顾)`；
5. 万方论文 / 万方专利 / 新闻 = 原始词直搜（方向无影响）；IEEE = 同义词水平
   扩展（与方向无关，方向 no-op）。

**结论：R2 = PARTIAL**（输入 UI 完整，查询效果仅单源真实）。

## 4. 重点复审 R13：结构化关键信息

现状盘点：
- **有**：三类型的 title/authors/abstract/完整 metadata；论文详情 metadata
  pipeline；专利详情 og 结构化字段（发明人/IPC/法律状态）；新闻详情全文/署名；
  Markdown/JSON/CSV 导出；推荐理由 = RankingService 评分拆解（非内容总结）。
- **无**：SummaryService / ContentExtractor / AI provider / 结构化四字段
  （研究内容/核心技术/主要成果/应用价值）——grep 全零命中；报告为书目模板。

**结论：R13 = PARTIAL**（"整理"目前 = 书目元数据 + 摘要获取；老师要求的
核心技术/主要成果结构化输出完全缺位）。这是当前**最大的演示叙事缺口**。

## 5. R9 / R11 与"等"字的需求风险判断

- R9 著作 / R11 获奖：无真实来源，MISSING。
- 老师原文："能够根据研究方向或人名自动检索：论文、著作、专利、获奖、新闻
  报道**等**"——"等"为开放列举；评分按"功能要求满足度"整体衡量。
- 判断：论文+专利+新闻三类真实闭环已覆盖"自动检索科研成果并整理"的主叙事；
  著作/获奖与论文/专利展示高度重叠、且均无稳定免费来源（获奖信息散落新闻/
  机构官网，易碎）。**建议不投入开发**，演示口径：artifact_type 类型层已为
  著作/获奖预留扩展位（ARTIFACT 常量 + 类型感知 Filter/Merger/UI 均已通用），
  来源接入按需扩展。

## 7. 最危险剩余缺口

1. **R13 结构化总结**——老师任务书原句要求（"整理每项成果的关键信息，例如
   核心技术、主要成果"），当前零实现；演示时"整理"环节只能展示书目字段，
   是主叙事最弱一环。
2. **R2 扩展方向仅 CNKI 生效**——老师任务书明确列举例（应用/理论/综述）；
   演示时若在万方/IEEE 切换方向看不到差异，属于"UI 有控件但无效果"的观感风险。

## 8. 剩余优先级排序（9/27 前开发时间分配）

| 优先 | 项 | 理由 |
| --- | --- | --- |
| **1** | **B. R13 结构化总结** | 任务书明确原句要求 + 当前零实现（最大缺口）+ 三类型摘要/详情数据基础已就绪（边际成本低）+ 演示价值最高（"整理"是系统名称本身）+ 单条用户触发可控制成本/幻觉边界 |
| **2** | **A. R2 扩展方向跨源生效** | 任务书明确举例 + 现仅 CNKI 生效 + IEEE Boolean 加方向组/万方主题行组合成本可控；风险：不得破坏万方 original_keyword 路由（既有回归区），专利/新闻可诚实标注"方向不适用" |
| 3 | D. R11 获奖 | 无稳定来源，成本高、易碎、演示价值低 |
| 4 | C. R9 著作 | 无稳定来源，与论文展示重叠，价值最低 |

明确不默认"功能越多越好"：R9/R11 的开发时间投入对评分与演示的边际贡献
显著低于 R13/R2，且新增来源会带来新的维护面（9/27 冻结前风险）。

## 9. 核心决策问题的明确回答

**9/27 前最值得投入的是 2（结构化总结，R13），其次 1（扩展方向跨源），
不投入 3（著作/获奖）。**

理由：
- R13 是任务书唯一"当前完全缺位"的明确要求项，且是系统名"信息自动检索
  **整理**系统"的核心动作；三类型的摘要/详情文本获取链已全部就绪，
  只差"选中单条 → 结构化输出"一层（Phase 0 P0-6 已有设计：用户触发、
  provider 可换、AI 标注、失败不影响检索）；
- R2 有真实但单源的能力，补齐为"跨源一致"属增强性质，且万方/专利/新闻
  的原始词路由是踩坑后刻意设计，改动需谨慎；
- R9/R11 无来源基础，硬接会产生易碎链路，损害 9/28 演示稳定性。

## 10. 可以停止扩展的功能

- R9 著作 / R11 获奖：停止来源开发（类型层扩展位保留即可）；
- 新闻"热度排序"、artifact-level quota 配比、英文模式新闻：明确不做
  （9/27 冻结前不新增面）；
- strict × 新闻元数据：保持现有阻止/提示语义，不做 NER 补元数据。

## 11. 9/27 前开发计划建议（仅建议，不启动）

1. **Phase 2.4（建议下一步）：R13 结构化总结最小链**
   - 单条选中触发（论文/专利/新闻通用）→ 摘要/详情文本 → 结构化四字段
     （研究内容/核心技术/主要成果/应用价值）→ AI 标注 + 来源文本展示 →
     失败/无文本降级不影响检索；provider 选型先行 PoC（含成本评估）。
2. **Phase 2.5（时间允许）：R2 扩展方向跨源**
   - IEEE：方向限定词译英并入 Boolean 组；
   - 万方论文：主题行 + 方向词行组合（或诚实标注不支持，以探针定）；
   - 专利/新闻：文档标注"扩展方向不适用"；
   - 全程不得破坏万方 original_keyword 路由（回归区）。
3. **冻结前**：演示脚本固化（默认论文路径 + 专利/新闻类型切换 + 总结单条
   触发），不再新增功能面。
