# v0.7.1 授权流程修复

> 日期：2026-09-02。对应审计文档：`docs/debug_authorization_flow.md`。
> 范围：最小修改，不重构；未触碰 Adapter / SearchService / GUI 布局 / 数据源逻辑。

---

## 1. 修改原因

真实运行 `python main.py` → 点击“检查授权状态”时：

- 弹出 Edge 后页面**立即关闭**；
- GUI 显示“无法确定天津大学授权状态”。

审计结论（详见 `docs/debug_authorization_flow.md`）：

1. **RC-1 时序竞态**：`check_tju_auth` 用 `goto(domcontentloaded)` + 固定 `sleep(2.5s)`
   后**单点采样** URL/body。门户 `p.lib.tju.edu.cn/` 是 Angular SPA，会客户端重定向到
   `p.lib.tju.edu.cn/login`（Edge History 证据：加载后约 2s 重定向）。若采样早于重定向，
   URL 无登录特征、body 未渲染“已授权/登录” → 误判 `unknown`。
2. **RC-2 立即释放**：`worker.check_auth` 的 `finally` **无条件** `_release()` →
   `context.close()`，无论结果如何 Edge 都会马上关闭；GUI 提示“请在受控浏览器中完成
   官方登录”时浏览器其实已不存在，用户无从登录。

本次修复目标：检查等待改为**条件轮询**（不再依赖固定 sleep 判断），并让
`login_page` 时**保持 Edge 打开**供用户完成官方登录。

## 3. 生命周期变化

### 3.1 `BrowserSession.check_tju_auth`（session.py）

**之前**：`goto` 后固定 `sleep(2.5s)`，单次读取 `page.url` + `inner_text("body")` 判定；
读取异常**静默**返回 `unknown`。

**之后**（`timeout_ms=15000` 默认）：

```
轮询（0.5s 探测间隔）直到任一条件出现，或超时：
  1) is_login_url(page.url)          → login_page
  2) body 含 "已授权"                 → logged_in
  3) body[:150] 含 "登录"            → login_page
  超时仍未判定                        → 记录现场日志，返回 unknown
```

- 判断依据是**条件轮询**；`time.sleep(0.5)` 仅作探测间隔让步，不是判断依据。
- 单次读取异常（页面导航/执行上下文销毁）不再直接判 unknown，而是记录异常后**继续轮询**。
- 返回 `unknown` 前记录现场：`page.url` / `page.title()` / `context.pages` 数量 /
  `body` 前 200 字符 / 异常 `traceback`（`_log_unknown`，`logger.warning`）。
- `open_tju` 移除固定 2.5s：等待跳转稳定完全交给 `check_tju_auth` 的条件轮询
  （PortalNavigator 有自己的 120s 就绪等待，不受影响）。

### 3.2 `BrowserWorker.check_auth`（worker.py）

**之前**：`finally: self._release()` 无条件关闭 Edge。

**之后**：

```
check_auth():
  state = service.check_tju_auth()
  auth_result.emit(state)
  若 state == "login_page"  → 不释放：保持 Edge 打开，供用户在受控浏览器中完成官方登录
  否则（logged_in / unknown）→ 释放临时会话（Profile 保留）
  异常                           → 上报错误并释放（清理失败会话）
```

- `login_page` 保持的会话：交给下一次任务 `_new_session()`（会先关闭旧会话）或
  窗口关闭时的 `shutdown()` 统一释放。
- `unknown` 保留原安全策略（释放），现场日志由 `check_tju_auth` 负责。

## 5. 已知限制

1. **启发式仍基于文本**：`check_tju_auth` 依赖 `已授权` / `登录` 关键词与
   `is_login_url` URL 子串。若门户 DOM 文案或重定向 URL 变化，需同步调整
   （`poc_browser.is_login_url` 的 hint 列表）。
2. **`login_page` 保持的浏览器由用户手动关闭或下个任务接管**：再次点击检查时
   `_new_session` 会先关闭旧 Edge 并 `sleep(5s)` 再启动（既有的“等旧进程退出”策略），
   存在约 5s 的额外等待。
3. **`unknown` 仍释放浏览器**（安全策略）：用户面对 `unknown` 无法直接在受控
   Edge 中操作；建议结合日志（url/title/pages/body/traceback）判断后重试或先手动
   用 `poc_browser.py` 完成登录。
4. **真实浏览器测试依赖在线 TJU 会话**：`test_portal` / `test_wanfang` 的真实浏览器
   fixture 需要 `runtime/edge_profile` 中 TJU 授权有效，且同一时刻不能被其他 Edge
   进程占用（并发会偶发失败）。离线 CI 建议排除这两类测试。
5. **历史崩溃（RC-4）未在本轮处理**：Crashpad 曾记录 `0xc0000005` 崩溃；本次未修复
   浏览器崩溃本身，但读取异常现已带 traceback 落日志，可据此区分“崩溃”与“导航中”。
6. **版本号已随本次发布升至 `0.7.1`**：`src/tju_info_retrieval/version.py`、
   `README.md`、`scripts/run_acceptance_check.py`（`check_version_info` 断言）与
   `tests/test_acceptance_check.py` 已同步；后续再次升级需同时更新以上四处。
