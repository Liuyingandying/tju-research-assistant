# v0.17 课程任务书覆盖实施路线

目标：2026-09-27 主体冻结；2026-09-28 可向老师演示“论文 + 专利 + 中文新闻 + 选中条目关键信息总结”的科研信息检索整理闭环。  
依据：`docs/v0.17_requirements_traceability_audit.md`。  
本文件是 Phase 0 路线，不实施代码。

## 1. 优先级原则

- **P0**：直接修复任务书明确缺口；没有它就仍是论文搜索器。
- **P1**：把 P0 能力串成稳定、可解释、可导出的演示闭环。
- **P2**：不影响 9 月 28 日主叙事的扩展；时间不足立即停止。
- citation ranking、更多排序算法、纯 UI 美化不列 P0。

## 2. 推荐实施顺序

### P0-1：允许“研究方向 OR 人员姓名”启动检索，并完成三源人名 E2E

| 项 | 内容 |
| --- | --- |
| 对应需求 | R3、R14 |
| 预计模块 | `ui/main_window.py`、`models/query.py`、`services/search_service.py`、`services/query_expansion.py`；CNKI/Wanfang/IEEE adapter 仅做确有证据的最小作者语义补齐 |
| 新数据源 | 否 |
| 新依赖 | 否 |
| PoC | 构造 `research_direction="", author_name="张三"`，验证请求能进入服务；先用 fake adapters 明确每源收到的 author 条件/降级 query |
| 新增测试 | UI direction-only/name-only/both/neither；QueryRequest OR 校验；SearchService author-only；CNKI native author；万方/IEEE author 策略；三源组合语义 |
| 风险 | ExpansionService 当前必须有方向；万方/IEEE没有原生 author query；姓名重名与作者元数据缺失 |
| 成功标准 | A 仅方向、B 仅姓名、C 方向+姓名、D 姓名+单位均有确定行为；三源至少 fixture PASS，并形成用户执行的真机清单 |
| 停止条件 | 若某源无法可靠 native author，明确标 `local-filter` 并保证不误称原生；不得用扩大抓取数量无限补偿 |

这是推荐的第一项实施任务：改动面可控、直接修复任务书原句、也为新闻/专利的 related person 查询定义输入语义。

### P0-2：让四种扩展方向在三源真正产生不同查询

| 项 | 内容 |
| --- | --- |
| 对应需求 | R2 |
| 预计模块 | `query_expansion.py`、`query_translator.py`、`query_builder.py`；必要时 adapter 只消费结构化 intent，不直接接不兼容 Boolean 串 |
| 新数据源/依赖 | 否 / 否 |
| PoC | “太赫兹”四方向分别打印 CNKI/万方/IEEE 最终 query；断言应用/理论/综述概念进入英文路由 |
| 新增测试 | 四方向×三源 query snapshot；未知方向校验；万方不接受 Boolean 时的字段化构造；source-specific routing 回归 |
| 风险 | 直接把中文限定词塞给 IEEE；万方把括号/OR 当字面文本；扩展过严导致 0 结果 |
| 成功标准 | 四方向不是标签差异；每源最终查询有可解释差异，综合不附加垂直限定；现有论文检索不回归 |
| 停止条件 | 若某站不支持复合语法，则用该站原生字段/本地轻量重排，文档明确能力，不伪造统一语义 |

### P0-3：建立多类型 `ResearchArtifact + typed metadata` 兼容层

| 项 | 内容 |
| --- | --- |

| 成功标准 | 旧论文路径零行为变化；新 adapter 不必伪装论文；JSON/报告能保留 typed metadata |
| 停止条件 | 不做全仓一次性替换；若兼容层导致 UI/adapter 大面积重构，缩回只服务 patent/news 新路径 |

### P0-4：真实专利最小链

| 项 | 内容 |

### P0-5：中文新闻网站 + News Result

| 项 | 内容 |
| --- | --- |

| 预计模块 | `NewsAdapter`、`NewsMetadata`、registry/service、UI 来源与类型、详情、export/report |
| 新数据源 | 是；P0 先 1 个稳定中文科研/高校新闻源，P1 再评估第二源 |
| 新依赖 | 首选否；优先 RSS/稳定 HTML + 标准库/现有 Playwright |

| 风险 | 页面易变、robots/访问限制、新闻与科研成果相关性不稳定 |
| 成功标准 | 至少一源真实返回新闻，UI 明示“新闻”，不使用论文 authors/venue 伪装；证据含真实 URL/date/media |
| 停止条件 | 无稳定许可/结构则换源；不得以通用搜索结果截图替代生产 adapter 证据 |

### P0-6：用户选中条目的结构化关键信息总结

| 项 | 内容 |
| --- | --- |
| 对应需求 | R13 |
| 预计模块 | 新 `ContentExtractor`、`SummaryService`、provider protocol、summary cache/typed model；详情窗口、report/export 最小接线 |
| 新数据源 | 否 |
| 新依赖 | 待 provider PoC；优先复用现有模型能力/标准库，不先引入 SDK |
| PoC | 以固定摘要 fixture + fake provider 输出 `research_content/core_technology/main_results/application_value` |
| 新增测试 | schema 校验；无摘要；详情失败；provider 超时/非法 JSON；缓存命中；AI 标签；原文与 AI 字段隔离 |
| 风险 | 当前仓库没有模型 provider；幻觉；延迟/费用；批量调用；敏感文本外发 |
| 成功标准 | 用户主动选择一条才调用；有来源文本才总结；四字段结构化显示并标“AI总结”；失败不影响检索；缓存可复用 |
| 停止条件 | 不批量总结 20/30 条；无来源文本不调用；provider 未明确授权/配置时只保留离线 fake，不外发内容 |

## 3. P1：演示闭环

### P1-1：统一展示、详情、导出和报告

- 预计模块：`main_window.py`、artifact renderer、`export.py`、`report_generator.py`、详情窗口。
- 内容：类型 badge/筛选；共同字段列；专利/新闻 typed 字段详情；结构化总结和来源证据；报告按类型分组。
- 测试：paper/patent/news 混合列表、选择详情、JSON/CSV/Markdown、空 optional 字段、AI 标记。
- 风险：表格硬编码 6 列、旧导出固定论文字段。
- 成功标准：一次演示可搜索并查看三类结果，选一条生成总结，最后导出报告。
- 停止条件：不做视觉重设计；只增加清晰的类型/详情/总结入口。

### P1-2：第二新闻源或专利备源

- 仅在 P0 主链稳定后做；目的为避免单站临时不可用。
- 不要求第二源达到论文 adapter 复杂度；同一 typed contract + fixture + 一次真机证据即可。
- 若 9 月 20 日前 P0-4/P0-5 尚未稳定，本项取消。

### P1-3：课程要求验收包

- 更新 Requirements Matrix，每个 PASS 附 UI→Request→Service→Adapter→Parser→Result→Tests 证据。
- 生成离线 pytest、fixture、真机探针清单与用户 GUI 验收表。
- 成功标准：老师可在 5-8 分钟内看到方向/人名、扩展方向、中文/外文、论文/专利/新闻、单条关键信息总结、导出。

## 4. P2：时间允许才做

| 项目 | 优先级理由 | PoC/停止条件 |
| --- | --- | --- |

| 更多排序/排名/UI 美化 | 不增加任务书覆盖率 | 冻结到 9/28 之后 |

## 6. 预计测试增量

最小新增测试组：

1. `test_query_entry_semantics.py`：direction/name OR 校验与四组合。
2. `test_author_search_contract.py`：三源 author native/local-filter 策略。
3. 扩展现有 expansion/translator/builder：四方向×三源最终 query。
4. `test_artifact_model.py`：base + Paper/Patent/News typed metadata。
5. `test_patent_adapter.py`：离线 fixture parser、失败语义。
6. `test_news_adapter.py`：离线 fixture parser、URL/date/media/summary。
7. `test_summary_service.py`：fake provider、schema、缓存、失败、证据不足。
8. 混合类型 GUI/export/report 测试。
9. 真机测试不纳入默认离线 suite；使用显式 marker/脚本，由用户授权后执行并保存证据。

## 7. 依赖策略

- P0-1/P0-3：不需要新依赖。
- 专利/新闻：优先复用 Playwright 或 Python 标准库；只有 fixture 证明现有手段不可维护时才提出单一轻量依赖。
- Summary provider：先定义 protocol + fake；当前仓库没有 TJU LLM 接口，不应假设已接入。真实接入必须单独确认 endpoint、凭据边界、文本外发许可和超时。
- 禁止为了一个 PoC 引入通用 agent framework、向量库、数据库服务或大型爬虫框架。

## 8. 总体成功标准

到 9 月 27 日，v0.17 至少满足：

1. 方向或人名任一非空即可启动；两者都空才拒绝。
2. 综合/应用/理论/综述对三源产生可解释的不同查询或明确的等价来源策略。
3. 论文、专利、中文新闻均有真实结果、typed 字段、详情 URL、fixture 和一次真机证据。
4. 用户选择一条后可生成四字段关键信息，带来源与“AI总结”标记；失败可降级。
5. 混合类型结果可以展示、导出并生成报告。
6. 默认 suite 全绿；新增真机脚本与默认离线测试隔离。
7. Requirements Matrix 逐链复审，P0 项不得用 UI 控件或预留接口代替实现证据。

## 9. 总体停止条件

- 不继续开发 citation ranking、更多排序算法或纯美化。
- 不批量调用 LLM，不在无摘要/详情文本时生成总结。
- 不绕过验证码、登录或站点访问限制。
- 不因某个外部源不稳定而重写现有论文底座。
- 不一次性替换 SearchResult；保持兼容转换和可回滚边界。
- 9 月 24 日后仅修 P0 验收缺陷；9 月 27 日冻结。
