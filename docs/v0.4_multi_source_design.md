# v0.4 多源论文检索设计

## 1. 当前架构评估

### 1.1 目录与职责现状

| 层 | 当前实现 | 审计结论 |
| --- | --- | --- |
| `sources/` | 已有 `base.SourceAdapter` 和 `cnki.CNKIAdapter` | 已有适配器雏形，但统一接口过窄，且服务层仍直接依赖 CNKI。 |
| `models/` | `QueryRequest`、`SearchResult` | 已有统一请求和结果雏形；`SearchResult` 字段偏 CNKI，尚不能无损表达开放论文库元数据。 |
| `services/` | `SearchService`、`QueryExpansionService`、`export.py` | Query Expansion 已接入，但输出的是 CNKI 布尔检索串；检索编排、TJU 授权和 CNKI 导航耦合在一起。 |
| `ui/` | `MainWindow` + `BrowserWorker` | 数据来源控件目前只有可用的 CNKI 复选框；请求已带 `databases`，但服务层没有读取它。worker 的命名和生命周期也默认所有检索都依赖浏览器。 |
| `export/` | 仓库中不存在独立 `export/` 包；导出实现位于 `services/export.py` | 当前能导出统一字典，但字段列表固定且仍使用 `database/detail_url` 等旧命名。短期可保留位置，待插件边界稳定后再决定是否拆包。 |

当前主调用链为：

```text
MainWindow
  -> QueryRequest(databases=["CNKI"])
  -> BrowserWorker
  -> SearchService
       -> TJU auth gate
       -> BrowserSession.open_cnki()
       -> QueryExpansionService（生成 CNKI 方言字符串）
       -> CNKIAdapter
  -> list[SearchResult]
  -> dict -> GUI / export
```

### 1.2 CNKI 架构的可扩展性判断

结论：**分层方向正确，但当前实现不适合直接增加多个数据源；需要小范围重构编排边界，不需要重写应用。**

已有的有利基础：

- `SourceAdapter` 已存在，CNKI 解析结果也已转换为统一对象。
- `QueryRequest.databases` 已预留多选列表。
- GUI、worker、service、adapter 的层次清楚，Qt 主线程与后台线程边界可继续保留。
- GUI 和导出主要消费字典，统一模型迁移可以保留兼容字段，渐进完成。

主要阻碍：

1. `SearchService.__init__()` 直接构造单个 `CNKIAdapter`，没有 adapter registry，也没有根据 `query.databases` 分派。
2. `SearchService.search()` 无条件检查 TJU 授权并打开 CNKI。arXiv、Crossref、OpenAlex 不应依赖浏览器或 TJU 登录。
3. `SourceAdapter.search(keyword, count)` 只表达字符串和数量，无法清晰承载结构化扩展词、来源特有过滤器、超时和分页信息。
4. `QueryExpansionService` 直接组装 CNKI 的 `AND/OR` 字符串。不同来源的查询语法与字段检索能力不同，不应把 CNKI 方言广播给所有 adapter。
5. `SearchResult.source` 实际表示期刊/来源出版物，而 `database` 表示 CNKI；在多源场景中 `source` 一词会产生歧义。
6. `rank` 是单源页面序号。合并后必须明确它是全局展示顺序，而不是来源内部排名。
7. 当前失败模型是“一处异常，整次检索失败”，多源检索需要允许部分成功并向用户报告各来源状态。

### 1.3 SourceAdapter 是否需要统一抽象

需要，但不是“新增另一个抽象”：应当**加强现有 `sources/base.py` 的 `SourceAdapter`**，让 `CNKIAdapter`、`ArxivAdapter`、`CrossrefAdapter`、`OpenAlexAdapter` 实现同一契约。

建议契约表达以下能力：

```python
class SourceAdapter(ABC):
    source_id: str                 # 稳定机器 ID：cnki/arxiv/crossref/openalex
    display_name: str              # GUI 文本
    requires_tju_auth: bool

    @abstractmethod
    def search(self, query: PaperQuery, limit: int) -> list[Paper]: ...
```

约束：

- `PaperQuery` 是来源无关的中间表示，至少保留 `original/terms/filters`；adapter 自己把它编译成 CNKI、arXiv 或 REST API 的查询参数。
- adapter 负责 HTTP/浏览器访问、来源协议解析、字段归一化和来源级异常转换。
- adapter 不负责跨来源合并、去重、全局排序、GUI 状态或导出。
- `source_id` 使用稳定小写 ID；显示文本、类名和复选框文字都不能作为路由键。
- HTTP adapter 的超时、User-Agent、联系邮箱/API key 等由配置注入，不写死在 GUI 或模型中，也不写入日志/导出。

为了兼容未来 Firefly 插件，`SearchService` 应依赖注入 adapter registry，而不是导入并构造所有具体 adapter。核心 `models/`、`sources/`、`services/` 不应依赖 PySide6。

## 2. 目标架构

建议目标结构：

```text
src/tju_info_retrieval/
├─ models/
│  ├─ query.py              # QueryRequest / PaperQuery
│  ├─ paper.py              # Paper 统一模型
│  └─ search_response.py    # 可选：分源状态、部分失败
├─ sources/
│  ├─ base.py               # SourceAdapter / SourceError
│  ├─ cnki.py
│  ├─ arxiv.py
│  ├─ crossref.py
│  └─ openalex.py
├─ services/
│  ├─ query_expansion.py    # 产出来源无关的 terms/filters
│  ├─ search_service.py     # 分派、汇总、部分失败
│  ├─ deduplication.py      # 第二阶段再落地
│  └─ export.py
└─ ui/
   ├─ main_window.py
   └─ worker.py             # 后续可更名 SearchWorker，避免 Browser 语义绑定
```

目标数据流：

```text
QueryRequest
  -> validate selected source IDs
  -> QueryExpansionService -> PaperQuery
  -> adapter registry selects adapters
  -> each adapter compiles its own query and returns list[Paper]
  -> collect per-source outcome
  -> merge
  -> deduplicate
  -> global ordering/rank
  -> GUI / export / Firefly plugin boundary
```

建议 registry 由应用装配层建立，例如：

```text
cnki     -> CNKIAdapter(session)
arxiv    -> ArxivAdapter(http_client)
crossref -> CrossrefAdapter(http_client, mailto)
openalex -> OpenAlexAdapter(http_client, optional_api_key)
```

CNKI 是唯一需要受控浏览器和 TJU 授权的 adapter。授权检查应成为 CNKI 执行前的来源级前置条件，而不是整次多源检索的全局 gate。这样 CNKI 登录失效时，公开来源仍可返回结果，并在响应中标记 CNKI 失败。

## 3. 统一论文数据模型设计

### 3.1 是否新增 Paper/Document

需要统一模型，建议命名为 **`Paper`**，而不是更宽泛的 `Document`。本项目当前范围是论文/预印本元数据，`Paper` 能避免把新闻、专利等未来对象过早塞进同一模型。

现有 `SearchResult` 已经承担统一结果职责，因此不建议长期并存两套核心模型。推荐渐进迁移：

1. 新建 `models/paper.py`，以 `Paper` 作为目标模型。
2. 在迁移期让 `SearchResult` 成为兼容别名/转换层，保持现有 GUI、测试和导出可用。
3. 所有 adapter 改为返回 `Paper` 后，再删除业务层对旧字段名的依赖。

### 3.2 建议字段

```python
@dataclass
class Paper:
    title: str
    authors: list[str]
    year: int | None
    abstract: str | None
    url: str | None
    source: str                 # cnki/arxiv/crossref/openalex
    source_id: str | None       # 来源内部稳定 ID，如 arXiv ID/OpenAlex ID
    doi: str | None             # 统一规范为不带 https://doi.org/ 的小写 DOI
    venue: str | None           # 期刊、会议或 repository 名称
    document_type: str | None
    categories: list[str]
    published_at: str | None    # ISO 8601；与 year 分开
    rank: int | None            # 合并后的展示顺序，由 service 赋值
```

字段语义规则：

- `source` 表示数据提供方；当前 `SearchResult.source` 应迁移为 `venue`，当前 `database` 应迁移为 `source`。
- `source_id` 用于来源内稳定识别和无 DOI 条目的去重；arXiv 应存去版本号后的 canonical ID，并可在扩展字段保留版本信息。
- `doi`、URL、标题空白和 Unicode 需要在模型边界统一规范化。
- `abstract` 允许为空。Crossref 摘要并非每条都有，且可能包含 JATS/XML 标记；OpenAlex 的摘要可能以 inverted index 表示；CNKI 当前列表页没有摘要。
- 不把完整原始响应默认放入 `Paper` 或导出文件，避免模型膨胀、来源协议泄漏和无意导出不必要数据。
- 第一阶段不引入“统一可信度分数”。来源、引用量、开放获取状态等是不同概念，不能压成一个未经定义的分数。

建议将请求字段 `databases` 迁移为 `sources: list[str]`，并在一个版本周期内兼容旧字段。合法来源集合应来自 registry，而不是写死在 `QueryRequest.validate()`。

## 4. SearchService演进方案

### 4.1 当前与未来

当前：

```text
query -> CNKI
```

未来：

```text
query -> selected sources -> merge -> deduplicate -> export
```

### 4.2 建议职责拆分

`SearchService` 保留为用例编排层，但改为：

1. 校验请求和稳定 source ID。
2. 调用 Query Expansion 得到来源无关的 `PaperQuery`。
3. 从 registry 选择 adapter。
4. 对需要授权的 adapter 执行其前置检查。
5. 调用各 adapter，收集 `papers/errors/duration` 等分源结果。
6. 合并并调用独立的去重策略。
7. 应用全局排序并生成展示 `rank`。
8. 返回能够表达部分失败的 `SearchResponse`；兼容期可继续暴露纯 `list[Paper]` 包装。

第一版多源编排建议**顺序执行**。当前 GUI 只有一个 QThread，CNKI 又有严格浏览器线程约束；先保证状态可解释和来源隔离，再评估只对 HTTP adapter 做有界并发。不要让 adapter 内部自行创建线程。

### 4.3 Query Expansion 的演进

当前 `ExpandedQuery.query_string` 是 CNKI 方言。目标应保留结构化信息：

```text
original = 太赫兹
terms = [太赫兹, THz, 太赫兹波, Terahertz]
filters = [理论, 机理, 原理, 模型, 算法]
```

随后由 adapter 编译：

- CNKI：继续产生已验证/可回退的 CNKI 布尔字符串。
- arXiv：产生带 `all:`/字段前缀和 URL 编码的 `search_query`。
- Crossref：映射为 `/v1/works?query=...` 或更精确的 query 参数。
- OpenAlex：映射为 `/works?search=...`，必要时再叠加受支持的 filter。

第一阶段不应假设四个来源对中文同义词、布尔优先级和“理论/应用/综述”限定具有相同语义。adapter 无法可靠表达某个 filter 时，应明确降级并上报说明，而不是悄悄改变含义。

### 4.4 GUI 数据来源复选框映射

未来每个复选框绑定稳定 ID：

| 显示文本 | 稳定 ID | 初始状态/条件 |
| --- | --- | --- |
| CNKI | `cnki` | 默认选中；需要 TJU 授权 |
| arXiv | `arxiv` | v0.4 启用；无需 TJU 授权 |
| Crossref | `crossref` | adapter 完成后启用 |
| OpenAlex | `openalex` | adapter 完成后启用；轻量匿名或可选 API key |

实现时可用 `checkbox.setProperty("source_id", "arxiv")`，或由 `SOURCE_DESCRIPTORS` 配置循环生成控件。`_on_search()` 遍历已启用且选中的控件，构造 `QueryRequest.sources`。禁止用显示文字做路由，以便后续本地化和 Firefly UI 复用。

GUI 还需要为多源语义预留：

- 状态提示采用“正在检索 arXiv / Crossref …”，而不是固定“正在打开 CNKI”。
- 结果表“数据库”列改为“数据来源”，展示 `Paper.source`；“来源”列明确改为“期刊/载体”。
- 完成提示区分“全部成功”和“部分成功（某来源失败）”。单个公开 API 故障不应清空其他来源结果。
- 导出默认文件名从 `cnki_results.*` 改为中性名称。
- “检查授权状态”仍只检查 CNKI；未选 CNKI 时搜索不受其状态影响。
- worker 后续应把 HTTP 检索与浏览器检索视为同一后台任务，但不应为纯 arXiv 检索启动 Edge。

这些边界也有利于 Firefly 插件：Firefly 只需调用无 Qt 依赖的 `SearchService`，独立 GUI 继续作为一个前端，不成为插件运行时的必需依赖。

### 4.5 第一批数据源评估

| 数据源 | 协议与元数据 | 接入难度 | 主要新增文件 | 对现有代码影响 |
| --- | --- | --- | --- | --- |
| arXiv | 公共 HTTP API，Atom XML；标题、作者、摘要、分类、发布日期、条目/PDF 链接等 | **低** | `sources/arxiv.py`、Atom fixture、`tests/test_arxiv_adapter.py` | 需要统一查询/模型接口；不需要 BrowserSession。XML namespace、空白规范化和版本 ID 需测试。 |
| Crossref | 公共 REST API，JSON；以 DOI 和出版方提交的书目元数据为核心 | **低到中** | `sources/crossref.py`、JSON fixture、`tests/test_crossref_adapter.py` | 需要 polite `mailto`/User-Agent 配置、429/backoff；摘要和日期字段不稳定，类型/venue 映射需容错。 |
| OpenAlex | 公共 REST API，JSON；works、authors、sources、institutions、topics 等关系丰富 | **中** | `sources/openalex.py`、JSON fixture、`tests/test_openalex_adapter.py` | 字段映射更丰富；摘要 inverted index、OA location、分页/credits/key 配置增加复杂度。首版只取统一模型所需字段。 |

依据 2026-09-01 查阅的官方文档：

- [arXiv API User's Manual](https://info.arxiv.org/help/api/user-manual.html) 说明查询接口返回 Atom 1.0，并建议连续请求间隔 3 秒及缓存相同查询。
- [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) 公开返回 JSON 元数据；[Access and authentication](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/) 说明无需注册即可访问，同时推荐 `mailto`/User-Agent、读取响应限流头并处理 429。
- [OpenAlex API reference](https://help.openalex.org/api/) 说明 `/works` 等实体端点和 JSON 查询；[Authentication](https://help.openalex.org/api/authentication/) 说明轻量查询可无 key，免费 key 提高每日预算，并需要按 credits/429 做退避。该策略可能继续变化，必须保持配置化并以响应头为准。

## 5. 风险分析

### 5.1 数据字段不一致

- arXiv 偏预印本，可能没有 DOI 或正式期刊；Crossref 依赖出版方提交质量；OpenAlex 会聚合多个来源；CNKI 当前只解析列表页字段。
- 年份可能来自首次提交、正式出版、online publication 或印刷日期，不能混为一个未经说明的精确日期。
- 作者姓名顺序、缩写、机构、摘要格式、文献类型和 venue 均不一致。

缓解：核心字段全部定义空值语义；保留 `source/source_id`；集中做 DOI/URL/标题规范化；导出文档说明字段口径；不伪造缺失摘要或 DOI。

### 5.2 去重问题

同一论文可能同时出现在 arXiv、Crossref、OpenAlex，标题或作者还可能因版本、标点和转写不同。

建议按确定性从强到弱去重：

1. 规范化 DOI 完全一致。
2. 可验证的来源交叉标识一致（例如 OpenAlex 记录中的 DOI/arXiv ID）。
3. 规范化标题 + 年份 + 第一作者的保守匹配。

首版不要仅凭标题模糊相似度自动删除结果。弱匹配可标记为“可能重复”，由用户确认。合并记录时保留 `found_in`/来源追踪信息，不能丢失 provenance。

### 5.3 API 限制与稳定性

- arXiv 要求礼貌访问、缓存并避免连续高频请求；Atom API 也可能返回带错误 entry 的 feed。
- Crossref 限流随 pool 和请求类型变化，应读取限流响应头，串行/有界请求并指数退避。
- OpenAlex 的 key、daily credits、计费与限流策略可能变化，应允许匿名模式和可选 key，绝不把 key 写入仓库、日志或导出。
- 所有 HTTP adapter 都需要显式连接/读取超时、有限重试、429/5xx 分类和可取消性；不能无限重试。

### 5.4 来源可信度与覆盖范围

- “公开 API”不等于“元数据完整或已同行评审”。arXiv 条目通常是预印本；Crossref 是注册/出版元数据；OpenAlex 是聚合索引；CNKI 是授权检索结果。
- 同一条目在不同来源的更新时效、撤稿/更正信息和引用量可能不同。

缓解：始终显示来源和原始详情链接；不默认把预印本标成已发表论文；不混合不同来源的引用量；未来若展示 OA、撤稿或引用信息，应保留字段来源和抓取时间。

### 5.5 现有功能与插件化风险

- 一次性替换 `SearchResult` 字段会破坏 GUI、导出和现有测试。
- 如果公开 API 继续经过 `BrowserWorker` 的浏览器启动逻辑，会造成不必要的 Edge 生命周期和插件耦合。
- 若 SearchService 返回类型直接改成复杂响应，现有 Qt signal 和测试会同步受影响。

缓解：采用兼容转换层；先 adapter 单测，再 service registry，再 GUI；保持核心层无 Qt 依赖；Firefly 插件通过服务接口消费结构化对象，不复用窗口控件。

## 6. 第一阶段最小实现计划

本阶段唯一新增数据源是 **arXiv**；不实现 Crossref、OpenAlex，不实现 IEEE、Web of Science、Scopus，也不做全文下载。

建议采用一个最小但可验证的纵向切片：

1. 定义/加强 `SourceAdapter` 契约和来源无关 `PaperQuery`。
2. 引入 `Paper` 模型，同时保留 `SearchResult` 兼容转换，避免 CNKI 回归。
3. 新增 `sources/arxiv.py`：
   - 通过公开 query endpoint 发起一次低频 HTTP 请求；
   - 使用标准库 `urllib` + `xml.etree.ElementTree` 即可完成首版，暂不引入新第三方依赖；
   - 编译 arXiv 查询参数并正确 URL 编码；
   - 解析 Atom namespace 下的 entry、author、summary、category、published、id/link；
   - 将结果转换为 `Paper(source="arxiv")`；
   - 设置显式超时，转换 HTTP/XML/来源错误，不进行无限重试。
4. 新增脱网单测与最小 synthetic Atom fixture，覆盖正常结果、空结果、缺失 DOI、多个作者/分类、协议错误和数量上限；自动测试不调用真实 arXiv API。
5. 将 adapter 注册到 `SearchService`，只在用户选择 `arxiv` 时执行；纯 arXiv 检索跳过 TJU 授权和 Edge 启动。
6. GUI 新增可用 arXiv 复选框并通过稳定 ID 映射；显示来源级状态和部分失败。CNKI 默认行为保持不变。
7. 导出增加 `abstract/doi/source/source_id/venue/url` 的兼容映射，并保留旧字段一个迁移周期。
8. 验证顺序：Atom fixture 单测 -> adapter 合同测试 -> SearchService 多选/部分失败测试 -> GUI 离线测试；真实 API smoke 需另行明确授权后，仅做一次低频请求，并与离线测试结果分开记录。

预计文件影响：

| 类型 | 文件 |
| --- | --- |
| 新增 | `models/paper.py`、`sources/arxiv.py`、`tests/test_arxiv_adapter.py`、最小 Atom fixture |
