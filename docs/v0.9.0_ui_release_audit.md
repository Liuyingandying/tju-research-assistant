### 1.2 版本策略分析

当前任务定义：**v0.8.2 = 后端/检索功能版本，v0.9.0 = UI 版本**。但代码、测试、文档全部仍停留在 `0.8.2` —— 即 UI 现代化已完成实现与验证，而版本元数据尚未切换。

**结论：需要统一升级为 `0.9.0`，不建议拆分“后端版本/UI 版本”双轨。** 理由：

1. 本项目是单一交付产品（桌面应用），`version.py` 同时驱动 GUI 关于对话框、检索报告抬头与验收脚本，双版本号会造成展示混乱。
2. v0.9.0 的 UI 重构与 v0.8.2 后端将同时面向用户交付，二者属同一发布物。
3. 项目既有惯例是单线语义化版本（v0.7.1 → v0.8.2），延续即可。
