## 1. 界面结构发现（真实页面 dump）

**a) “高级检索”入口**：结果页顶部存在文本“高级检索”（SPAN，无 class），点击**不导航、不展开面板**（多次尝试含 JS 强制点击均无效果）。

**b) 第二检索栏（second-search-lay）**：结果页内嵌，可见输入为
`题名 | 作者 | 关键词 | 起始年 | 结束年`（`input.second-search-input`）+ 提交控件 `span.second-submit`（svg 图标，**非 button**）。无“机构/单位”输入框。

**c) 快捷字段标签 `quick-keyword-item`（关键发现）**：页面存在 5 个字段标签——
**题名 / 作者 / 作者单位 / 关键词 / 摘要**
——即**官方“作者单位”检索字段标签确实存在**；但全部 `visible=false`、`getBoundingClientRect().height=0`（隐藏模板/未渲染），点击（含 JS 强制）无法激活。

**d) 字段名扫描**：页面 HTML 中命中“作者单位”“单位”等文本（位于 quick-keyword-item 区域）；无 `name`/`data-*` 属性承载字段标识（输入均无 name）。

## 2. 必答问题

### Q1. 万方高级检索是否支持机构字段？

**支持（UI 官方声明层面）**：`quick-keyword-item` 快捷检索字段列表包含 **“作者单位”**（与题名/作者/关键词/摘要并列），即官方机构检索字段。**但在当前代理游客态下不可用**：该字段未渲染为可操作输入（5 个芯片全部隐藏），第二检索栏仅暴露题名/作者/关键词/起止年；多次激活尝试（点击高级检索 ×3 种方式、JS 强制点击芯片）均失败。

### Q2. 真实字段名是什么？

- **UI 标签名 = “作者单位”**（作者单位 ≡ 机构），实测确认。
- **后端 gRPC 字段名：直接证据缺位**（未能在会话内绑定“作者单位”输入并提交，故未捕获到带机构值的 /search body）。基于此前 facet 探针证据，最可能的映射为 **`OrganizationNorm`**（/facet POST 字段号 9 的字符串值），但此为推断。

### Q3. 是否比 facet 路径更适合接入 WanfangAdapter？

**是（有条件地）**。对比：

| 维度 | facet 热词/复选框（此前探针） | 高级检索“作者单位”字段（本期） |
|-|-|-|
| 官方性 | 热词为 limitcheckbox 展示组件，勾选零请求、无提交控件 | **官方声明字段标签**，与关键词/题名并列 |
| 与 Adapter 现有技术同构 | 否（需点击链 + 面板，未实现可提交） | **是**（文本输入框 + 表单提交，与 `#search-input` fill/click 同模式） |
| 提交控件 | 无（buttons=0） | `span.second-submit`（identified） |
| 当前可行性 | 死路（四轮会话均无法提交） | 需先解决“作者单位”输入框的渲染/绑定才能提交 |

结论：**方向正确且更优**——若能在真实页面激活“作者单位”输入框（绑定字段），Adapter 只需“填框 + 点提交”，与现有实现同构；facet 路径已反复证实不可提交。但接入前必须补两条证据（见 §3）。

## 3. 缺口证据（接入前必补）

1. **“作者单位”输入框的渲染条件**：芯片隐藏的原因未明（候选：需鼠标悬停“高级检索”触发的 tooltip、需机构登录态、或仅在新版页面渲染）。需一次人工在可看屏幕的环境操作并在 DevTools 中查看该元素的 display/条件。
2. **绑定后的 /search body**：一次成功“太赫兹 + 作者单位=天津大学”提交的 `/search` POST（确认字段名是否为 `OrganizationNorm` 及其字段号）——这是 diff 表与 Adapter 实现契约的唯一依据。
