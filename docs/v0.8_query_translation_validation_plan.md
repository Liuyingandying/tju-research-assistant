## 一、审计当前 QueryTranslator 输出格式

### 1.1 当前生成形式

`services/query_translator.py` 的 `_to_english(expanded)`：

```python
def _to_english(self, expanded: ExpandedQuery) -> str:
    translated: list[str] = []
    for term in expanded.terms:
        for piece in term.split():
            en = TERMS.get(piece, {}).get("en")
            if en:
                translated.extend(en)
            else:
                translated.append(piece)
    return " ".join(translated)
```

**输出格式：空格分隔的关键词串（free-text keyword string）。**

以 `太赫兹 通感一体化` 为例（`expanded.terms = ["太赫兹 通感一体化"]`）：

| 词元 | 词典命中 | 输出 |
| --- | --- | --- |
| 太赫兹 | `["terahertz", "THz"]` | `terahertz THz` |
| 通感一体化 | `["integrated sensing and communication", "ISAC"]` | `integrated sensing and communication ISAC` |

**IEEE 输出**：`terahertz THz integrated sensing and communication ISAC`

**CNKI/万方输出**：`太赫兹 通感一体化`（透传 `expanded.query_string`）

### 1.2 是否支持 AND/OR

**不支持。** 当前 `_to_english` 把词典命中的英文等价词用空格平铺，不生成任何 `AND` / `OR` 布尔算子。多个等价词之间是隐式"或"关系（IEEE 自由文本检索把空格视为词间关系，通常为 AND 语义或相关度排序，具体取决于 IEEE 引擎），而不是显式布尔。

对比：`QueryExpansionService._build_query_string` 生成的**中文**串是显式布尔（`(A OR B) AND (C OR D)`），但该布尔串只用于 CNKI/万方；翻译到 IEEE 时布尔结构被**丢弃**。

### 1.3 是否支持短语

**部分支持，但无显式引号。** 当前输出 `integrated sensing and communication` 是**裸词序列**（无引号）。若 IEEE 引擎把空格视为 AND，则这会被当作 4 个词的 AND 检索，而非一个完整短语——这与"通感一体化"作为一个概念检索的意图不符。Phase 1 未加引号，属于已知取舍（见 `v0.8_query_translator_phase1.md` 第 5 节）。

### 1.4 是否影响现有 Adapter

**不影响 Adapter 代码。** 三个 Adapter（CNKI/万方/IEEE）的 `search(keyword, count)` 签名与内部逻辑零改动，只是 `keyword` 参数内容变了：

- 对 CNKI/万方：`keyword` = `expanded.query_string`（透传，与 Phase 1 前完全一致）；
- 对 IEEE：`keyword` = 英文空格串（`IeeeAdapter.search` 用 `search_input.fill(keyword)` 填入 IEEE 搜索框，无布尔预处理）。

**潜在影响（非代码层面）**：IEEE 搜索框收到的是裸英文串，检索质量取决于 IEEE 引擎对该串的解析；若引擎把空格当 AND，`integrated sensing and communication` 会被拆成 4 词 AND，可能过度收窄导致空结果——这正是 Phase 2 要验证的核心问题。

## 二、设计 IEEE 检索策略

### 2.1 方案 A：空格关键词串（当前）

```
terahertz THz ISAC
```

**IEEE 兼容性**：高。IEEE Xplore 搜索框原生接受自由文本关键词串，空格分隔的多个词由引擎按相关度/词间关系处理，几乎不会报语法错误。实现即当前 Phase 1 行为。

**实现复杂度**：极低（已实现）。无布尔组装、无引号处理。

**对 CNKI/万方影响**：无。CNKI/万方仍透传中文布尔串，方案 A 只作用于英文源。

**缺点**：
- 无法表达"同义词组内 OR、组间 AND"的语义层次；
- `integrated sensing and communication` 短语被拆词，收窄/失真；
- 多个等价词（`terahertz THz`）平铺，语义是"或"还是"且"不明确，依赖引擎猜测。

### 2.2 方案 B：Boolean Query

```
(terahertz OR THz)
AND
("integrated sensing and communication" OR ISAC)
```

**IEEE 兼容性**：中高。IEEE Xplore 高级检索支持布尔运算符（`AND`/`OR`/`NOT`）与引号短语（`"..."`），这是其官方检索语法。但需注意：
- 引号短语必须**成对**，且短语内不能含未转义引号；
- 混合 `OR`/`AND` 时需括号明确优先级（IEEE 默认从左到右，括号可显式分组）；
- 若某词元未命中词典（未知词），需决定其归入哪个组，否则布尔结构可能断裂。

**实现复杂度**：中。需要：
1. 英文布尔组装器（复用 `_build_query_string` 的思路，但为英文源新增）；
2. 短语引号包裹逻辑（多词等价词加引号，单词不加）；
3. 未知词元的分组策略（透传为独立组或并入相邻组）；
4. 词典扩充（覆盖目标场景）。

**对 CNKI/万方影响**：无。方案 B 只改变英文源的输出；CNKI/万方仍透传中文布尔串。

### 2.3 方案对比

| 维度 | 方案 A（空格串） | 方案 B（Boolean Query） |
| --- | --- | --- |
| IEEE 兼容性 | 高（自由文本） | 中高（需语法正确） |
| 实现复杂度 | 极低（已实现） | 中（组装器+引号+分组） |
| 语义表达力 | 弱（无层次） | 强（OR 组内、AND 组间、短语精确） |
| 短语支持 | 无（裸词被拆） | 有（引号精确短语） |
| 空结果风险 | 中（AND 隐式收窄） | 低（OR 组内放宽） |
| 对 CNKI/万方 | 无影响 | 无影响 |
| 测试改动 | 无（保持 Phase 1） | 需新增/调整翻译单测 |

### 2.4 推荐

**推荐方案 B**（Boolean Query），理由：
1. 语义表达力强，能精确表达"同义词组 OR + 组间 AND + 短语精确匹配"，与中文布尔串（`(A OR B) AND (C OR D)`）结构对齐，跨语言语义一致；
2. 引号短语解决 `integrated sensing and communication` 被拆词的问题，提升"通感一体化"这类复合概念的检索精度；
3. 对 CNKI/万方零影响，改动面隔离在英文源输出。

**但建议分两步落地**：先以**真实测试**（第三节）验证方案 A 的 IEEE 检索质量基线；若空结果率/相关性不达标，再引入方案 B。避免在未验证前就增加实现复杂度。

## 三、设计真实测试方案

> 目标：在 TJU 授权环境（`p.lib.tju.edu.cn`，Edge 受控浏览器）真实检索，记录原 query / 翻译 query / 返回数量 / 前 3 条相关结果。
> 前提：需已登录授权（`check_tju_auth` 返回 `logged_in`），否则先完成登录。

### 3.1 测试用例

#### 用例 1：中文输入 → IEEE

- **关键词**：`太赫兹通感一体化`
- **原 query**（`expanded.query_string`）：`太赫兹通感一体化`（未命中同义词表，透传原词）
- **翻译 query**（IEEE，方案 A）：`terahertz THz integrated sensing and communication ISAC`
- **预期**：返回英文文献，主题为太赫兹（terahertz）与通感一体化（ISAC / integrated sensing and communication）交叉领域。
- **记录**：返回数量；前 3 条 title / year / venue / document_type / url。

#### 用例 2：中文输入 → CNKI + IEEE

- **关键词**：`太赫兹通信`
- **原 query**（CNKI）：`太赫兹通信`（透传）
- **翻译 query**（IEEE，方案 A）：`terahertz THz 通信`（`太赫兹`命中→`terahertz THz`；`通信`未命中→原样保留中文）
- **预期**：CNKI 返回中文文献；IEEE 返回英文文献。注意 `通信` 未命中词典会以中文裸词进入 IEEE 搜索框，**预期为空结果或低相关**——这正好暴露"未知词对英文库效果差"的痛点。
- **记录**：两库各自返回数量；前 3 条 title / year / venue / document_type / url。

#### 用例 3：未知专业词

- **关键词**：`量子计算`（或任选不在 `TERMS` 的专业词）
- **原 query**：`量子计算`
- **翻译 query**（IEEE，方案 A）：`量子计算`（未命中，原样透传中文）
- **预期**：IEEE 搜索框收到纯中文，**预期空结果或极低相关**（IEEE 英文库不索引中文标题）。
- **记录**：返回数量（预期 0 或极少）；若为 0，记录 IEEE 空结果异常（`SearchError: IEEE Xplore 检索结果为空`）。

### 3.2 记录模板

| 字段 | 说明 |
| --- | --- |
| 用例编号 | 1 / 2 / 3 |
| 关键词 | 原始中文输入 |
| 原 query | `expanded.query_string`（中文布尔/原词） |
| 翻译 query | 送入 IEEE 的英文串（方案 A 空格串） |
| 数据源 | CNKI / 万方 / IEEE Xplore |
| 返回数量 | 实际解析到的结果条数 |
| 前 3 条相关结果 | title / year / venue / document_type / url |
| 空结果/异常 | 是否触发 `SearchError` 或验证码/登录失效 |

### 3.3 执行方式（建议）

1. 在 TJU 授权环境运行 `SearchService.search`（或直接调 `IeeeAdapter.search`）逐用例检索；
2. 通过 `service.last_expanded` 读取原 query，通过 `QueryTranslator().translate(expanded, sources)` 读取翻译 query；
3. 记录返回数量与前 3 条结果；
4. 对比方案 A 基线，判定是否需引入方案 B。

### 3.4 判定标准

- **通过**：IEEE 返回数量 > 0，且前 3 条主题与关键词相关（太赫兹/通感一体化/通信相关英文文献）。
- **部分通过**：用例 1 通过（命中词典），用例 2/3 空结果（未命中词典）→ 印证"未知词需扩词典"与"方案 B 引号/布尔可提升"。
- **不通过**：用例 1 也空结果 → 说明空格串方案 A 对 IEEE 无效，需直接上方案 B。

## 四、输出

本文档 `docs/v0.8_query_translation_validation_plan.md`。

**只读分析结论**：
1. 当前 `QueryTranslator` 输出为**空格分隔英文串**，**不支持 AND/OR**，**不支持显式引号短语**（`integrated sensing and communication` 会被拆词）；
2. 对现有 Adapter **零代码影响**（仅 keyword 内容变化，CNKI/万方透传不变）；
3. 推荐**方案 B（Boolean Query）**提升语义表达力与短语精度，但建议先跑真实测试验证方案 A 基线，再决定是否引入；
4. 真实测试用 3 个用例覆盖：命中词典（太赫兹通感一体化）、部分命中（太赫兹通信）、未命中（量子计算），以量化跨语言检索对 IEEE 质量的提升。
