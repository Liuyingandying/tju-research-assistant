## 3. Phase B：Dashboard 实现

### 3.1 模块

`ui/dashboard_widget.py`

- `DashboardWidget(QWidget)` — 可复用内容，5 段式：
  1. **系统名称**：`TJU Research Assistant` + 定位语 + 发布版本
  2. **科研画像摘要**：研究方向 / 研究阶段（未设置时友好引导）
  3. **统计**：论文库数量 / AI 分析数量 / 报告数量
  4. **最近活动**：最近收藏论文（≤5）/ 最近生成报告（≤5）
  5. **快捷入口**：搜索论文 / 打开论文库 / 生成报告
- `DashboardDialog(QDialog)` — 独立窗口包装，应用 `theme.THEME_QSS`，
  三个快捷入口信号向外转发并自动关闭。

### 3.2 数据来源（全部只读）

| 数据 | 来源 API |
|------|----------|
| 论文库数量 / AI 分析数量 | `LibraryStore.stats()` → `total` / `analyzed` |
| 最近收藏论文 | `LibraryStore.load_all()` 按 `saved_at` 倒序 |
| 报告数量 / 最近报告 | `ResearchReportStore.list_summaries()` |
| 科研画像 | `ResearchProfileStore.load()` |

### 3.3 快捷入口信号契约

```python
search_requested  = Signal()   # → MainWindow._on_dashboard_search（聚焦检索输入）
library_requested = Signal()   # → MainWindow._on_open_library_window
report_requested  = Signal()   # → MainWindow._on_dashboard_report（打开论文库并提示）
```

主窗口仅新增「开始」菜单（不改底部按钮栏）：

```
开始 ▾
├── 首页概览
└── 演示模式（首页）
```

> **为何用菜单而非底部按钮**：`tests/test_gui.py::test_narrow_window_two_rows`
> 硬断言底部按钮栏为 11 个（第一行 5 / 第二行 6）。新增按钮会破坏该既有契约，
> 因此选择"只增不改"的菜单入口，避免改动主流程布局。

## 4. Phase C：Demo 模式

`services/demo_provider.py` → `DemoDataProvider`：

| 内容 | 数量 | 返回类型 |
|------|------|----------|
| 示例论文 | 3 篇 | `list[LibraryRecord]` |
| AI 增强分析 | 2 份 | `list[EnhancedSummary]` |
| 调研报告 | 1 份（6 章节，来源可追溯） | `ResearchReport` |
| 聚合快照 | — | `snapshot() -> dict` |

只读保证（已测试）：
- 模块**不导入任何 store**、**无 write/save/mkdir/open 调用**（AST 断言）；
- 所有访问器返回**新建副本**，篡改互不影响；
- 调用全部访问器后，仓库 `data/` 与 `runtime/` 条目无变化。

Dashboard 以 `demo_mode=True` 切换到演示数据源，展示"论文 → AI 分析 → 报告"
完整链路（3-2-1）。
