# v0.18 Phase 2.9-C-E-A —— 调研报告 UI 架构审计

- 阶段：Phase 2.9-C-E-A（实现前审计）
- 日期：2026-09-11
- 结论：**报告入口放在 `LibraryWindow`（论文库窗口），不放主窗口搜索区**；
  UI 不直接调用 LLM Provider，只经 `ReportService` → `ReportProvider`。

## 2. 入口位置：为什么在论文库而不是主窗口搜索区

| 维度 | 主窗口搜索区（结果表） | 论文库窗口（**选定**） |
|---|---|---|
| 数据前提 | 检索态结果，多数未收藏、未分析（无 EnhancedSummary、无 abstract 之外的证据） | 已收藏论文，含 `abstract` + 既有 `basic_summary` / `enhanced_summary`（报告输入齐备） |
| 与报告输入匹配度 | 低（会产出空壳章节） | 高（`ReportContext.papers` 直接来自库记录快照） |
| 既有入口冲突 | 已有 `btn_report`"生成报告"（检索结果 Markdown 报告） | 无冲突 |
| 流程连贯性 | 收藏 → 论文库 → 选论文 → 生成报告 | 同左（自然下游） |

**文案区分**（避免与 `report_generator.py` 混淆）：

| 位置 | 文案 | 产物 |
|---|---|---|
| 主窗口 | **生成报告** | 检索结果 Markdown（纯模板，无 AI） |
| 论文库 | **生成调研报告** | `ResearchReport`（AI 六章节 + 来源追溯） |

## 3. 调用链（UI 不直接碰 LLM）

```
LibraryWindow.btn_generate_report.clicked
    ↓（数量校验：0 禁用 / 1-4 二次确认 / 5-20 直接 / >20 拒绝）
LibraryWindow.generate_report_requested(list)   ← 只传论文 id
    ↓
MainWindow._generate_library_report(paper_ids)
    ↓  ReportWorker.set_service(ReportService)   ← UI 只做依赖注入
    ↓  ReportWorker.progress / succeeded / failed / finished
ReportWorker.run_report(paper_ids, title)        ← 独立 QThread
    ↓
ReportService.generate_report(...)               ← 服务层决定 Provider
    ↓
ReportProvider（LLMReportProvider 或 Mock / None → 降级）
```

- `MainWindow._build_report_service()` 仅**构建** `LLMReportProvider`（经
  `APIConfigManager.provider_config()`）并注入 `ReportService`；
  UI 代码中没有任何 `complete()` / `requests` 调用（AST + 运行期替身双重断言）；
- 报告查看窗口 `ResearchReportDialog` 只读渲染，不触发任何网络。

## 4. 线程与生命周期

| 项 | 实现 |
|---|---|
| Worker | `ReportWorker(QObject)`，`moveToThread(self._report_thread)`，`_report_thread.start()` |
| 信号 | `progress(int,int,str)` / `succeeded(dict)` / `failed(str)` / `finished()` |
| 提交 | `self.report_requested.emit(ids, "")`（队列连接 → worker 线程执行） |
| single-flight | `MainWindow._report_busy`；进行中忽略重复提交 |
| 进度 | `QProgressDialog`（非取消按钮；`WindowModal`），`progress` 信号更新文案与进度 |
| 关闭窗口 | `closeEvent` 中 `_close_report_progress()` + `_report_thread.quit()` + `wait(3000)`（与既有 summary / evidence 线程一致） |
| 异常 | Worker 内 `try/except` 兜底（日志只记异常类型），`failed` 文案可读；正常路径由 `ReportService` 降级，不产生 traceback |

## 5. 与既有 UI 的一致做法

- 与 `SummaryWorker` 同构（构造/信号/清理方式一致），**不修改** `SummaryWorker`；
- 测试替身策略与既有 `test_settings_dialog` 一致：模态窗口（`SummaryDialog` /
  `ResearchReportDialog`）在测试中必须 mock，否则会阻塞在 `exec()` 的嵌套事件循环；
- 主题样式复用既有 objectName（`btnSearchPrimary` / `btnGhost` / `summaryMeta` 等），
  不新增 QSS。
