## 2. candidate quota 规则（B2）

仅 `ranking_mode == CITATION` 启用；普通模式保持 `effective_candidate_count` 均分，**不增加任何网络请求**。

```
candidate_quota(output) = min(max(3 × output, output + 10), 50)
```

例：output=10 → 30；output=7 → 21；output=2 → 12（保底缓冲）；output≥17 → 50 封顶。
Adapter 侧以候选配额调用检索，并先触发原生被引降序（native），使候选窗口即高被引窗口。

## 3. output quota 规则（B1）

复用现有 `SearchService._allocate_counts(result_count, len(sources))`（未新造算法）：
20/2→[10,10]；15/2→[8,7]；20/3→[7,7,6]；2/3→[1,1,0]（尾部源 0 时跳过检索）。差值 ≤1，前置源多 1。

## 4. 来源均衡选择与缺额回填（B3/B4）

新模块 `services/citation_selector.py`（纯逻辑），接入管线：

```
adapter 检索（CITATION 模式候选配额 + 原生被引降序）
→ ResultMerger 跨库去重
→ FilterService
→ 【CitationBalancedSelector.select】（仅 CITATION 模式）
→ RankingService 全局排序（CITATION 语义）
→ 截断 result_count
```

- 分组：按 `result.database`（与 sources 键一致；不在配额表中的来源不参与）；
- 组内排序键：`(已知=0/未知=1, −被引, −综合分, 原始序)`——已知 citation（含 0）按降序；**None 恒排该来源所有已知 citation 之后，绝不当作 0**；同被引按现有 RankingService 综合分（`_entry` 同一评分管线）；再同保持稳定原始序；
- **整来源全 None**：自动退化为综合分排序，仍保留该来源 quota（不为空）；
- **缺额回填**：`shortage = Σquota − 已选`；按配额表（sources 顺序）轮询，每次从仍有剩余候选的来源补 1 条，直至补满 N 或候选耗尽——确定性（有测试锁定轮询次序）。缺额只可能来自不足额的源（其候选已全部入选），轮询只发生在多个足额源之间；
- **去重原则**：ResultMerger 先去重（DOI→URL→标题），选择器对唯一论文分组；不为 quota 保留重复文献（重复论文计入首现来源组，缺额由其它来源回填）。

## 5. None / 0 语义（全局收紧）

`RankingService` CITATION 模式排序键同步改为 `（已知/未知, −citation, −total, index）`——最终全局展示序同样满足 `100 → 20 → 0 → None`。既有测试（None 排有引用之后、None tie-break 按综合分）全部兼容。普通/最新模式排序键未动。

## 9. 剩余风险

1. **CNKI 授权态依赖**：被引值列在匿名/授权失效态不下发（排序行为本身可用但值不可见）→ 本地排序退化为综合分回退（native 顺序仍在）。GUI 授权有效时无此问题；建议真机验收时确认授权态。
2. **CNKI toggle 竞态**：被引排序为升降 toggle，极端时序下可能落在升序（实现已读态校准 + 本地排序兜底，但候选窗口质量可能下降）。
3. **万方高级路径单击假设**：依赖"高级表单每次全新提交 → 默认排序"的前提；若 SPA 未来持久化排序态，单击可能变升序（兜底同上）。
4. **IEEE 弹层结构**：ngbdropdown 结构变更会使 native 排序静默失效（候选回退相关性序，本地 citation 排序仍生效——但候选窗口可能不含全局最高被引）。
5. **候选窗口截断本质**：native/扩大候选池只能保证"窗口内最优"；某来源真实最高被引论文若排在检索相关性 30 名之外（极少见）仍可能落选——这是检索式召回边界，非本轮逻辑缺陷。
6. strict 过滤可能显著削减某源入选数（回填机制可补足总量，但来源均衡性下降）——属过滤语义的固有交互，已由回填兜底。
