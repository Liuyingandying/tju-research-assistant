# v0.9.2 IEEE 访问体验增强 · 只读审计

日期：2026-09-03　性质：**只读分析，未修改任何源码，未新增功能**

## 0. 问题定性

点击“打开全文页面”打开 IEEE 文献时，受控 Edge 经 TJU 资源代理
（`p.lib.tju.edu.cn` 隧道）访问 document 页：IEEE 站点部署 AWS WAF 反爬，
其 challenge 脚本（`AwsWafIntegration`）在代理隧道内被破坏/阻断，控制台报
`AwsWafIntegration is not defined` 与 `ERR_CONNECTION_CLOSED`，页面白屏。
直接访问原始 URL `https://ieeexplore.ieee.org/document/{id}` 不经过代理隧道，
WAF 正常执行，页面可渲染（未经代理时全文可能受订阅墙限制，摘要页正常）。

当前实现对此**无任何感知**：`open_detail` 只要 `goto` 不抛异常就算成功，
白屏也照常发出 `detail_opened` 信号。

## 1. “打开全文页面”完整调用链

| # | 环节 | 文件 · 函数 | 说明 |
| --- | --- | --- | --- |
| 1 | 按钮 | `ui/main_window.py` `_build_bottom_bar` | `btn_detail`（“打开全文页面”，external 图标，无结果时禁用） |
| 2 | 绑定 | `ui/main_window.py` `_connect_worker` | `btn_detail.clicked → _on_open_detail` |
| 3 | Handler | `ui/main_window.py` `_on_open_detail` | 取当前行 `self._results[sel].get("detail_url")`；为空 → 提示“没有可用的全文页面链接”；否则 `open_detail_requested.emit(url)`，状态栏置“正在打开全文页面...” |
| 4 | 信号 | `MainWindow.open_detail_requested = Signal(str)` | 主线程 → worker 线程（Qt QueuedConnection） |
| 5 | Worker | `ui/worker.py` `BrowserWorker.open_detail` | `_new_session()`（每任务新建 BrowserSession，旧会话先释放），`session.open_detail(url)`，成功后 `detail_opened.emit(url)`；**成功时保持 Edge 打开供阅读** |
| 6 | 会话 | `browser/session.py` `BrowserSession.open_detail` | 仅一行 `self._page.goto(url, wait_until="domcontentloaded", timeout=45000)`——无白屏检测、无重试、无回退 |
| 7 | URL 来源 | `sources/ieee.py` `_parse_results` | 结果页 DOM：`url: titleEl.href`（DOM href **属性值**，真实页面上解析为代理域绝对 URL）→ `SearchResult.detail_url` |

注意两点：

- worker 的 `open_detail` 是**独立新会话**：先 `start()` 打开 TJU 平台入口，
  再 `goto` 存储的代理 URL。能到达 IEEE document 域说明代理会话 Cookie 有效
  （专用 Profile 持久化），失败点不在登录态，而在代理×WAF 交互。
- 万方结果 `detail_url=None`（UI 走“没有可用链接”分支）；CNKI 为站内链接。
  **白屏问题仅影响 IEEE 路径。**

## 2. 当前 URL 来源与模型字段分析

- **使用的是代理 URL**：`detail_url` 存的是经 TJU 代理解析后的绝对 URL；
  **原始 IEEE URL 未被保存**。
- 路径结构可证明保留 `/document/{id}/`：
  `tests/test_ieee.py:81`（`/document/1/`）、`tests/test_ieee_parser.py:88`
  （`/document/8663550/`）的 fixture 锚点即为相对路径，真实页面上 `href`
  仅是前面拼上代理域/前缀。用户现象（“代理 IEEE document 页面”）亦印证。
- **SearchResult 字段现状**（`models/result.py`）：
  - 已有：`detail_url`、`doi`（v0.4 扩展字段；IEEE 搜索页解析器**未提取
    doi**，实际运行中为 `None`）；
  - 已有但 IEEE 未填：`abstract`、`keywords`；
  - 没有：`document_id`、`pdf_url`、`original_url`。
- **原始 URL 可零存储成本重建**：`document/{id}` 路径已在 `detail_url` 中，
  正则提取 id 后拼接模板即可：
  - 论文页 `https://ieeexplore.ieee.org/document/{id}/`
  - PDF/stamp 页 `https://ieeexplore.ieee.org/stamp/stamp.jsp?tp=&arnumber={id}`
- 下游引用（改动影响面）：`result_merger.py` 以 `detail_url` 为第二去重键
  （DOI 优先）；`export.py` 导出含该列；`report_generator.py:105-107` 输出
  “链接：{detail_url}”。**重建原始 URL 属纯函数新增，不动这些语义。**

## 3. 回退方案比较

### 方案 A：检测代理白屏后自动打开原始 IEEE URL

- 用户体验：保留“一键直达”，失败自动补救；但用户可能困惑最终落在哪个版本
  （原始页无订阅身份，全文可能付费墙）。
- 成功率：理论上最高；实际受**检测可靠性**制约——WAF challenge 本身需要
  数秒执行，白屏判定（body 内容/URL 特征）必须等待足够时间，慢加载易误判，
  早判易漏判；自动二次跳转使时延翻倍。
- 测试影响：需为新增检测启发式补测试（session 或 worker 层）；GUI 信号级
  现有测试不受影响。
- 修改范围：`session.py` 或 `worker.py`（检测+回退）+ URL 重建工具；**中等**，
  且检测逻辑是后续维护负担。
- 风险：启发式误判/漏判；与“不进入详情页”的检索边界无冲突，但自动跳转
  行为对用户不可见、不可控。

### 方案 B：默认直接打开原始 IEEE URL

- 用户体验：页面必定渲染，最“稳”；但绕过代理即**丢失机构订阅身份**，
  全文大概率付费墙——“打开全文页面”名不副实。
- 成功率：页面加载成功率高；“可读全文”成功率反而可能下降。
- 测试影响：最小（URL 替换点单一）。
- 修改范围：最小（URL 重建 + 打开时替换）。
- 风险：与项目“复用天津大学授权会话获取订阅资源”的核心语义相悖，
  **不建议作为唯一路径**。

### 方案 C：双入口——“访问论文页面”（原始）+“代理全文页面”（现状）　★推荐

- 用户体验：两个确定性入口，用户按需选择；无自动跳转的不确定性。
  命名建议：“打开全文页面（校园代理）”与“访问论文页面（原始站）”。
- 成功率：代理路径成功率不变；代理失败时用户有**确定性替代路径**
  （原始页至少稳定渲染摘要/官方元数据）。
- 测试影响：**最小且全部为新增**——新按钮的连接/启用态测试 + URL 重建
  纯函数测试；既有 `test_gui`（信号级 mock）、`test_worker`（`open_detail`
  生命周期，含 goto 失败分支）完全不动。
- 修改范围：`main_window.py`（新增一个 bottom-bar 按钮 + handler +
  启用态与 `btn_detail` 同步）+ 一个纯函数（如
  `ieee_original_url(detail_url) -> str | None`）+ 测试。**最小、风险最低**。
- 成本注记：bottom bar 现有 5 按钮等宽布局，新增 1 个不破坏现有 QSS
  （`btnGhost` 复用）；启用条件与 `btn_detail` 一致（有选中行且有可重建
  URL/有 detail_url）。

### 推荐

**方案 C**。方案 A 的“白屏检测”复杂度与误判风险与收益不匹配，可作为
v0.9.3 增强（代理打开后仅做轻量提示“如白屏请使用‘访问论文页面’”，不做
自动跳转）；方案 B 单独使用违背订阅语义，其价值已被方案 C 的原始入口覆盖。

## 4. 低成本增强可行性

| 增强 | 依赖 | 成本 | 结论 |
| --- | --- | --- | --- |
| 原始 URL 入口 | 从 `detail_url` 正则提取 `document/(\d+)` 拼模板 | 纯函数 + 1 按钮 | **可行，成本最低**，建议随方案 C 落地 |
| PDF 入口 | 同一 id → `stamp/stamp.jsp?tp=&arnumber={id}` 模板 | 与上共用工具函数 + 1 入口 | 技术可行；同样存在代理 WAF/订阅墙问题，建议作为原始站的姊妹入口一并评估 |
| DOI 复制 | 模型已有 `doi` 字段，但 **IEEE 解析器当前不提取**，实际为 None | UI 侧（clipboard + 按钮禁用态）极小；数据侧需在 `_parse_results` 的 evaluate 中补 doi 提取（IEEE 搜索页 DOM 是否暴露 DOI 需真页面确认） | 可行但**数据可得性未证实**；若搜索页无 DOI，则需进入详情页解析（越出“不进入详情页”边界），建议列为独立小任务 |
- 公共依赖：一个纯函数（建议放 `sources/ieee.py`，如
  `parse_document_id(detail_url)` / `ieee_original_url(...)` / `ieee_pdf_url(...)`），
  单测可全离线覆盖，零浏览器依赖。
- UI 载体建议：bottom bar 按钮（与方案 C 同批）或结果表右键菜单；
  剪贴板用 `QApplication.clipboard().setText(...)`，无需新依赖。

## 5. 结论与建议实施顺序（下一轮执行，本轮未动代码）

1. **v0.9.2 主体**：方案 C——新增“访问论文页面（原始站）”入口 +
   `ieee_original_url` 重建纯函数 + 测试；`btn_detail`（代理）语义不变。
2. **同批可选**：PDF/stamp 入口（共用 id 解析）；DOI 复制视 IEEE 搜索页
   DOM 确认结果单独立项。
3. **v0.9.3 备选**：代理打开后的白屏轻量检测与提示（不自动跳转）。
4. 全程不触碰检索核心链路（Adapter 解析、Translator、Builder、SearchService、
   merger/ranking），与任务约束一致。
