## 1. 结论：原生支持 ✅（普通检索 + 高级检索同控件）

| 确认项 | 实测 |
| --- | --- |
| 排序控件 | 结果表上方排序栏的 `li` 元素（文本「被引」），父容器 class 含 `DESC order`；同级有 相关度/发表时间/被引/下载/综合。另有 `label.dsorder` 形态（导出栏），两者并存 |

## 2. 关键行为细节（Adapter 实现依据）

1. **toggle 语义**：对「被引」连续点击会在 降序/升序 间切换（本轮高级路径第二次点击后列表变为升序——首行被引值空）。确保降序的方式：点击后读取 `li.cur` 状态，若为「被引 + DESC」即达成，否则再点一次（最多 2 次）。
2. **SPA 会话内状态残留**：普通路径选过被引降序后，高级检索结果页的排序栏直接保持 `被引 DESC cur`（本轮实测）——Adapter 每次应先检查当前态再决定是否点击。
3. 排序响应自带被引统计值 → 结果页解析通道（Phase A2 `td.quote`）在排序后同样可用。

## 3. Phase B 策略：**native**

Adapter 在 `ranking_mode == CITATION` 时：检索 → 确保排序栏为「被引 DESC」→ 抓取候选。候选顺序即被引降序，配合本地来源内排序（citation 已提取）双重保障。
