## 2. 结论

**当前代码全链路无丢弃：Adapter=20 → Merger=20 → Filter=20 → UI=20。**

- 上一轮 GUI“检索完成：0 条”的根因（查询扩展把关键词改写为 `(太赫兹 OR THz OR 太赫兹波 OR Terahertz)` 传入万方高级表单导致提交超时/空结果）已由**原始关键词策略修正**解决：本次实测 `query_string` 参数虽仍为扩展词（SearchService 层不改），但 `WanfangAdapter._advanced_search` 已按 `query_context.research_direction` 以原始词“太赫兹”提交高级表单并成功返回 20 条。
- 各层再无丢弃点；GUI 复跑（万方+太赫兹+天津大学）应显示“检索完成：20 条”。

## 3. 边界观察（非丢弃，如实记录）

1. **authors 大多为空**：DOM 优先解析下，仅当正则条目与 DOM 标题归一化匹配时才补充作者/来源/年份；样例中前两条 authors=[]、第三条有值——这是解析信息完整度问题，不影响数量。
2. **detail_url 为空**：真实万方页面仍无 `<a href>`，详情依赖已验收的 B′ 标题解析打开——已知边界。
3. **strict 模式对照（纯逻辑）**：`20 → 0 条`——万方结果无单位元数据，strict 语义设计内全删。当前 GUI 默认 soft（智能匹配），故 UI 为 20 条；若用户切到“严格匹配”，万方结果将按设计被过滤为空（需单位元数据增强或来源验证支持，属另一议题）。

## 4. 复跑 GUI 的预期
