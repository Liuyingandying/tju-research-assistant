## 3. 数据流与隔离边界

```
LibraryStore.load_all()  ──(只读)──▶ LibraryRecord[]
                                        │  report_source_from_record()  快照转换
                                        ▼
                                  ReportSource[]  ──▶ ReportContext（校验：拒绝传入 LibraryRecord 实例）
                                        │
                            ReportCache.get(key)  ──命中──▶ 直接返回（禁止调用 Provider）
                                        │ 未命中
                                        ▼
                                  ReportProvider.generate(context)
                                        │
                              validate_sources()  ──失败──▶ 降级基础报告
                                        │ 通过
                                        ▼
                            ResearchReportStore.save()  ──▶ runtime/reports/<id>.json
```

边界要点：

1. **输入侧只读**：`LibraryStore.load_all()` / `ResearchProfileStore.load()`；
   不调用 `save()` / `update()` / `remove()`（测试断言 `library.json` 字节不变）；
2. **不触碰单篇链路**：不调用 `SummaryService`、不读写 `enhanced_summary` 缓存、
   不触发任何单篇分析；
3. **不触碰浏览器与数据源**：无 BrowserSession、无 Adapter、无 Evidence Fetcher；
4. **本阶段零网络**：只有 `MockReportProvider`（固定输出）；未注入 Provider 时
   直接降级，`provider_calls == 0`（测试用 `requests.post/get` 替身做零网络反证）。

## 4. 与 SummaryProvider 的关系（刻意不复用）

| 维度 | `SummaryProvider`（单篇） | `ReportProvider`（本阶段新增） |
|---|---|---|
| 输入 | `EvidenceBundle` + `SummaryContext` | `ReportContext`（论文快照集合） |
| 输出 | `StructuredSummary` / `EnhancedSummary` | `ResearchReport` |
| 依赖 | `OfflineSummaryEngine` / LLM 单篇 Prompt | 无（本阶段仅 Mock） |
| 失败语义 | 单篇降级占位 | 降级为**基础报告**（6 节骨架 + 2 节数据聚合） |
| 缓存 | `enhanced_summary/` | `research_reports/`（独立命名空间） |
| 线程模型 | `SummaryWorker` + `_summary_busy` | （UI 阶段）`ReportWorker` + `_report_busy` |

两者共享的仅是"都调用 `OpenAICompatibleProvider`"这一将来事实，
**代码上零耦合**（`report_provider.py` 不 import 任何 summary 模块）。

## 5. 接口契约（供 2.9-C-D 接入真实 LLM）

```python
class ReportProvider(Protocol):
    name: str
    def generate(self, context: ReportContext) -> ResearchReport: ...
```

- Provider **只需产出 `title` 与 `sections`**；`id` / `created_time` /
  `papers` / `profile_snapshot` / `generation_scope` / `provider` / `model` /
  `report_prompt_version` / `status` 由 `ReportService` 统一填充；
- Provider **失败必须抛异常**（不要自己吞）：降级策略集中在 Service 一处，
  便于审计（`DEGRADED_*` 常量与 `DEGRADED_MESSAGES` 文案集中定义）；
- 来源约束：`sections[].source_papers ⊆ context.papers[].paper_id`，
  由 `ReportService.validate_sources()` 强制校验，违反即降级。
