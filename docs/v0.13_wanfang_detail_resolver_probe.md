## 1. 探查目的

为 B′（用户点击万方论文时按需解析真实详情 URL）验证两个关键假设：

- **实验1**：结果页点击标题的导航形态（新标签 vs 同页路由）、原页面状态、恢复方式；
- **实验2**：完整标题检索的匹配可靠性（resolver 的"定位"步骤是否成立）。

## 2. 实验1：点击导航形态

### 2.1 结论

**成功导航全部为 `new_tab` 形态（5/5），未出现同页路由。** 点击后 ~1 秒内新标签出现；关闭新标签后原结果列表原样保留（`restored_ok: true`）。→ Resolver 应用 `context.expect_page()` 包裹点击，捕获后 **adopt 新标签为详情会话活动页**；恢复 = 关闭新标签，无需 go_back。

### 2.2 关键发现：点击有效性由"水合等待"决定

跨 4 个运行的点击数据（同一会话形态、同一结果页）：

| 运行 | 点击前等待（结果渲染后） | 点击方式 | 结果 |
|---|---|---|---|
| click_ladder | ~1.5s → ~40s（4 连击） | locator 中心 / position(160,12) / JS el.click() / dblclick | **0/4 全败** |
| resolver EXP1 | ~1.5s | locator `span.title` 中心 | 失败 |
| detail_meta 探针 | ~20s（先 JS click 失败） | position(160,12) | ✓ new_tab |
| click_diag | **25s** 充分水合 | position(160,12) × 2（第 0、1 条） | **2/2 ✓** new_tab，~1s |
| ladder2 | **15s** 充分水合 | focus+Enter 失败 → position(300,12) | **✓** new_tab |

规律：**渲染后 ≥15s 的可信位置点击 5/5 成功；<5s 的点击 0/4 成功**（click_ladder 的 m4 为唯一晚点击失败样本，疑似多次失败交互后页面状态劣化或 dblclick 语义差异）。首条成功后立即关闭新标签再点同页其它条目同样成功（click_diag nth=1 ✓）。

### 2.3 点击方式排序（实测）

1. **`position` 偏移点击**（160,12 与 300,12 均验证成功）——水合就绪后可靠；
2. locator `span.title` 中心点击——2/2 失败（中心可能落在 `span.highlight` 高亮子元素上，且早期点击时机差），不推荐；
3. `focus + Enter`——不支持（键盘激活未实现）；
4. JS `el.click()`——不支持（非可信事件）。

## 3. 实验2：全标题检索匹配率

**10/10 首条精确命中（exact@1 = 100%），0 失败。**

- 样本：基础检索"太赫兹成像"第 1 页 20 条中随机抽 10 条（seed=42，清单见 `base_titles.json`）；
- 方法：**URL 参数化直达** `goto(<智搜结果页 base>/paper?q=<urlencode(全标题)>)`，不依赖表单控件——实测完全可行，resolver 可免除搜索框选择器依赖；
- 结果：每条目标均出现在结果首位（归一化精确相等），部分查询返回多条（1~20 条）不影响 top-1 命中；
- 逐条明细见 `exp2_matches.json`（searched_title / result_count / top1_title / exact_at_1 / target_position）。

**实验2 意义**：resolver 的"定位"步骤成立——标题即查询键，无需点击前再做任何消歧；匹配算法只需归一化 top-1 校验。

## 4. 对 B′ 设计的修订输入

Resolver 定案算法（全部在 DetailWorker 线程栈内、DetailBrowserSession 独立会话）：

```
1. goto  portal → 万方资源（复用 PortalNavigator 提炼的窄协议）
2. goto  <智搜结果页>/paper?q=<urlencode(完整标题)>          ← 免表单（实验2）
3. wait  .title-area 出现且计数连续 ~3s 稳定，且渲染后总等待 ≥15s   ← 水合阈值（实验1）
4. match 归一化标题 == top-1（严谨模式：仅接受 exact@1）
5. click position 偏移点击（阶梯 160 → 300，各验证一轮，失败间隔 10s 重试一轮）
6. adopt expect_page 捕获的新标签 → 作为详情会话活动页（DetailBrowserSession.adopt）
7. 之后进入既有 wait_until_closed / finally 同栈释放流程
失败降级：任一步超时 → error 提示"未能在万方定位该文" → 不开窗、同栈释放
```

相对上版设计的修订：① 导航形态定案为 new_tab，删除同页路由分支与 go_back 恢复逻辑（保留 expect_page 超时兜底）；② 新增水合稳定等待（≥15s，这是点击成败的决定因素）；③ 点击方式从"locator span.title"改为 position 偏移阶梯；④ 搜索步骤定案为 URL 参数化直达。

## 5. 剩余风险与说明

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 水合阈值 15s 为经验值，慢网络下可能不足 | 阶梯含两轮重试；阈值可配置化 |
| R2 | click_ladder m4（晚点击仍失败）个案未完全解释 | 阶梯的"验证-重试"循环覆盖；失败即降级，不会挂死 |
| R3 | 同标题论文歧义 | exact@1 校验 + 保留归一化全文比对；实测 10/10 无歧义 |
| R4 | 风控（单次用户点击 = 单次解析，频率接近人工） | 低；不加自动重试风暴 |
| R5 | 本轮 JSON 日志齐全但无新截图（成功路径未触发截图分支） | 页面视觉以前次探针 `runtime/wanfang_probe/*.png` 为准；resolver 实现时在失败分支加截图 |
