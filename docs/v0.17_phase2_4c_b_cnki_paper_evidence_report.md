# v0.17 Phase 2.4-C-B 报告：CNKI Paper On-demand Evidence Enrichment

日期：2026-09-08
范围：CNKI 论文单条 on-demand 摘要获取链（用户选中 → 关键信息整理 → 无摘要 →
后台 fetch detail_url → 写回 `result.abstract` → OfflineSummaryEngine → 展示）。
未实现：IEEE/万方 paper evidence、英文 tuning、API/LLM、批量摘要。
未修改：cnki.py / cnki_advanced.py 主链、OfflineSummaryEngine 算法、FilterService、
Ranking、artifact_routing、SearchWorker。

---

## 1. Selector Confirmation（实现前低频取证）

2 条真实 CNKI 论文（runtime/v0.17_paper_evidence_probe/06 json）：各 ~3.8s direct URL 打开，
**摘要 = 详情文本“摘要：\t<首行长文本>”**（首行 ≥10 字即取），休眠“安全验证/拖动”
元素存在但内容可读（与 CNKI Patent 同构）。提取策略：`摘要[:：]\s*([^\n]{10,})` + 空白归一。

## 2. Fetcher（sources/cnki_paper_evidence.py）

`CnkiPaperEvidenceFetcher.fetch(detail_url) -> str`：direct URL 打开详情 → 轮询正文就绪 →
`parse_abstract`（首行 + normalize）→ 返回；进程级 cache（key=detail_url，上限 300）；
失败按分类抛 `EvidenceError(code∈{no_url,timeout,auth,captcha,no_abstract,network})`。
只取摘要，不取 PDF/全文/引用/附件。

## 3. Evidence Contract

**摘要写入 `SearchResult.abstract`**（唯一正式字段；OfflineSummaryEngine 已从该字段读
证据）。未创建 `artifact_metadata["abstract"]` 第二套语义。fetch 成功后仅内存写回该行
dict，不落持久层。

## 4. Worker（ui/evidence_worker.py）

`PaperEvidenceWorker`（QObject 独立线程，MainWindow `_evidence_thread`）：每次 fetch 在
slot 内创建/使用/销毁独立 BrowserSession（Playwright 同槽生命周期约束）；
信号 `abstract_ready(str) / evidence_failed(str) / finished()`；失败按 code 映射用户文案
（无链接/超时/授权失效/需人工验证/无可读摘要/网络异常）。未触碰 SearchWorker。

## 5. Cache

进程级 dict（key=detail_url）；真机验证二次调用 0.0s 且同摘要，不重复开详情。

## 6. Single-flight

`_on_summarize` 顶部 `if self._evidence_busy: return`；fetch 期间按钮 disabled，完成后
恢复；同窗口同一时刻仅一个 evidence fetch。

## 7. Auth / CAPTCHA

- Auth：仅按 URL 跳登录页判定（`/login`）——修正了一次误报：详情页顶部导航含
  “登录/注册”chrome，正文文本不参与判定；
- CAPTCHA：休眠 captcha 元素 + 摘要可读 → 成功（真机验证）；仅摘要不可得 + 标记存在
  → 真阻断（CAPTCHA 文案）。禁止拖滑块/绕验证码/换 UA/无限刷新。

## 8. Summary Integration

`_on_summarize` 路由：
- CNKI paper 无摘要 + 有 detail_url → evidence_requested 后台 fetch；
- 无 detail_url → “当前论文缺少可用详情链接，无法获取摘要。”；
- 其余（paper 已有摘要 / 非 paper）→ 直接现有 `summarize_offline`；
- 非 CNKI paper 无摘要 → 保持现有“信息不足”路径（不 fetch，IEEE/万方未实现）；
- fetch 成功 → 写回行 dict.abstract → summarize_offline → SummaryDialog；
- fetch 失败 → 用户提示、不整理、不崩溃、不自动切来源。

## 9. Tests（tests/test_cnki_paper_evidence.py，22 条）

Fetcher：摘要解析/空白归一/无摘要(no_abstract)/超时(timeout)/真阻断(captcha)/
休眠验证码+摘要成功/cache(二次不 open)/无效 URL(no_url)/授权跳转(auth)/网络异常(network)；
Worker：成功信号/失败文案映射；Summary UI：搜索完成 evidence 调用计数=0（No batch）、
CNKI paper 无摘要触发 fetch、已有摘要不 fetch、非 CNKI paper 保持不足、非 paper 保持
既有、single-flight 忽略二次点击、ready 写回+整理、failure 不整理。OfflineSummary 集成。

## 10. Real Probe（runtime/v0.17_paper_evidence_probe/07 json）

生产链模拟：CNKI 检索“太赫兹”→ SearchResult 初始 abstract=None → on-demand fetch
**1.0s** 得 297 字真实摘要（“太赫兹技术由于对极性分子…”）→ 写回 → 二次调用 cache
0.0s → OfflineSummaryEngine 输出：研究内容/核心技术/应用价值 可溯源自摘要，
主要成果诚实“不足”。全部具体文本来自真实摘要（no hallucination 保持）。

## 12. GUI Manual Checklist（用户执行）

1. 搜索：太赫兹；成果类型=论文；数据库=CNKI；
2. 选择一条结果 → 点击“关键信息整理”；
3. 预期：短暂 loading（按钮 busy）→ 不冻结界面 → 后台获取 → 展示四字段，
   具体内容来自真实摘要（非全“不足”）；再次点同一结果 → 即时（cache）；
4. 无 API 行为；重复点击 single-flight；窗口可关闭。

## 13. Remaining Risks

1. detail_url 缺失的 CNKI paper → 提示无链接（不 fetch）；
2. CNKI 站点改版（摘要节点结构变化）→ parse_abstract 需重新取证（有 信息不足
   诚实兜底）；
3. 授权失效时按 /login 判定——若 CNKI 改变登录跳转形态需重探；
4. fetch ~1-4s 在后台线程，主线程不阻塞（worker 已保证）；
5. IEEE/万方 paper 摘要仍未接（用户对非 CNKI 论文点“关键信息整理”仍显示不足）。

## 14. IEEE（Phase 2.4-C-C）是否值得继续

**值得，但附前置**：IEEE Abstract 详情 direct URL 稳定可取（PoC PASS），但需先做
OfflineSummaryEngine 英文最小支持（英文词类 + 句点分句，属独立小改动），否则英文
摘要可 fetch 却无法离线整理。接入模式与 CNKI 完全同构（复用 PaperEvidenceWorker +
fetcher 接口 + `result.abstract` 契约），成本低。建议顺序：先英文 offline tuning，
再 IEEE fetcher。
