## 0. 背景

v0.9.3 Phase 1.5 已完成 GUI 收藏入口（"收藏当前论文"按钮 + LibraryStore 写入）。
下一步：增加"我的论文库"查看界面，让用户浏览、打开已收藏论文。

## 1. GUI 架构分析

### 1.1 当前 QSS 主题复用

`theme.py` 的 `THEME_QSS` 使用**精确 objectName 选择器**，通用选择器（如 `QTableWidget`、`QPushButton`、`QLabel`）无特定样式。这意味着：

- 新增窗口中的 `QTableWidget`、`QPushButton`、`QLabel` 等标准控件**自动继承全局样式**；
- 如需定制，只需给特定 widget 设置 `setObjectName()` 并添加 QSS 规则；
- 主题色常量 `COLORS`（primary #1A5CB0、navy #143D7B 等）可在新窗口中直接使用。

### 1.2 是否适合新增 QDialog/QWidget 窗口？

**适合。** 当前 `MainWindow` 是 `QMainWindow`，包含菜单栏/工具栏/状态栏架构。
新增的论文库窗口是一个**独立功能窗口**，不应嵌入主窗口（不修改 Tab 页、不替换结果表）。

### 1.3 当前窗口创建方式

`MainWindow` 是应用的唯一窗口，通过 `main.py` 创建：

```python
window = MainWindow()
window.show()
```

论文库窗口应作为 `MainWindow` 的子窗口（`parent=self`），通过按钮点击打开。

### 1.4 新窗口基类推荐

**推荐：`QDialog`**

| 基类 | 评估 |
| --- | --- |
| **QDialog** | ★推荐——模态/非模态对话框，天然适合"查看列表"场景；可设 `setModal(False)` 实现非模态（用户可同时在主窗口操作）；自带关闭按钮 |
| QWidget | 不推荐——无标题栏、无关闭按钮，需手动实现窗口装饰 |
| QMainWindow | 不推荐——论文库窗口不需要菜单栏/工具栏/状态栏，过度设计 |

### 1.5 窗口交互模式

**推荐：非模态（非阻塞）**

- `setModal(False)`：用户可在论文库窗口浏览时，同时在主窗口执行检索；
- 收藏新论文后，论文库窗口可手动刷新或自动刷新；
- 避免模态窗口阻塞主窗口操作。

## 2. LibraryStore 接口分析

### 2.1 load_all() 返回结构

```python
def load_all(self) -> list[LibraryRecord]:
    # 返回 list[LibraryRecord]，每个对象包含：
    # id, title, authors, year, source, database, venue,
    # abstract, detail_url, doi, tags, note, saved_at, reading_status
```

### 2.2 是否支持直接展示？

**支持。** `LibraryRecord` 已有 `to_dict()` 方法，可直接用于表格展示：

```python
records = self._library_store.load_all()
for i, rec in enumerate(records):
    d = rec.to_dict()
    table.setItem(i, 0, QTableWidgetItem(d["title"]))
    table.setItem(i, 1, QTableWidgetItem("；".join(d.get("authors") or [])))
    table.setItem(i, 2, QTableWidgetItem(d.get("year") or "—"))
    table.setItem(i, 3, QTableWidgetItem(d.get("source") or "—"))
```

### 2.3 是否需要新增查询接口？

**Phase 2 不需要。**

- `load_all()` 返回全部记录，单用户收藏通常 < 5000 条，内存过滤足够；
- 后续如需按标签/关键词过滤，可在 GUI 层实现（`[r for r in records if "tag" in r.tags]`）；
- 如 Phase 3 引入大量数据（>10000 条），再考虑 `LibraryStore` 新增 `filter_by_tag()` / `search_by_keyword()` 方法。

### 2.4 是否需要排序功能？

**Phase 2 不需要。**

- QTableWidget 自带列点击排序（`setSortingEnabled(True)`），可后续添加；
- 默认排序：按 `saved_at` 倒序（最新收藏在前），可在 GUI 层排序：
  ```python
  records = sorted(records, key=lambda r: r.saved_at or "", reverse=True)
  ```

## 3. 论文库功能范围设计

### 3.1 方案比较

#### 方案 A：独立弹窗"我的论文库" ★推荐

**设计**：底部栏新增"我的论文库"按钮，点击打开非模态 `QDialog` 窗口，内含 `QTableWidget` 展示收藏列表。

| 维度 | 评估 |
| --- | --- |
| 开发复杂度 | **低**——新建 1 个 `QDialog` 子类，~100 行代码 |
| 用户体验 | **高**——独立窗口，可拖拽、调整大小、与主窗口并存 |
| 对现有测试影响 | **零**——不修改主窗口结构、不修改表格列 |
| 后续扩展 | **好**——可新增标签编辑、笔记编辑、删除等按钮 |

#### 方案 B：主窗口增加 Tab 页

**设计**：在主窗口顶部新增 Tab（"检索" / "论文库"），切换显示不同内容。

| 维度 | 评估 |
| --- | --- |
| 开发复杂度 | **中**——需修改 `_build_ui`、新增 Tab 页布局、切换逻辑 |
| 用户体验 | **中**——窗口内切换，无需额外窗口 |
| 对现有测试影响 | **中**——修改主窗口布局可能影响 `test_gui.py` 中基于 widget 属性的断言 |
| 后续扩展 | **好**——可新增"标签"Tab、"笔记"Tab 等 |

#### 方案 C：替换当前结果表

**设计**：在论文库模式下，结果表被替换为收藏列表。

| 维度 | 评估 |
| --- | --- |
| 开发复杂度 | **高**——需切换数据源、重建表格、处理状态同步 |
| 用户体验 | **低**——检索结果与收藏列表混合，上下文切换成本高 |
| 对现有测试影响 | **高**——修改结果表结构可能破坏多个测试 |
| 后续扩展 | **一般**——两种模式切换逻辑复杂 |

### 3.2 推荐：方案 A（独立弹窗）

- 开发复杂度最低，测试影响为零；
- 用户体验好（独立窗口，可拖拽调整）；
- 后续扩展灵活（可新增工具栏按钮、右键菜单等）。

## 4. 打开论文逻辑

### 4.1 LibraryRecord.detail_url 复用

`LibraryRecord` 继承自 `SearchResult` 的 `detail_url` 字段（`str | None`），存储的是：
- IEEE：代理 URL（`https://ieeexplore-io-org-443.webvpn.p.lib.tju.edu.cn/document/123456/`）
- CNKI：站内链接（`https://kns.cnki.net/kcms2/article/abstract?...`）
- 万方：`None`（万方结果页不提取 detail_url）

### 4.2 如何复用现有 open_detail_requested？

**直接复用。** 论文库窗口的"打开"按钮逻辑：

```python
def _on_open_selected(self) -> None:
    sel = self.table.currentRow()
    if sel < 0:
        return
    rec = self._records[sel]  # LibraryRecord
    url = rec.detail_url
    if not url:
        QMessageBox.information(self, "提示", "该记录没有可用的全文页面链接。")
        return
    # 通过信号通知主窗口打开（跨窗口通信）
    self.open_detail_requested.emit(url)
```

### 4.3 是否需要新增 worker 逻辑？

**不需要。**

- `open_detail_requested` 信号已连接到 `BrowserWorker.open_detail`（主窗口创建时已绑定）；
- 论文库窗口只需 emit 同一信号（通过 `self.parent().open_detail_requested.emit(url)`）；
- Worker 层无需任何改动。

### 4.4 跨窗口通信设计

```
论文库窗口（QDialog）
  ↓ emit open_detail_requested.emit(url)
  ↓ 通过 parent() 引用
MainWindow
  ↓ connect(open_detail_requested, worker.open_detail)
BrowserWorker
  ↓ session.open_detail(url)
受控 Edge 打开页面
```

## 7. 最终方案

### 7.1 推荐架构

```
MainWindow（主窗口）
  ├── btn_library ("我的论文库") → _on_open_library_window()
  │     ↓ 创建
  └── LibraryWindow(QDialog, parent=self)
```

### 7.6 推荐开发顺序

1. **步骤 1**：创建 `ui/library_window.py`——`LibraryWindow(QDialog)` 类，含 `QTableWidget`（4 列：标题/作者/年份/来源）、"打开全文页面"按钮、"刷新"按钮；
2. **步骤 2**：实现 `_load_records()`——从 `LibraryStore.load_all()` 加载，排序（`saved_at` 倒序），填充表格；
3. **步骤 3**：实现 `_on_open_selected()`——选中行 → `LibraryRecord.detail_url` → `open_detail_requested.emit(url)`（通过 `self.parent()` 获取主窗口信号）；
4. **步骤 4**：在 `main_window.py` 新增"我的论文库"按钮 + `_on_open_library_window()` handler（创建 `LibraryWindow(parent=self).show()`）；
5. **步骤 5**：新增 `tests/test_library_window.py` 覆盖 6-8 用例；
6. **步骤 6**：全量回归 `python -m pytest -q`。

预计总改动量：**~100 行源码 + ~80 行测试**，1 个修改文件 + 2 个新增文件，风险极低。
