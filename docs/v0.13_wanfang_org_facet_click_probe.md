## 2. 关键观测（8 次独立浏览器会话汇总）

1. **机构热词芯片（span.words）点击 ≠ 应用过滤**：
   - 展开后点击 → 稳定触发 `POST /facet`（body 含字段 `OrganizationNorm`，字段号 9，长度 16，其后随查询与状态字节）；
   - **从未**在点击后捕获到携带机构条件的 `/search` POST；
   - URL 与结果数在全部会话中恒定不变。
2. **对照实验（v7）**：常规筛选芯片"资源类型 > 期刊论文"在相同单次自动点击下**同样不触发任何 /search/结果变化**（posts=0，count=128,799）——说明问题不在"机构"特殊，而在**该 SPA 的 facet 芯片交互不接受自动化单次 Playwright 点击**（或点击未命中真实可点击区域；展开步骤对点击竞争力有影响：未展开时连 /facet 也不发）。
3. **点击后无弹层/面板出现**（v6 三次 dump modals 逐字节相同，均为隐藏遗留对话框）；存在 8 个可见 `ivu-checkbox-input`（分属其它 facet 组复选框），机构热词行本身是**无复选框的 span.words 芯片**。
4. **gRPC-web 架构确认**：结果与 facet 全部经 `POST <智搜>/SearchService.SearchService/{search,facet}`（`application/grpc-web+proto`）拉取；`/search` body 含 `paper`+查询词+配置串（`search`/`AI_READ`/`AI_EXTRACT` 等），机构条件字段名**`OrganizationNorm`**，**不在 URL 中**。
5. **程序现状对照**：`WanfangAdapter` 仅复刻普通表单搜索，`query_context`（author_affiliation）全程未使用。要复现网页端机构过滤，需要复刻的**恰恰是那段未知的"芯片→确认"交互**，而非 URL 参数。

## 3. 障碍定位与缺失证据

自动点击命中"天津大学"后，SPA 只回一条 OrganizationNorm 的 /facet 请求即止。推测有两种可能：
- **A**：facet 热词芯片是"选中态切换"，真正确认需第二次点击/勾选其（折叠视图中不存在的）复选框，或点击"已选条件"确认区；
- **B**：该 /facet 请求实为"按词检索机构全列表"，完整机构列表（含复选框行）需在更深交互中展开，过滤在列表内完成。

**缺失证据**：一次真人操作下"应用机构过滤后"的 `/search` POST body（应含 `OrganizationNorm=天津大学` 与对应字节变化）——获取途径：人工在真实浏览器操作一次，同时用 DevTools/Playwright 记录完整 POST 序列；或对展开后的机构列表深层 DOM 做一次性 dump（确认复选框/“更多”结构）。

## 4. 对后续实现的影响（仅建议）

- URL 参数方案**确定不可行**（机制在 gRPC body）。
- UI 复刻方案：在普通搜索后追加“展开机构盒 → 命中热词 → 完成未知确认交互 → 重抓结果”；其中“未知确认交互”需先按 §3 补齐证据，否则会产生与当前探针相同的“点击无效”。
- 直接 gRPC 方案：可绕过 UI 确认态，直接构造含 `OrganizationNorm=天津大学` 的 `/search` POST；前置仍是补全该请求的完整 proto 字段布局（§3 缺失证据）。
