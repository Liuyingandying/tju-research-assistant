## 一、验收目标

验证端到端链路：**中文用户输入 → QueryTranslator → QueryBuilder → 多数据库检索**。

```
中文输入
  → QueryExpansionService.expand        # 原始 query（中文）
  → QueryTranslator.translate_concepts  # 概念分组（中文概念 → 英文概念）
  → QueryBuilder.build                  # 数据库专用 query（IEEE Boolean / 中文透传）
  → Adapter.search(query, count)        # 真实检索
```

## 二、三个 Case 设计与实测

### Case 1：`太赫兹通感一体化` → IEEE Xplore

**设计记录**：

| 字段 | 值 |
| --- | --- |
| 原始 query | `太赫兹通感一体化` |
| Translator 输出 | `{"IEEE Xplore": [["太赫兹通感一体化"]]}` |
| Builder 生成 query | `{"IEEE Xplore": "(太赫兹通感一体化)"}` |
| 返回数量 | **0** |
| 前 3 条结果 | 无（空结果） |

**实测发现（重要）**：`太赫兹通感一体化` **无空格**，`_concepts_for` 基于 `expanded.original.split()` 切分，只按**空白**切分，因此整串被当作**一个未知中文概念** → IEEE 收到 `(太赫兹通感一体化)`（纯中文）→ 0 结果。

**对照**（有空格 `太赫兹 通感一体化`）：

| 字段 | 值 |
| --- | --- |
| Translator 输出 | `[["terahertz", "THz"], ["integrated sensing and communication", "ISAC"]]` |
| Builder 生成 query | `(terahertz OR THz) AND ("integrated sensing and communication" OR ISAC)` |

有空格时正确切分并生成 Boolean（与 `v0.8_ieee_query_validation.md` 实测 Case B 一致，返回 5 条相关）。

### Case 2：`太赫兹通信` → CNKI + IEEE Xplore

**设计记录**：

| 数据源 | 实际 query | 返回数量 | 前 3 条结果 |
| --- | --- | --- | --- |
| CNKI | `太赫兹通信`（透传中文） | 3 | VO2和GST相变材料的太赫兹波响应特性…（2026）；基于软件无线电的低轨星间太赫兹通信宽带正交调制技术（2026）；全介质集成超构天线产生聚焦涡旋电磁波（2026） |
| IEEE Xplore | `(太赫兹通信)`（纯中文） | 0（脚本会话错误） | 无 |

**两库实际 query 是否不同**：**是**——CNKI 收到 `太赫兹通信`（中文透传），IEEE 收到 `(太赫兹通信)`（Builder 对未知中文概念包了括号）。但 IEEE 的 query 仍是纯中文（`太赫兹通信` 未命中 `TERMS`，`通信` 无英文映射），因此对英文库无效。

**实测发现**：`太赫兹通信` 整体未命中 `TERMS`（`TERMS` 只有 `太赫兹`→`["terahertz","THz"]` 和 `通感一体化`→`[...]`，无 `通信`→`communication`），因此 `太赫兹通信` 作为一个整词未被切分/翻译。即使切分，`通信` 也缺英文映射。这印证 `v0.8_query_builder_implementation.md` 第 5 节的"M2 词典扩充"需求。

### Case 3：未知专业词（`量子计算`）→ IEEE Xplore

**设计记录**：

| 字段 | 值 |
| --- | --- |
| 原始 query | `量子计算` |
| Translator 输出 | `{"IEEE Xplore": [["量子计算"]]}` |
| Builder 生成 query | `{"IEEE Xplore": "(量子计算)"}` |
| 返回数量 | 0（脚本会话错误） |

**安全 fallback 验证**：**通过**。未知词 `量子计算` 被透传为 `[["量子计算"]]`，Builder 生成 `(量子计算)`——**语法合法**（单概念括号，无错误 Boolean），**不抛异常**、**不生成错误布尔结构**。但语义上对英文库无效（纯中文 → 0 相关结果），符合"未知词对英文库效果差"的预期。

## 三、验收结论

### 3.1 链路是否跑通

**是**。中文输入经 `QueryExpansion → QueryTranslator → QueryBuilder → Adapter.search` 全链路可执行，无代码崩溃。CNKI 侧真实返回相关结果（Case 2 的 3 条均为太赫兹相关中文文献）。

### 3.2 关键发现

| 发现 | 影响 | 建议 |
| --- | --- | --- |
| **中文无空格切分缺失** | `太赫兹通感一体化`（无空格）被当作单个未知概念，IEEE 收到纯中文 → 0 结果 | `_concepts_for` 需支持**中文词元切分**（词典最长匹配），而非仅按空白切分 |
| **`TERMS` 词典覆盖不足** | `太赫兹通信` 的 `通信` 无英文映射，整词未翻译 | M2 扩充 `TERMS`（如 `通信`→`communication`、`太赫兹通信`→`terahertz communication`） |
| **未知词安全 fallback 正确** | `量子计算` → `(量子计算)`，语法合法、不报错 | 保留；但对英文库语义无效，需以 note 提示用户 |
| **IEEE 空结果** | 纯中文 query 进英文库 → 0 结果 | 需切分 + 词典扩充；或对英文源检测到纯中文时提示/跳过 |

### 3.3 验收判定

- **Case 1**：**不通过**（无空格切分缺失，IEEE 空结果）。有空格变体通过。
- **Case 2**：**部分通过**（CNKI 真实返回相关结果；两库 query 不同；但 IEEE 因词典缺 `通信` 无效）。
- **Case 3**：**通过**（安全 fallback 正确、无错误 Boolean、不抛异常）。

**总体**：链路架构与安全回退正确，但**中文无空格切分**与**词典覆盖**是当前两大短板，直接导致 IEEE 空结果。这是 v0.8.0 下一阶段（M2 词典扩充 + 中文切分）必须解决的核心问题。

## 四、下一阶段建议

1. **M2a 中文切分**：`_concepts_for` 支持无空格中文词元切分（基于 `TERMS` 词典最长匹配），使 `太赫兹通感一体化` 正确切为 `太赫兹` + `通感一体化`；
2. **M2b 词典扩充**：补充 `通信`→`communication`、`太赫兹通信`→`terahertz communication` 等目标场景词元；
3. **M3 真实回归**：切分 + 词典扩充后重跑本验收，确认 Case 1/2 的 IEEE 返回相关结果；
4. **M4 英文源纯中文检测**：对英文源检测到纯中文 query 时，提示用户或跳过（避免静默空结果）。
