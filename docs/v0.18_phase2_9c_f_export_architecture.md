# v0.18 Phase 2.9-C-F 导出架构设计

## 1. 目标

为 `ResearchReport` 增加三种导出格式：

- **Markdown** — 纯文本，保留章节结构和来源编号
- **Word (DOCX)** — 使用 python-docx，保留标题层级
- **PDF** — 使用 reportlab，支持中文字体

## 2. 架构原则

1. **只扩展展示层**：新增 `services/report_exporter.py`，不修改任何 Service/Model/Provider 层
2. **数据来源单一**：导出内容全部来自 `ResearchReport` 实例，不重新读取论文库，不调用 LLM
3. **导出安全**：导出失败不影响原报告；导出过程不修改 `ResearchReport` 对象
4. **不修改报告**：导出是纯读操作，`ResearchReport` 对象不可变

## 3. 数据源确认

导出使用 `ResearchReport` 模型接口：

```python
# 核心接口
report.title                    # 报告标题
report.created_time             # 生成时间
report.provider                 # Provider 名称
report.model                    # 模型名称
report.report_prompt_version    # Prompt 版本
report.profile_snapshot         # 画像快照
report.schema_version           # Schema 版本
report.generation_scope         # 生成方式
report.status                   # 状态
report.paper_count              # 论文数量（属性）

# 论文来源
report.papers                   # list[ReportSource]
paper.index                     # [P#] 编号
paper.title, paper.authors, paper.year, paper.doi, paper.source

# 章节
report.ordered_sections()       # list[ReportSection] 按 order 排序
section.key                     # 章节键 (background/trend/...)
section.title                   # 章节标题
section.content                 # 章节正文
section.source_papers           # list[str] 来源 paper_id
section.insufficient            # 证据不足标记

# 来源编号映射
by_id = {p.paper_id: p for p in report.papers if p.paper_id}
paper = by_id.get(paper_id)     # 通过 paper_id 查找 ReportSource
```

**不使用** `report.to_dict()` 的深层拷贝，而是直接通过对象属性访问，避免不必要的序列化开销。

## 5. ReportExporter 设计

```python
class ReportExporter:
    """ResearchReport 导出器（只读，不修改报告）。"""

    @staticmethod
    def export_markdown(report: ResearchReport, path: str | Path) -> str:
        """导出为 Markdown 文件。"""

    @staticmethod
    def export_docx(report: ResearchReport, path: str | Path) -> str:
        """导出为 Word (DOCX) 文件。"""

    @staticmethod
    def export_pdf(report: ResearchReport, path: str | Path) -> str:
        """导出为 PDF 文件（支持中文）。"""
```

所有方法签名统一：`(report, path) -> str`，返回实际写入的文件路径。
异常不吞掉，由 UI 层捕获并提示。

## 6. Markdown 结构

```markdown
# {report.title}

## 报告信息

- 生成时间：{created_time}
- 论文数量：{paper_count} 篇
- Provider：{provider}
- 画像版本：{profile_version}

---

## 1. 研究背景

{section.content}

来源：[P1] [P2]

---

## 2. 领域发展趋势

...

---

## 参考论文

[P1] {title}
作者：{authors}
年份：{year}
DOI：{doi}

...
```

来源编号 `[P#]` 与 `ReportSource.index` 保持一致。

## 7. Word 格式

- 报告标题：`Heading 1`
- 报告信息：`Normal`
- 章节标题：`Heading 2`
- 章节正文：`Normal`
- 来源编号行：`Normal`（斜体）
- 参考论文标题：`Heading 3`
- 参考论文元信息：`Normal`

## 8. PDF 格式

- 使用 `reportlab.platypus.SimpleDocTemplate`
- 中文字体：宋体 (`SimSun`) / 黑体 (`SimHei`)
- 标题使用黑体，正文使用宋体
- 使用 `Paragraph` 处理中文内容
- 生成失败返回错误信息，不阻塞 UI

## 9. UI 集成

在 `ResearchReportDialog` 底部按钮行增加三个按钮：

```
[导出Markdown] [导出Word] [导出PDF] [关闭]
```

点击后弹出文件保存对话框，选择路径后后台生成，完成后提示成功/失败。

## 10. 安全保证

| 要求 | 实现方式 |
|------|----------|
| 不重新调用 LLM | 导出只读 `ResearchReport`，不调用 Provider |
| 不修改报告 | 导出方法只读取属性，不写入任何字段 |
| 导出失败不影响原报告 | 异常在导出方法中捕获，原 `ResearchReport` 不变 |
| 不修改报告文件 | 导出到用户指定的新路径，不覆盖报告 JSON |
