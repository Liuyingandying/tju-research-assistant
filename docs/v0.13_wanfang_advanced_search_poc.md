## 2. 真实失败原因（如实记录）

1. **fill() 与 iview 输入框 v-model 不同步**：提交后现场 JSON 显示全部 `.ivu-input` 值均为空——`page.fill()`（一次性设值+input 事件）未被该 iview Input 组件完整接收为模型值；表单提交时 Vue 侧视为空表单（仅触发埋点与自身重载 `?t=`，不发起检索）。
   - 证据：`poc_report.json["layout_after_submit"]["input_vals"] == ['', '', '', '']`，而表单填值步骤无任何异常返回。
2. **提交触发页面自身重载**：点击 `span.submit-btn` 后 URL 追加时间戳参数 `?t=` 且表单被重置——可能为校验失败后的重载路径或反自动化行为；重载丢掉了字段选择与输入。
3. **结论**：不是站点功能缺失（作者单位字段、提交控件、埋点均真实存在），而是**自动化输入层的模型同步问题**——真人键盘逐键输入可正常注册 v-model。

## 3. 对后续实现的直接输入（供实现参考，本 PoC 未实现）

1. 表单字段选择已可可靠复现：`click .ivu-select` → `click .ivu-select-item:has-text('作者单位')`（两次运行均成功）。
2. **输入必须用逐键方式**（Playwright `press_sequentially`/`type` 逐字符，或 `keyboard.type`），不能用一次性 `fill()`；填写后立即读取 `input.value` 断言回读值等于目标，直到回读成功再提交。
3. 提交控件 = **`span.submit-btn`（文本“检索”）**，非 button；点击前确保无打开的下拉、避免点击空白触发重载。
4. 提交成功判定 = 出现 `POST /SearchService.SearchService/search`（**排除** `www.wanfangdata.com.cn/analysis/log` 埋点）。
5. 注意事项：点击空白/escape 可能触发表单重载（`?t=`），填写与提交之间应避免多余交互。
6. 附加发现：页面可**直连原始域名** `www.wanfangdata.com.cn`（埋点请求未走代理）——与早期"原始站直连不可用"结论不冲突（详情页 SPA 水合问题仍然存在），但为后续网络层选择提供参考。
