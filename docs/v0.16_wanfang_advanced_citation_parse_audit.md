# v0.16 万方高级检索高引用解析审计与修复

日期：2026-09-06  
范围：`src/tju_info_retrieval/sources/wanfang.py`、万方定向测试、独立 Playwright 真机探针。未修改 QueryBuilder、Translator、citation_selector、quota 算法、FilterService、SearchResult、IEEE/CNKI adapter。

## 结论

根因是高级检索结果页的两阶段 SPA readiness 判断不足，不是关键词扩展，也不是 `.title-area span.title` 或 citation selector 失效。

1. 首次提交后的旧 `_wait_advanced_results` 只以 `.title-area` 存在为就绪条件，没有排除仍覆盖结果区的 loading；慢响应时可能把旧/过渡 DOM 当成首次结果完成。
2. CITATION 分支点击“被引频次”后，旧 `_apply_native_citation_sort` 只固定等待 4 秒；没有确认排序 active、loading 消失、结果内容已从点击前状态变化、或新 DOM 连续稳定。
3. 真机 MutationObserver 证明排序不是原地改序：一次排序在约 318 ms 时移除全部 20 个旧 `.title-area`，并加入 20 个新 `.title-area`。另一次慢响应中，URL 和 active 已先变化，但旧综合结果仍保留约 775 ms；因此 URL/active/旧标题非空均不能单独证明 hydration 完成。
4. `_parse_results` 的 DOM-first 路径本身正常。它在有 `.title-area span.title` 时直接生成结果，并从同一卡片 `.stat-item.quote` 提取 citation；只有标题为空且正文正则也无命中时才返回 `[]`。

报告中的“结果页已渲染但无可解析条目”由 `_advanced_search` 中 `results = _parse_results(...)` 后的 `if not results` 精确触发。旧代码调用顺序是：首次结果等待 → 点击排序 → 固定 4 秒 → 立即 `_parse_results`；没有排序后 hydration gate。

## 调用链审计

- `WanfangAdapter.search`：读取 `query_context.research_direction` 为 `original_keyword`；读取 `author_affiliation`。单位非空进入 `_advanced_search`，CITATION 仅通过 `citation_sort=True` 改变结果页排序。
- `_advanced_search`：作者单位与原始关键词逐键输入并回读；提交后 `_wait_advanced_results`；CITATION 才调用 `_apply_native_citation_sort(..., advanced=True)`；其后调用共享 `_parse_results`。
- `_parse_results`：优先 `.title-area span.title`；`_extract_card_citations` 在同一 `.title-area` 内读取 `.stat-item.quote`。排序前后真实页面均使用这套结构，无需 citation 专用 parser。
- `candidate_quota`：SearchService 只把计算后的候选数传给 adapter；不会改变万方页面的 DOM selector 或“显示 20 条”状态。本次没有发现 quota=30 导致 parser 不兼容，也未修改配额算法。

## 最小修复

只修改万方 adapter 的 readiness：

- 首次高级结果等待：标题数大于 0、可见 loading 消失、连续两个 250 ms 周期稳定。
- 点击被引排序前保存标题前三项与 citation 前五项组成的内容签名。
- 排序后要求：`被引频次` class 为 `active/down/up`、标题数大于 0、loading 消失、内容签名相对点击前发生变化，并连续两个短周期一致。
- URL 变化不再单独视为完成证据。
- 高级排序 30 秒仍未达到条件时显式报“被引排序结果未就绪”，避免继续解析空 DOM 或旧综合结果。
- `_parse_results` 与 `_extract_card_citations` 没有分叉或新增 citation 专用 parser；普通万方 CITATION URL 参数路径保持原行为。

## 是否仅影响 CITATION

本次用户报告的“排序后 0 parse”缺口只位于高级检索 CITATION 分支，因为综合推荐不会执行第二次 SPA 排序。A/B 真机均能解析 20 条，C 在完整成功轮次也能解析 20 条。

不过首次 `_wait_advanced_results` 的 loading 漏检是高级检索共享风险；真机曾在 A 组未排序状态出现 60 秒无标题，也曾在已有标题时仍有 loading overlay。因此一并强化首次结果 gate。该站点波动通常会表现为“首次结果超时”，与 CITATION 排序后空解析不是同一个触发点。

## 为什么原测试没有捕获

此前测试覆盖静态 DOM parser、单卡 citation 提取、原始关键词与高级表单输入，但没有任何 `_apply_native_citation_sort` 测试，也没有模拟“点击后先清空、loading、延迟重建”的 Vue 生命周期。静态 fixture 从未出现 active 先变、旧标题仍在或 title 暂时为 0 的中间态，所以固定 4 秒与真正 hydration 没有被区分。
